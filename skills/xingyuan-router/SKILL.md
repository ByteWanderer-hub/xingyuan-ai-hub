# 星愿技能入口

## 路由步骤

1. 提取用户的目标、平台、动作和对象。沿用明确上下文；没有平台信息且涉及实际实现时才确认平台。技能名/`$技能名` 优先于一般关键词，但仍检查适用范围。
2. 查下表，或运行 `python scripts/route.py "用户任务"`（从本技能目录运行；任意目录可使用脚本绝对路径）。机器输出是候选，不是授权或自动执行结果。
3. 选择一个主技能；有实际依赖再加辅助技能。明确实现默认走工程技能；故障取证用排错技能辅助；纯素材搜索不启动完整 UI/交付流程。
4. 打开对应的 `../<技能名>/SKILL.md`，再按它的链接只读相关参考。安装后仍从本技能目录定位相邻技能；缺失时报告缺少的技能及安装方式，不假装已调用。
5. 简述选择后继续完成用户任务。只要求找技能时给出路径与理由即可。未知、否定词和混合任务不能只凭命中数下结论；例如“不要 Roblox，做千星 UI”应走千星。

## 细分入口与缺口

- 千星对话/黑幕/选项/打字机：读 `miliastra-code` 后按其对话工程参考继续。
- 参考图重建、按圈选小改、图片转 GIA/Lua：读 `miliastra-ui` 的 `references/client-template-gia.md`。仅图片控件可走通用输出，不要求指定地图；加入其他控件或玩法才按地图适配。区分预览、离线 GIA 与 Lua 创建模块，不把图片文件本身当可导入资源，不为通用美术或其他地图误启《天堂之门》专用流程。
- GIL/GIA、节点图、REA：先读 `miliastra-code` 的 `references/node-graph-capabilities.md` 与 `references/plugin-toolbox.md` 的相关能力。仓库未包含 `rea` 技能或通用地图 GIA 生成器；素材样例不等于生成工具。
- 土狼时间/郊狼时间/coyote time、输入缓冲/input buffer：本库暂无对应移动/输入专项技能。`game-feel` 不负责原始控制器数学；可结合已核实引擎 API 实现，但明确是补充实现而非调用现成专用技能。
- `platformer`、`input-systems`、`camera-systems` 等旧文档提及的外部技能：先确认实际存在，不能从名字推断已安装。
- 已接入的桌面软件：读 `desktop-toolbox`，其接入记录区分已安装、可启动和已完成实际功能验收；不因曾经安装就默认可用。
- 关键词未命中：回到任务目标判断，必要时追问一句；不默认启动全部技能。

## 安装与维护

本技能目录和其他技能目录应同级。仓库安装器默认安装本入口与十项千星技能；备用审查、维护和 Roblox 技能可按名安装，或使用 `--all`。只安装入口时仍可查索引，但运行目标技能前必须补齐目标目录。

索引真源为 [routes.json](references/routes.json)，脚本仅检索，不执行目标技能。仓库访问、文件安装、客户端发现、插件可用和真机验收分别报告。

## 技能变更必须同步维护入口

把入口维护作为每次新增、修改、重命名、合并或删除技能的完成条件，与技能变更在同一轮、同一提交中交付，无需用户另行提醒。所有修改在仓库真源进行。

| 变更 | 必须核对和更新 |
| --- | --- |
| 新增/导入技能 | 在 routes.json 添加唯一条目：name、purpose、platform、中英文/自然表达关键词；在上方快速表加入或并入对应行 |
| 修改职责、适用条件或能力 | 同步 purpose、platform、keywords、快速表、主辅技能分工及细分入口；新增能力落实后撤销对应过时的缺口提示 |
| 更名、合并、删除 | 更新目标名称与路径，移除失效条目；有必要时将旧名称作为新目标的关键词，不能指向已删除目录 |
| 仅修正文案/内部实现 | 仍核对该技能索引；若职责与关键词没有变化，记录“入口已核对，无需变更”，不制造无意义改动 |

1. 先读变更后的目标 SKILL.md，按实际能力整理关键词，不能只靠目录名猜测；缺口说明同时检查 routes.json 的 gaps 与本入口正文。
2. 核对同义词、用户常用说法、平台边界及同关键词下主辅关系；新增平台需同步 route.py 的平台识别、过滤和参数，不能只填一个脚本不认识的平台值。
3. 新增/改变路由时增加能代表用户表达的正例和易误触发的反例。保留原有路由行为；全部目标必须存在，每项实际技能（本路由自身除外）恰好一个索引条目，关键词不能为空。
4. 在仓库根运行 `python -B -m unittest discover -s scripts/tests -p test_route_skills.py`。目录或元数据变化再运行相关结构检查。测试失败先修复，不以“技能正文已完成”跳过入口维护。
5. 技能、路由数据、必要入口说明和测试一起提交推送。更新实际使用副本时也选择 xingyuan-router，不能只更新目标技能而留下旧索引。当前无法访问客户端时报告“仓库入口已更新，安装副本待同步”。

规则和测试不会后台监听文件，也不会自动理解新能力；执行技能维护任务的助手负责落实以上步骤。
