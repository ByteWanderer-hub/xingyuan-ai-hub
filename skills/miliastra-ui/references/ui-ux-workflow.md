# 千星 UI/UX：从需求到试玩

最后核对：2026-10-25。用于新整屏、菜单流程和交互改版；素材搜索、单控件位置/颜色调整只检查受影响项。沿用已有主题文档，以下表格可直接嵌入，不另建七份阶段文档。方案默认本地保存，技能维护按仓库授权同步。

## 使用顺序与产物

需求拆解 → 分区布局 → 控件选型 → 模板化 → 多端适配 → 绑定实现 → 试玩迭代。适配从布局阶段就考虑，绑定后再验证；试玩发现问题回到对应步骤。参考图虽写“六步”，实际包含七项，不沿用其跳过绑定的箭头。

| 步骤 | 做什么 | 最小产物 / 检查点 |
| --- | --- | --- |
| 1 需求拆解 | 先写玩家目标，将信息、操作、反馈分开；区分高频/低频、个人/共享数据 | `目标｜要看什么｜要做什么｜频率｜数据归属｜成功/失败反馈`；知道下一步做什么 |
| 2 分区布局 | 先主信息与主要操作，再安排辅助信息；标题/内容/操作区是参考结构，HUD 不必套三段 | 文字线框或既有布局标注；主次、遮挡、层序、退出入口明确 |
| 3 控件选型 | 按任务语义选择原生控件，核对当前编辑器/客户端支持 | 控件表及所需状态；不把装饰图片当按钮，也不凭样子承诺交互 |
| 4 模板化 | 复用控件组和素材组，保存语义命名、索引、参数与归属 | 组件映射表；同类组件同一配方，修改模板前列出受影响实例 |
| 5 多端适配 | 检查画布、锚点、安全区、触控和焦点路径 | 目标设备/比例矩阵；每端能读、能操作、能退出 |
| 6 绑定实现 | 明确使用节点图还是 Lua；将数据、事件、可见性与生命周期接通 | 事件契约及状态转移；先有交互闭环，再声称功能完成 |
| 7 试玩迭代 | 从首次使用者视角完成任务，检查目标端及相关多人行为 | 实际结果、证据、问题与复测状态；未测端明确待验证 |

## 控件选型与反馈

| 需求 | 优先方案 | 易错点 |
| --- | --- | --- |
| 信息、说明、数值 | 文本展示控件；进度有界时配进度条与数值 | “文本框”不等于可编辑输入框；长文本须检查换行、截断与阅读入口 |
| 一次操作 | 按钮或已核实的交互控件 | 常态、按下、禁用原因和结果反馈；悬停是鼠标补充，不能是触屏唯一入口 |
| 持续开关 | 原生开关或语义相同的已核实组合 | 选中/未选中与悬停/按下分开；同步实际变量，不用颜色单独表达状态 |
| 阻断式选择 | 模态弹窗 | 控制背景输入，默认焦点、取消/返回、关闭后焦点恢复明确 |
| 就近补充信息 | 浮层/详情面板；原生交互页须核对能力 | 触屏提供点击查看与关闭；遮挡关键内容或无法退出时改布局 |
| 装饰与分组 | 图片、底板、素材组 | 装饰不抢焦点、不吞点击；保留素材与模板的必要子树 |

“看得懂、点得到、有反馈”分别验收。按下反馈可立即出现，涉及共享状态的操作须等权威结果再显示成功；加载、空态、失败、禁用只按实际路径补齐。动效时长与粒子按需读 [miliastra-motion](../../miliastra-motion/SKILL.md)，不在本表编造动画或节点 API。

## 模板、索引与状态

建议表头：`语义名称｜用途｜布局/控件组来源｜组合索引｜子控件索引｜素材 ID｜实例归属｜可变参数`。未知字段明确待核实，不能拿素材 ID 当模板索引；运行时实例也不等于库模板。命名示例 `Shop/ConfirmPurchase` 只是项目约定，不是平台强制格式。

节点图控件组需先区分生命周期与表现状态：未激活时不能操作表现状态；激活后才切换开启、隐藏、关闭。隐藏后重开保留动态改动，关闭后重开会重新初始化。布局自带的组随布局激活，只能调整表现；节点创建的组才按对应移除节点回收。设计“返回保留选择”或“重开清空表单”时据此选择，不能互换。（[官方控件组说明](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhg1700h8bug)）

这些是**节点图控件组**语义，不能套成 Lua 的 `SetVisible`、`SetActive`、销毁或事件订阅语义。Lua 生命周期按 [客户端 UI API](../../miliastra-code/references/api-client-ui.md) 和 [交互可靠性](../../miliastra-code/references/ui-interaction-reliability.md) 核对。

## 多端适配

- 新布局先检查手机上的可读性与主要操作可达性，可把横屏 16:9 列为一个设计测试场景；它不是已证实的全平台最小尺寸。已有项目的 1600×1000 是 PC 参考画布，不强制重做。按真实画布选择等比留边、重排或扩展策略，禁止只拉伸截图。
- 分开记录参考设计尺寸、运行画布、可操作安全区域与实际热区。项目的 32 逻辑单位外边距不能代替设备安全区；刘海、圆角、系统/原生 HUD 占用及手指遮挡要实际核对。UI 不可操作区域与摇杆输入死区不是同一参数。
- 高互动频率按钮放在目标设备易达区域，热区可大于图案，但不能互相覆盖。官方自定义开关只有自定义样式支持调整点击区域，实际响应以配置的区域为准；不能推广为所有控件均有同一开关。（[官方开关说明](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhkrafr3w6um)）
- 手柄以焦点导航为主、快捷键为辅：定义初始焦点、邻接顺序、可见焦点、确认/返回、弹窗焦点限制与关闭恢复；隐藏/不可用项不成为死路，必要说明另有入口。切换键鼠/手柄后仍能继续。只配置“允许聚焦”不代表导航已实现。
- 按支持范围覆盖手机 16:9、实际较长比例手机、PC 16:10/目标窗口及手柄；不要求无关端。逐项记录真实尺寸、输入方式和结果，模拟缩放只能证明布局检查。具体跨引擎原理见 [game-ui-ux](../../game-ui-ux/SKILL.md)，不能直接复制其中 Godot/Unity API。

## 绑定契约

先记录 `触发控件与索引｜触发玩家｜数据所有者/类型/初值｜事件入口｜状态转移｜显示更新者｜回执/失败｜退出清理`。选择一个渲染归属，避免多个脚本互相覆盖显示。

- 节点图：确认组来源和激活时机，核对事件支持的控件种类、组合与子项索引，再读取/修改正确玩家或共享变量。官方“界面控件组触发时”只由发生交互的玩家节点图收到；不能假设自动广播或任意图片/文本均可触发。（[官方事件参数](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhn7ko01v3yw)）
- Lua：使用 [miliastra-code](../../miliastra-code/SKILL.md) 已核实 API/事件；展示侧绑定初始化、变化通知和重开刷新，退出时按实际生命周期解除监听/取消未完成任务，避免重开重复回调。缺少事件时先查平台能力，不虚构信号。
- 可交互前保证初值和处理入口就绪；快速连点、关闭后迟到回执、重复通知与重新打开均有明确行为。重入保护是否需要、失败如何恢复由操作性质决定，不给所有按钮统一加延迟。
- 多人时明确个人 UI、共享结果与广播范围；玩家 A 操作不能误改玩家 B 的个人选择。业务状态确认与本地按下反馈分开；计数与购买等操作的有效性由权威侧核验。

## 试玩、预算与交付

让首次使用者在尽量少提示的条件下完成一条主路径，记录误解、误触、卡住点和退出是否可达；没有实际测试者时仅称“首次使用者视角走查”。至少覆盖受影响的正常路径、取消/返回、失败恢复、连续操作、隐藏/关闭再开；涉及共享状态才加入多人隔离与同步检查。

建议在同一主题文档记录：`场景｜设备/输入/尺寸｜预期｜实际｜证据｜状态｜下一步`。区分实现、保存、离线检查、真机操作和用户观感确认；未执行标待验证，不用勾选清单冒充试玩通过。

参考图的布局/模板/组内/单屏数量没有版本与模式依据，本次未作为平台上限收录。将来引用须附官方出处、适用模式、计数对象与核对日期；容量上限不等于性能预算。记录本方案实际控件/动态实例数量，需要性能诊断时读 [performance-optimization](../../performance-optimization/SKILL.md) 实测，不能从控件数推算帧率或 Draw Call。
