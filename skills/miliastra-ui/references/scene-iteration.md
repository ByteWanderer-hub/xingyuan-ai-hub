# 场景几何、分层美术与可编辑预览

适用于房间/门示意图落地、局部改图、食物分层美术和浏览器微调回流。承接 [参考图到原生控件](client-template-gia.md)，不替代同型资产优先和目标平台规则。经验来自《天堂之门》多轮反馈；具体厨房主题、颜色、关卡编号留在项目参数里。

## 语义与几何只定义一次

- 分开记录房间、初始气体、食物需求和房间装饰。需要蒸汽的对象不等于蒸汽源；含一个小对象不必把整个宿主房间改成专属环境。按用户最后确认的语义渲染，不从填充颜色猜游戏规则。
- 先用稳定 ID 建邻接和门组。双门可能隔出独立口袋，也可能在同时打开后形成连接邻房的中间区域；外形相似不代表同一规则。检查单开、双开、交换顺序、关闭恢复及角落对象归属。缺门导致不可达时指出具体矛盾，不自行补门；用户补图后只替换对应版本。
- 房间地板、墙厚、墙顶、门洞、转轴、阴影、热区、气体本体和裁切共用几何真源，不在各绘制函数里分别猜偏移。逻辑子区不一定需要可见隔墙；相连的同一房间先合并轮廓，再生成边界，避免窄连接块多出墙顶/接缝。
- 外墙与可转动门扇独立：门打开后是否保持完整墙面按设计处理，不能因为复用普通门洞代码而漏出场景外。艺术上的阴影不能改变逻辑通路。

## 房间材质、人物与显示区域

材质铺满实际可见地板并裁切；蒸格等重复纹理保持统一单元尺寸/相位，不按每个长宽不一的子块独立拉伸。冰箱边框/内衬限制在指定边界，原素材的把手或透明边距不能露出墙缝。基础物体尺寸用标准房间或短边定标，再按可用空间约束；长房间不自动把锅放大到满房，角落物体避免塞进墙厚。

关卡整体按可用区域求最大统一缩放，并保留已定房间比例。区域带凹口/保留装饰时，不能只拿外接矩形求 fit；检查缩放平移后的真实边界、门旋转范围及必要波动边带是否进入保留区。HUD、标题案板、导航和下一关各自有固定角色，关卡信息位置不复用成“胜利/失败”标题。最终同时看全屏构图和最小房间的可读性，不用任意拉伸填满空白。

## 不透明杯子与食物遮挡

旧球体配新杯子时，先定位各层真实可见轮廓和杯口，而不是只按图片矩形中心对齐。

1. 语义拆层：背侧杯沿、球体/配料、实心杯身、前侧杯沿、杯脚与阴影；具体先后以杯形为准。食物下缘由杯身/前沿遮住，上缘保持完整。
2. 统一椭圆透视、杯口左右端点和球体支撑位置；杯口有效宽度要容纳该组合，不能只扩大透明画布。球体整体缩放/下移后检查配料与杯沿是否相穿。
3. “不要透明杯子”同时检查填充 alpha、绘制先后、镂空路径和旧数据覆盖。填充不透明但食物仍画在杯身上方，同样会呈现透视穿帮；再调 alpha 无法修复。
4. 使用用户实际保存的图层与参数检查，不能只证明默认配方正确。融化终态、游戏缩小显示和结果弹层分别看合成图；单层 PNG 正确不证明组合正确。

## 浏览器微调如何可靠回流

仅在用户要求可编辑预览时提供编辑器；普通小改不强制开发新工具。

- 按语义图层提供选择、移动、缩放、旋转、层序和可见性。添加装饰与编辑透视是不同能力，按请求提供；不要把“能调位置”说成完整编辑。
- 文档有 schema/version、稳定对象 ID、父子关系、变换、层序、材质和素材来源。用户保存的值是输入事实；新增默认参数不能静默覆盖旧草稿，旧草稿也不能无提示绕过本次要求的实心遮挡规则。迁移保留原件，并说明冲突如何解决。
- 四角透视/单应变换与普通平移旋转缩放分开存，按一致顺序组合父子变换。导出的实际形状与预览使用同一参数链；目标原生控件不支持的变换必须明确近似方案，不丢字段后声称忠实还原。
- 保存时把参数、导出几何、缩略图/合成图和版本绑定为同一快照；完整写入成功后再更新当前版本指针，避免图片来自新版、参数来自旧版。页面成功提示需对应真实保存结果，刷新后能恢复。
- 在用户实际保存状态上验证导出；修改限定在图层/字段白名单。局部替换保留其他已定稿层，不能通过剔除整个美术配置来证明“未变化”。

## 分层的所有权

场景普通美术、气体、达成反馈、HUD、结果模态、转场分别设置层级。背景是常驻场景资源时只创建一次，切关清理不应销毁它；结果是关卡上的叠层时保留底下关卡及撤销历史，不能跳到仿造关卡的新页面。跨层动画与恢复由 [场景动效](../../miliastra-motion/references/stateful-scene-motion.md) 及 [交互生命周期](../../miliastra-code/references/ui-interaction-reliability.md) 负责。

圈线/箭头等截图标注仅用于定位。按圈选删除箭头时确认目标实例；不顺手去掉所有门的提示，也不把绿色框画进正式游戏。验收查看轮廓、遮挡、实际屏幕尺寸和场景上下文，不只检查中心坐标或控件边界相交。
