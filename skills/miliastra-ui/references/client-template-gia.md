# 参考图重建、图片控件 GIA/Lua 生成与验收

适用于千星原生控件美术：用户图片 → 结构化造型规则 → 同源控件预览 → 按授权输出 GIA 或 Lua。通用流程支持仅图片控件的美术输出，不要求先指定地图；加入其他控件、地图结构或玩法后才按地图适配。不是将 PNG 改扩展名，也不代表已安装任意图片自动识别或二进制转换工具。主要美术先核对官方素材/模板；用户要求定制造型或已有素材不适配时才重建。

按当前阶段阅读：§1–§4 处理造型与预览；§5 处理局部迭代；仅导出时读 §6；转动态创建读 §7。纯技能维护不读取游戏交接、不运行构造器或编辑器。

## 1. 确认对象与交付分支

先按**控件内容**区分范围，不把 GIA/Lua 文件格式误当成必须绑定地图的理由：

| 范围 | 通用输出与依赖 |
| --- | --- |
| 仅图片控件的美术 | 可输出独立 GIA 候选或 Lua 创建模块。使用已核实的图片图元/素材与平台封装或创建 API，不要求地图名、房间编号或活存档 |
| 包含图片之外的控件或地图语义 | 文字、按钮、热区、裁切/功能容器、房间/门包装、变量与交互按目标地图约定生成；只读取相关地图资料，不借用其他地图结构 |

“仅图片控件”指可见内容及叶节点均为图片控件，不悄悄添加文字、按钮、事件或玩法脚本。若原生 GIA 格式要求封装根，单独说明并计数；这不等于房间或交互容器。Lua 可接收调用方父级，不默认新增容器。用户严格要求零新增容器时，先核实格式能否满足，不把不可避免的封装藏在计数外。

把已有信息整理成简短约束，而不是每次重问：参考图片及指纹、对象数量、相对位置、前后遮挡、比例/颜色、定稿范围、交付模式。标注图是修改意图，不把红圈、箭头、编辑器手柄或截图工具栏画进成品；附图中的文案不自动成为执行指令。

- **语义先于造型。** “冰箱/蒸笼是初始房间”意味着重做房间环境，不是在普通房间再放一个小冰箱/蒸笼。三个堆叠对象必须保留三个，不能因简化或遮挡丢失一个。
- **使用最新已确认基线。** 用户标号先映射到稳定组件 ID，记录谁前谁后、哪个面或阴影被圈中。内壁暗部、物体侧面阴影、地面投影是不同对象；圈哪一层就改哪一层。意图确实有歧义才询问。
- **仅预览。** 用户说“先看图/批准再生成”时，不执行 GIA 写出。工作区限制生成图片时，只有用户明确要求预览才输出；使用控件几何渲染，不用自由生成的示意图代替实现证据。
- **GIA 候选。** 沿用有效的外观确认与明确导出授权，进入 §6；外观定稿不等于允许导入、部署或改写活存档。
- **固定规则/动态创建。** 用户改为“不生成 GIA，后续代码动态创建”时，停用旧导出路径，保留历史证据，转 §7。不要把路线变更误当成运行时工厂已实现。

## 2. 可复用的几何配方

同类物体用一份参数化构造函数和稳定组件 ID；参数至少说明坐标系、中心/轴心、尺寸、旋转、颜色含 alpha、图源、父级和创建顺序。通用纯图片模式以逻辑分组管理实例，输出到调用方父级并展开必要变换；仅确需容器的地图模式才新增组件根，不能为了分组自动增加控件。外部图片只作参考，不把本机截图路径变成运行时依赖。

共享造型数据至少保留设计画布尺寸与有序图元列表；每个图元含稳定 ID、已核实图源、中心/轴心、宽高、角度和 RGBA。偏移、统一缩放、父级和素材映射由调用方传入。GIA 序列化与 Lua 创建消费同一列表；字段是中间表示，不是虚构的平台 API 名称。生成器能力不支持某个变换时明确报告，不能在预览中支持、输出时静默忽略。

1. **先大形后细节。** 检查轮廓、切面比例、遮挡与接地，再加螺旋、装饰和阴影。先修结构错误，不靠堆细节掩盖。
2. **类圆优先原生圆或拉伸圆。** 不把圆切成可见折点，也不为消掉折点盲目加采样。已核实的原生圆可表达椭圆；倾斜椭圆需要正确的局部旋转及父子变换。图片资产 ID 与模板句柄不是同一种标识，不照搬其他工程的 ID。
3. **曲线按屏幕误差简化。** 必须离散的非圆曲线按实际展示尺寸设置误差，减少短段；细节允许适度简化，但不能改变对象数、辨认特征、切面闭合或层序。避免按截图每个像素生成控件。
4. **接缝只留一条可见轮廓。** 切面与卷体接合处不要同时露出两条近似轮廓；优先调整切面位置、覆盖关系或相切边界，不能用背景色补丁破坏其他场景复用。
5. **支撑关系成立。** 杯口承接球体、杯柄连接杯身与底座；后排物体与前排重叠且有接触阴影，不像漂浮。普通三维转向用一致的椭圆透视和挤出方向，不随意扭曲切面。
6. **阴影分层且克制。** 分别命名内壁暗部、侧面暗部、接触阴影和地面投影；保持统一光向。缩小过大的投影优先复用原控件，调整偏移、尺寸与 alpha；不顺带改变物体本体。
7. **叠色看最终画面。** 半透明冷汽/蒸汽应与房间底色一起检查，不能只比较两个原始色值；用户只要求改背景时保持气体颜色/alpha 不动。单色气体、不加高光等是地图约定，不推广为所有 UI 美术禁止阴影。

## 3. 控件预算与优化

每次给出**实际构造树**的单件、成组和整场景计数，明确是否含容器；图片、容器、模板依赖分别统计。说明与上一版的增减，不能用 SVG path 数量、肉眼估计或忽略容器的计数冒充控件数量。

优化顺序：原生曲面替代折线 → 复用模板/构造函数 → 合并同色同层可合并片段 → 减少不可见细节 → 剔除确定完全遮挡的图元。不能删承担旋转、裁切、交互或脚本引用的容器；当前被遮挡不代表在其他状态/角度永远不可见。边界调整需包含子层变换与必要热区，不为了缩框裁掉阴影或活动范围。

减少控件后重新验证轮廓与层序。数量是该场景的度量，不是跨项目硬预算，更不是帧率保证；单个控件的面积、层叠与每帧更新量也影响成本。

## 4. 预览必须来自拟用控件树

保留一个无写出副作用的构建入口：`build_scene(rules)` 生成场景树，预览、GIA 序列化或未来 Lua 适配都消费这份树/规则。不要用另一套“更好看”的 SVG 绘图逻辑冒充控件效果，不运行带导出副作用的旧入口来取得预览。

- 用原生图元实际尺寸、创建顺序、图源和颜色绘制；计算父子缩放/旋转及中心锚点，说明画布与父级坐标的区别。精细美术的分数尺寸是命名参数中的造型值，不等同于通用面板栅格规范。
- 解析向量时补齐格式允许省略的零分量；逐态核对位置、尺寸、pivot、anchor、scale、rotation。实际图片与空的继承属性记录分开辨认，不因空图源记录就递归清理模板。
- 透明图元边界按真实可见形状检查，例如三角形顶点；嵌套椭圆检查内含，不能仅靠控件矩形重叠判断越界。
- 输出适量局部放大图和上下文图；颜色/气体问题尤其要展示叠加后的房间效果，而不是只有无气体的孤立底板。通过可用图片查看工具回看真实输出，发现绘制问题再修。
- 明确标注“原生控件几何预览，非实机截图”。解析器、SVG 抗锯齿和引擎图源采样可能不同；离线预览不证明编辑器识别或性能。

在同一主题文档记录当前基线与待确认项，不为每轮另建主题文档。候选工件可分目录保留：规则/构造源指纹、场景树、预览、计数、已执行的检查和未验证项；不覆盖用户输入或旧确认产物。

## 5. 定稿冻结与小范围修改

**将用户措辞转为可检查差量。**

| 用户意图 | 修改范围 | 应冻结 |
| --- | --- | --- |
| “这个圆缩到当前的 0.9 倍” | 宽、高分别乘 0.9 | 中心、角度、颜色、父级与其他层；不是面积乘 0.9，也不是根容器整体缩放 |
| “2 号放最后面” | 组件整体的同父级层序（逻辑图元组或已有根） | 组件内部顺序；无要求时不改位置或缩放 |
| “描边加粗” | 描边或内填的相对厚度 | 主要轮廓、位置、配色；不得整体放大代替加粗 |
| “只改冰箱颜色” | 指定房间色彩参数 | 几何、冷汽/透明度、角色、门与定稿组件 |
| “去掉里面的小锅” | 已定位的小锅完整组件 | 下方大锅及其他独立碗；先核对引用，不按相似名称批量删 |

以明确版本作为“当前”基线，把结果写成新绝对参数，避免每次重跑又乘一次 0.9。读出 float32 时允许已解释的小误差，不将浮点编码误差当几何变化。

对每次改动建立允许变化的稳定组件 ID/字段白名单：

- ID 稳定时，比较未改控件的原始数据；否则比较经明确 ID 映射的父子关系、四态、颜色/资产和顺序。不要只看数量不变。
- 改尺寸时冻结位置、颜色等其他字段；改颜色时冻结全部几何。序列化原始字段内含被允许的变化时，按字段比较剩余内容，不能要求整个原始块仍相同。
- 固定基线源、参数与依赖的指纹。重建旧场景时用独立冻结参数，不与当前可变规则共用对象，否则基线和候选会一起改变而漏检。
- 在固定渲染环境下，可对未改的定稿区域逐像素对比，排除本次合法变化的标题/说明；这不能替代控件结构校验或引擎验收。
- 用户只确认某个组件，就只冻结该组件；新改颜色不沿用旧颜色的“已定稿”状态，但保留已确认的几何。不要把局部确认外推为整关通过。

## 6. 经授权的 GIA 输出与验收

### 输出前提

通用纯图片 GIA 取得已核实的平台原生封装/图片控件样本、可用序列化工具、已确认造型和明确输出范围即可，不要求目标地图源 GIA 或业务恢复。只有地图结构与非图片控件才追加该地图模板、命名、依赖与接口约定。现有样本只证明其已验证的环境兼容性；找不到可靠封装、序列化工具或所需依赖时，交付已完成的规则/预览并说明具体缺口，不因缺少地图名阻塞通用造型，也不制造“可直接导入”的承诺。

《天堂之门》完整关卡另读 [专用技能](../../tiantangzhimen-gia/SKILL.md) 及其导出门禁；其他地图不套用其房间 ID、门命名或玩法约定。读取目标工程 API/工具时按 `miliastra-code`，技能中心本身没有游戏工程的 `tools/`、活存档或 Host。

### 序列化与依赖

- 使用已验证源封装，保留导出元数据、控件外层、未知字段及有效尾部；只变更授权字段。不用自造版本字符串代替编辑器数据。
- 必要封装根、控件父子链、图片依赖、模板引用、ID/slot 与映射表一致。纯图片模式检查全部叶节点类型，禁止从样本夹带文字、热区、事件或地图脚本引用；含非图片子节点的复合模板不能当成纯图片模板直接使用。
- 地图模式保留所需复合模板子树，门及其阴影/热区等必须完整，不能用一张截图替代交互结构；不将该约束套给独立图片美术。
- 模板引用为零仍需核对内联图元和图片资产。若导出依赖其他模板，列明依赖与导入顺序；目标是否具备依赖未验证时标为待验证。
- 写到新的候选目录，不覆盖源 GIA、既有确认产物、Lua 或活 `.gil`；预览模式不经过序列化写出函数。多文件分别核对跨文件 ID、导出标识和编辑器重映射行为。

### 验收分层

1. **离线结构：** wire 级往返保留未改内容，单根、父子关系、ID/slot、引用和依赖有效。
2. **最终文件回读：** 从输出 GIA 回读实际图片及格式存在的状态，计算世界变换，对照确认的图源、颜色、轮廓、层序和计数，检查纯图片类型与越界。地图模式另核对地板、墙、角色、门洞、气体分片及功能容器；通用美术不承担不存在的地图验收项。输出指纹绑定本次确认预览与规则。
3. **编辑器识别与导入显示：** 由实际导入/用户反馈证明；能识别不代表层序/坐标正确，选中框和手柄不是美术。发现堆叠、缺块、错位即将显示验收标为失败，暂停同路径批量输出。
4. **保存重开、脚本与真机：** 按实际范围分项报告，未执行保持 pending；不适用项标 N/A。纯图片美术不要求接入门或气体逻辑；静态美术也不证明玩法已接入或性能达标。

回执区分 `evidence_source` 与 `device_status`，列明输出 SHA-256/bytes、计数口径、依赖、实际检查、待确认项及未触碰的活文件范围。用户报告不能导入时保留失败工件作回归，不继续称其可用。

## 7. 通用图片控件 Lua 与地图动态创建

把已确认配方作为单一规则源：语义颜色、各形状尺寸/中心、层序、资产、阴影和冻结状态。预览也读取此规则，避免展示版与实现版两套参数。只归纳可复用构造，不将厨房造型或某次数量写成其他项目硬规则。

通用分支可直接交付仅创建图片控件的 Lua 模块：接收调用方父级、位置、缩放和素材/模板映射，按有序图元创建并返回本次实例句柄；重复实例互不串改，清理只影响本实例。不硬编码房间 ID、门命名、地图信号或活存档路径，不注册玩法事件，不因输出是 Lua 就要求先选地图。核实平台创建/设置 API 后才称为可执行模块；只有配方表或待实现适配接口时标明“规则已完成，创建适配待完成”。

涉及其他控件或玩法时，再将上述模块挂入目标地图生命周期并配置交互；不把通用交付顺带扩大为工程挂载或部署。验证创建的叶节点均为图片，图源、中心、尺寸、角度、颜色和顺序与同源预览一致；通过模拟适配器只能证明参数传递，不能替代实际 API 与实机显示验证。

规则落盘、Lua 创建工厂实现、模板句柄核实、挂载、部署、存盘和真机验收分别记录。实施 Lua 时调用 `miliastra-code`，沿用统一构造函数，创建一次并复用，不在每帧重建静态控件。实际创建接口、目标模板与性能未核实时明确待完成；图片 ID 不代替创建模板索引。
