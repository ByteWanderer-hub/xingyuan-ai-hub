# UI 的数据来源与渲染归属（"这块字为什么晚一拍 / 为什么不显示"）

> 《侦探杀》真机一轮暴露的问题里，**一半不是画得不好，而是"这块字的数据从哪来、谁负责画"没定清楚** ✗。
> 本文补上 UI 规范缺的那一维：**每个可见区域，除了"摆在哪、多大、什么色"，还要写清"数据走哪条通道、由哪个脚本重画"** ✓。
>
> 用法：**Step 2 出坐标表时，多加一列「数据来源 / 通道」与一列「渲染者脚本」** ✓（见 §5 表模板）。

---

## 1. 三条通道的**时机差**（决定了"哪块字会落后"）

| 通道 | 时机 | 用它显示的后果 |
|---|---|---|
| **`Invoke` 直推**（客户端脚本 → 客户端脚本） | ⭐ **当帧同步** | **不会落后** ✓ —— 即时反馈必须走这条 |
| **自定义变量 + 服务器信号**（→ 节点图 → 变量） | **异步**（要过信号与节点图 ✓ 通常 ≥1 帧） | ⚠️ **必然晚一拍** ✗ —— 只适合"状态"，**不适合"刚发生了什么"** |
| **黑板文本框**（旧做法） | 写入当帧 ✓ 但**读方什么时候重画不定** ✗ | ⚠️ 时好时坏：**点一下才对齐** / **隔一条才显示** ✓ |

### 症状 → 病因对照（照这个查，别改画法 ✗）

| 屏幕上的症状 | 十有八九是 | 怎么修 |
|---|---|---|
| **"落后一条"**：刚发生的消息没出现，做下一个动作才补上 | 这块字**走变量**（异步 ✗） | 改成 **`Invoke` 直推** ✓ |
| **"点一下才对齐"**：数据其实早到了，就是屏上不更新 | 读方**只在某个时机重画**（点击/状态变化 ✓） | 直推 + **到达即写**（或让该区每帧对齐 ✓） |
| **"隔一条才显示"**：第 1 条有、第 2 条没有、第 3 条又有 | 数据源**有两份在交替**（如"本容器黑板为空就换另一份"的兜底 ✗） | **消掉多来源** ✓ 只留一条权威通道 ✓ |
| **"整块界面消失"**（控件数/位置尺寸都对，就是不画） | ①文本框高度 < 字号×1.4（§3.1 铁律 ✓）②**读方因为"控件没了"整块 return** ✗ | ①按行高给足 ✓ ②护栏改成"有直推就继续画" ✓ |
| **某条字压根不出现**（连一次都没有） | 推送**从未发生**（如守卫读了个**不存在的名字** ⇒ 静默 no-op ✗） | 在**守卫内侧**打一行日志 ✓ 看它有没有进去 ✓ |

## 2. ⭐ 渲染归属：每个可见区域**必须有一个唯一的"渲染者脚本"**

UI 布局表里通常只写"这块放什么"✗ —— 出问题时才发现**没人画它** / **推给了不画它的人** ✗✗。

**规矩**：
1. **一个可见区域 = 一个渲染者脚本** ✓（谁把字写进那个控件 ✓ 就归谁 ✓）
2. **推送前先确认真身** ✓：`grep` 渲染点（字段名 / `setText(` ✓）—— **不按模块名猜** ✗
   （实测代价：把滚动日志推给了 board 和 view，而真正画它的是 **HUD** ✗ ⇒ 连改两轮、日志还显示"推送正常" ✗ 更容易误判成修好了 ✗）
3. **要压在最上面的东西（弹窗/提示条/按钮）只许建在最上层脚本里** ✓（与 §1.4b/§6 同一条纪律 ✓）
4. **删任何控件之前**：先 grep 有没有 `if <控件> == nil then return end` 这类**整块早退** ✗
   ⇒ 有就改成"**只要新通道有值就继续画**" ✓ 否则一删控件整块界面就没了 ✗✗

## 3. "提前布点"：换数据通道时**不弄坏画面**的做法

UI 最怕"为了改数据来源把画面改坏" ✗。稳妥顺序（每步都可回退 ✓）：

1. **先加新来源，不动旧来源** ✓ —— 渲染时 **新值优先、旧值兜底** ✓
   ⇒ 新来源还没就绪时 = **纯 no-op** ✓（画面一个像素都不变 ✓）
2. **打一行"命中日志"** ✓（命中数变化时才打 ✓）—— 这就是"新通道到底通没通"的判据 ✓
3. 观察一局没问题 ⇒ 才把旧来源降级为兜底 / 删除 ✓
4. **删控件永远是最后一步** ✓（且先补 §2.4 的护栏 ✓）

> 一句话：**"换数据源"应该像换灯泡——先把新的接上、亮着，再拆旧的** ✓；不要"先拆后接" ✗。

## 4. 验收：把"字对不对"变成可判的

| 要问的 | 判据 |
|---|---|
| 值有没有到？ | 日志里**命中数 / 推送行**（"该出现却没出现"= 最强定位信号 ✓） |
| 画面更没更新？ | **截图**（`.gia` 落盘会随机失败 ✗ ⇒ **别用"日志里没有"当"没跑"** ✓；画面为准 ✓） |
| 动效在动？ | `miliastra_sim op=frames`（帧间像素差 ✓） |
| 顺序/压盖对不对？ | 三句自检：**结算面板在上面吗 / 按钮看得见点得着吗 / 格子上的字被图盖住了吗** ✓ |

## 5. 表模板（Step 2 版面表 —— 加两列就够 ✓）

| 区域 | x | y | w | h | 字号 | 颜色 | ⭐ 数据来源 / 通道 | ⭐ 渲染者脚本 |
|---|---|---|---|---|---|---|---|---|
| 主画面格子 | … | … | … | … | 28 | 文字 | 变量+信号（状态 ✓ 可晚一拍） | `board` |
| 事件日志 | … | … | … | … | 22 | 次要 | ⭐ **`Invoke` 直推**（"刚发生" ✗ 不能晚） | `hud` |
| 消息 / 提示条 | … | … | … | … | 22 | 强调 | ⭐ **`Invoke` 直推** | `board` |
| 时间 / 名声 | … | … | … | … | 22 | 数值 | 变量+信号（状态 ✓） | `hud` |

**填表时的三条判据**：
- 这块字**"晚一拍会让人以为卡了"** ⇒ 必须 `Invoke` 直推 ✓（消息 / 滚动日志 / 动作提示 ✓）
- 这块字**"慢一点无所谓"** ⇒ 走变量 ✓（时间 / 分数 / 关卡 / 开关 ✓）
- **同一块区域的多个字段，尽量用同一条通道** ✓（混着来最容易出现"一半快一半慢" ✗）
