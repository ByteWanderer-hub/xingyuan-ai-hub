# 产物回看：截 → 读 → 修 → 复截（千星 UI 版）

> 对应 `code-vue` 的 Step 5「产物回看（截→读→修）」，但千星这边**必须更依赖画面**：
> 客户端**没有几何 getter**（`posX/width/anchoredPosition` 读出来都是 `nil`，见 SKILL §1.3）⇒
> **截图是唯一的验收手段**。而"看不出问题"通常不是因为没问题，而是**没有按清单逐条问**。

---

## 0. 四步闭环（缺一步就等于没验证）

| 步 | 动作 | 要点 |
|---|---|---|
| ① **截** | `miliastra_shot target=game`（游戏画面）/ `target=editor`（沙箱编辑器） | 回执带 `pid / process / title` —— **先确认截对了窗口**（实测抓错过程序，光看 `ok:true` 发现不了） |
| ② **读** | `read_image <png 绝对路径>` | **必须自己看**。禁用替代品：日志"没报错"、PNG 字节数、别人的描述 |
| ③ **修** | 每次**只改一处** | 回复里写清"改了哪 / 为什么 / 预期画面怎么变"——否则第二张图无法对比 |
| ④ **复截** | 再截一张对比 | **没有第二张图 = 没有验证**；改完直接说"好了"是不合格的 |

> ⚠️ **字节数不是判据**：实测同一关卡的正常画面 41.8 KB，而"控件还没建完"的那张反而 109 KB（平色压缩率高）。
> 要对比就用**同场景的哈希/像素差**，或者干脆看图。

## 1. 看图必问的 6 句（依次问，别跳）

| # | 问什么 | 不合格的样子 | 依据 |
|---|---|---|---|
| 1 | **读得清吗？** | 文字直接压在素材/花背景上、灰字配灰底 | SKILL §3.3（对比 ≥4 级、压素材垫暗底） |
| 2 | **有层级吗？** | 所有文字同字号同色；大而模糊的装饰抢焦点 | §3.1 字号 4 档 / §5 黑名单 4 |
| 3 | **谁在上？** | 结算面板压住按钮、角图压住格子文字、提示条被格子盖住 | §1.4b 层序契约 |
| 4 | **能点吗？** | 按钮/热区被"清理逻辑"或装饰盖住；弹窗出现时热区不在最上 | §6 多脚本纪律（白名单） |
| 5 | **边界干净吗？** | 亮白大色块当底板；同屏两种边界做法（内条 + 素材面板混用） | §3.3 / §4 面板边界 |
| 6 | **有没有"随手数"？** | 元素间距忽大忽小、宽度不在 480/720/960 档 | §2 栅格 8 基数 |

## 2. "动效真的在动"要拿数字，不靠感觉

```powershell
# 三个时间点各出一帧 + 帧间像素差（可复现：内部是"暂停+单步"推进）
miliastra_sim op=frames frames:[0,0.5,1]
```

- 回执里看三个字段：`changedPixels`（变了多少像素）/ `changedRatio` / `changedControls`（**哪个控件的哪个字段变了**，例如 `matrix.tx: 800 → 850`）。
- 判据：**静态界面**应当 `identical:true` 且 `changedPixels:0`（这本身也是证据：说明确实"没动"）；
  **动效**必须 `changedPixels > 0`，且 `changedControls` 指向你预期的那个控件。
- 长动效（阶段切换、弹窗入场）取 3~4 个时间点：`frames:[0, 0.3, 0.8, 1.5]`。

> 真机侧的等价物：`miliastra_shot op=burst`（连拍）后**比两张图的差异区域**；
> 注意开局 **~14 秒是加载画面（星空）**，要看进图后的帧，别把加载图当界面。

## 3. 提升命中率的三个习惯

1. **对位辅助线**：脚本顶部留 `DEBUG_GRID = false`，打开时用图片控件画安全区（32 边距）与 8 倍数横竖线（≤20 条），
   截图一眼看出"差了几格"；**验收前必须置回 `false`**（SKILL §6）。
2. **固定取景**：同一个界面版本用同一取景（同 target、同窗口）再截，**只在改了一处之后**复截，才能归因。
3. **HUD 当闭环条件**：读画面上的字优先用 `miliastra_sim op=hud`（只回 `textbox.text`），比整屏 dump 场景省一个数量级。

## 4. 不能截图 / 拿不到通道时的降级

| 缺什么 | 怎么办 |
|---|---|
| 不能截图（插件没跑、模拟器不可用） | 让创作者截图；自己**只做"可计算"的部分**（坐标表 + 颜色表 + 层序表），把"看不清/丑"的判断交出去 |
| 拿不到画布尺寸 | 按 1600×1000 设计，代码里保留 `GetUICanvasSize()` 校准（**勿写死**） |
| 拿不到素材/模板索引 | **不许编造**——先用色块 + 文字把结构搭出来，把"素材接入"标成待办 |
| 模拟器通过 ≠ 真机通过 | 官方素材渲染 / 联机 / 手感不覆盖；这类项如实标 `pending`，别写成"已验证" |

## 5. 三种常见误判（本工程真实踩过）

| 误判 | 真因 | 正确做法 |
|---|---|---|
| "画面是空的 → 代码没建控件" | 截在了**加载画面**或**脚本还没跑完那几帧**（frame 0 时 `treeCount:0`） | 等进图/推进几帧再截；或用 `op=frames` 指定时间点 |
| "两张图一样大 → 没变化" | 用**字节数**代替像素对比 | 比 `op=frames` 的 `changedPixels`，或同场景哈希 |
| "日志没报错 → 界面没问题" | 日志只证明**代码跑了**，不证明**画面对** | 画面问题一律看图（本文四步闭环） |
