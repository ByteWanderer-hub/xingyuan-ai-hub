# UI2 栅格档位：坐标 / 尺寸 / 间距取 8 的倍数

> 归属：`miliastra-ui` 客户端 UI 铁律｜细则正文在 SKILL.md §2

## 违反长什么样

- 20 / 37 / 53 / 620 这类**随手数**出现在坐标、宽高、间距上。
- 面板宽度不是三档之一（`480` / `720` / `960`）。
- 外边距 < 32；元素之间 < 24；不同分组之间不是 48。
- **横向分配加不平**：实测踩过 `桌面 1232 + 右栏 480 = 1712` ✗ —— 超出设计稿 1600 共 112，真机上会被裁掉 / 挤变形。

## 为什么

- 设计稿 1600 × 1000 + 外边距 32 ⇒ 内容区 1536 × 936；节奏基数 **8**，所有数从 8 的倍数里取（8/16/24/32/48/64/96/128）。
- 有档位就**不用测量**：客户端读不到几何（§1.3），"查出来的数字"比"调出来的数字"可靠。

## 正确写法

- 只从 §2 的表取值；面板宽只三档；元素间 ≥ 24、分组间 48；外边距 ≥ 32（整屏背景除外）。
- **横向 / 纵向分配用"固定件优先"**：先把固定件（侧栏 / 底栏）写死，主区取**剩下的那一份**
  （`主区 = 1600 − 边距×2 − 间距 − 侧栏`）。
- 算不平 ⇒ **改档位或把边距降到 24**；**不许随手写一个接近的数**（那违反 UI1，宁可 `-- TODO(token)` + 算过的候选）。

## 审查动作

```bash
node tools/check-ui-contract.mjs       # 坐标 / 尺寸是否 8 的倍数
```

外加人工逐行加总：横向合计 = **1600**、纵向合计 = **1000**（常见分配对照表见 SKILL.md §2）。
