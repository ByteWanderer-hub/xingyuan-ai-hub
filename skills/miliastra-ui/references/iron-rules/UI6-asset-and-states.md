# UI6 素材按类型复用；可点元素四态

> 归属：`miliastra-ui` 客户端 UI 铁律｜细则正文在 SKILL.md §1.5 · §4.1

## 违反长什么样

- 无必要地拆散复合模板、破坏素材内部关系；将独立官方单图误当作必须整组导入，或直接写未文档化的 `rotationZ` 字段。
- 素材**只摆位不缩放** ⇒ 原始尺寸糊满半屏、把面板全盖住（实测：玩家问「**这一整块是个啥**」）。
- **可点元素没有任何状态反馈**（悬停 / 按下跟常态一模一样）⇒ 玩家不知道能点、也不知道点没点上。
- **弹窗出现了却没开 `showCursor`** ⇒ 光标事件根本不派发、点不动。

## 为什么

- 复合模板可以整体实例化、缩放和位移；独立图片可按用途直接接入。当前 API 提供 `SetLocalRotation`，不能以 `rotationZ` 字段写入失败推断平台不支持旋转；实际显示仍需验证。
- 素材「原始尺寸」通常远大于栏位：实测「人物解释图片」原始约 **740 × 900**（设计稿 1600 × 1000 的半屏）。
- **只有 PresetButton 自带多态**；图片 + 文字自绘的按钮必须在事件回调里自己改属性。

## 正确写法

- **能整组就用整组**；**先整体缩放再摆位**（例：放进 480 宽栏位 ≈ `SetLocalScale(0.6, 0.6, 1)`）。
- 复合模板保留原子树，禁止递归 sanitize 或按空 imageId 批量隐藏。仅对已核实的单图模板白名单处理空图，先排除容器、热区、动态填充与其他读取依赖，见 [工程 V2](../../../miliastra-code/references/iron-rules/V2-no-sanitize-composite.md)。
- **四态**（至少前三态）：常态（底板色 + 主文字）· 悬停（`CursorEnter/Exit` 提亮一档，如底板 (28,32,48)→(58,66,92)）· 按下（`CursorDown/Up` 压暗，或 `SetSizeDelta` 缩 4~8px）· 禁用（降对比，**不用纯灰**——会踩 UI4 第 1 条）。
- ⚠️ **硬前置**：光标事件需**祖先容器 `showCursor = true`**（引擎与文档同款）。做法：弹窗 / 菜单出现那一帧置 true、关掉置 false（常开会挂一个常驻光标，很难看）。
- 热区与视觉分开建时（透明"光标检测区域"压最上层），**状态视觉改的是底下那层图片 / 文字**，不是改热区。

## 审查动作

```bash
grep -n 'showCursor' <脚本>     # 有光标交互却没有 true/false 切换 ⇒ 打回
grep -n 'rotationZ'  <脚本>     # 写了就是白写（平台不生效）
```

外加截图看：可点元素有没有悬停反馈；素材有没有糊满屏。
