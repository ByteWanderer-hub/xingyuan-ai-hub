# UI4 颜色只从语义色表取；对比三条硬规则

> 归属：`miliastra-ui` 客户端 UI 铁律｜细则正文在 SKILL.md §3.2 · §3.3

## 违反长什么样

- 颜色不取自语义色表（随手 `(120, 200, 255)`）。
- 文字与背后**亮度差 < 4 级**（中间灰对中间灰）。
- 文字**直接压在素材 / 花图上**不垫底 —— 实测教训：「证词整理」直接压素材，几乎读不出来。
- 用大面积纯白（如 `100001` 白底图）**当面板底板**：刺眼且盖住一切。

## 为什么

"看不清"的头号原因不是审美，是**随手配色 + 直接压花图**；语义色表让"这个颜色属于什么用途"一眼可查（与 UI1 同一张表）。

## 正确写法（语义色表）

| 语义 | RGBA | 用途 |
|---|---|---|
| 主文字 | (245, 240, 234) | 正文、标题 |
| 次文字 | (184, 184, 196) | 说明、辅助 |
| 强调 / 数值 | (255, 210, 77) | 分数、星级、关键数字 |
| 成功 | (140, 240, 168) | 指认正确、通过 |
| 警告 / 失败 | (255, 122, 110) | 指认错误、失败 |
| 面板底板 | (28, 32, 48) | 深色底 |
| 面板描边 / 分层 | (58, 66, 92) | 做边界感 |
| **半透明文字底** | (10, 12, 20, **190**) | **文字压素材 / 花色上必须垫** |
| 全屏遮罩 | (8, 10, 18, **180**) | 弹窗 / 暂停时压暗场景 |

三条硬规则：① 亮度差 ≥ 4 级；② 压素材必须垫半透明暗底；③ 亮白大色块不许当底板。

## 审查动作

- 截图逐条问「**读得清吗**」（§7 清单）。
- `grep imageColor` 对照语义色表；出现表外颜色 ⇒ 要么回表，要么补进表并写明语义。
