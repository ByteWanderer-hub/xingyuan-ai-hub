# UI3 字号只许 4 档、同屏 ≤3 档、正文 ≥22

> 归属：`miliastra-ui` 客户端 UI 铁律｜细则正文在 SKILL.md §3.1

## 违反长什么样

- 自造字号：15 / 17 / 56 / 60（想"大一点"就随手 +4）。
- 同屏超过 3 档字号 = 视觉噪声。
- 用**加粗**做层级（客户端字体粗细不可控）。

## 为什么

- 层级只能靠"**字号 + 颜色 + 位置**"三者；字号档位是"可机械判定"的锚。
- 写 60 / 56 会被 `tools/check-ui-contract.mjs` 按 UI3 拦下（白名单只有 `64 / 52 / 28 / 22`）——想加档必须**同时**改表 + 改校验脚本，否则下一个人不知道它算哪一级。

## 正确写法

| 用途 | 字号 |
|---|---|
| 关卡横幅 / 当前关卡条 | **64**（一屏最多一处） |
| 页面主标题 | **52** |
| 小标题 / 正文 | **28** |
| 说明 / 注释 | **22**（**正文下限，不许更小**） |

## ★★ 字号大了，矩形必须跟着高（真机铁律）

- 文本框 `sizeDeltaY` 容不下字号的行高（CJK ≈ **1.4 × fontSize**）⇒ 该控件**整条什么都不画**。
- 特征：**不裁一半、不变小、不报错**，`visible` 仍是 true、日志里 `text` 也确实设上了 —— **只有真机截图看得出**；**模拟器不模拟这个截断**（同代码在模拟器里画得出来）。
- 实测：`52` 号放进 **64** 高 → 空白；`64` 号放进 **80** 高 → 空白；同字号放进 **90~120** 高 → 正常。
- ⇒ 定字号的同时把高度按 `fontSize × 1.4 + 余量` 给足（64 号建议 ≥ 96，常用 120）。

## 审查动作

```bash
node tools/check-ui-contract.mjs       # ① 字号白名单 64/52/28/22 ② h ≥ 字号 × 1.4
```
