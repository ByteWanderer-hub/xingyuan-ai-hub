# UI5 层序 = 创建顺序

> 归属：`miliastra-ui` 客户端 UI 铁律｜细则正文在 SKILL.md §1.4 · §1.4b · §6

## 违反长什么样

- **面板建在按钮之后** ⇒ 面板盖住按钮（真机现象：「**下一关按钮呢**」）。
- **角图 / 素材建在格子文字之后** ⇒ 图盖住文字（真机现象：「**翻牌的文字咋还是没有**」）。
- **提示条 / 弹窗建在底层脚本里** ⇒ 被别脚本建的东西盖住（真机现象：「**文字层级不对**」）。
- 写"**隐藏所有非自己建的控件**"这类清理 —— 实测：`view` 这么写，把 `input` 的**点击热区**和 `fx` 的闪效层一起隐藏 ⇒ **点击彻底失效**。

## 为什么

- 客户端**没有 z-index**：层级 = **创建顺序**（后建的在上面）。
- **跨脚本的先后不可控**（谁后建看脚本执行顺序）⇒ 会互压的元素必须同脚本。

## 正确写法

**① 固定绘制顺序**（照抄就不会错）：

```
1 背景（底板拼块 / 光晕 / 粒子）
2 底层美术（格子底、角图、素材组）
3 文字（格子文字、HUD、面板文字）
4 面板（结果页、弹窗）
5 按钮 / 点击热区（永远最后建）
```

- **② 会互压的放同一个脚本**；**③ 每个脚本头部写一句"我负责哪几层"**（例：`board.lua` = 2+3+4+5）。
- **④ 要盖住别人的东西（弹窗 / 提示条 / 按钮 / 角标）只许建在最上层的那个脚本里**。
- **⑤ 清理兄弟控件必须白名单**：按可辨识特征精确打击（"名为『图片』且图源为空"），并显式**排除**热区与黑板控件名。
- ⑥ 改完**必须重开一局真机验证交互**（层级 / 可见性的改动最容易静默破坏点击）。

## 审查动作

- 交付前截图上问三句（10 秒）：「**结算面板在上面吗**」「**按钮看得见点得着吗**」「**格子上的字被图盖住了吗**」。
- `grep -n 'SetVisible(false)\|GetChildren()' <脚本>` —— 有遍历式清理但**没有白名单条件** ⇒ 打回。
