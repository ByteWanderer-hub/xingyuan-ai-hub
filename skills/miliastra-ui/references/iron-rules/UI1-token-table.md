# UI1 数值只许从脚本顶部常量表取

> 归属：`miliastra-ui` 客户端 UI 铁律｜细则正文在 SKILL.md §3 顶部 · §1.5

## 违反长什么样

- `SetSizeDelta(37, 53)`、`imageColor = (120, 200, 255)`、`fontSize = 15` 之类**在控件创建处裸写数字**。
- 档位里找不到合适的值，就**随手编一个接近的**（最常见：面板块差 4px 就写 620 而不是 608/640）。
- 一次性定位（确实只此一处、不该进档位）**不写标注**，下一个人看不出它为什么特殊。

## 为什么

- 一屏几十个控件：裸写数字 ⇒ **改一处漏九处**，改完版面还是歪的。
- 常量表本身就是 §2/§3 的**落点**：有表 ⇒ 下一个人（或下次改动的你）一眼看出"这个颜色/字号属于什么语义"。
- 与 §1.3 咬合：客户端**几何读不回来**，布局只能"算出来" —— 表就是可复算的那一份。

## 正确写法

- 脚本顶部一张表：`THEME = { ... }`（颜色 / 字号 / 间距 / 关键坐标）。
- 控件创建**只引用表项**（`THEME.panelBg` / `THEME.font.body`）。
- 档位里确实没有 ⇒ 写 `-- TODO(token): 需要 <语义> 档`，**并给出算过的候选值**（不是随手数）。
- 一次性定位 ⇒ 写 `-- one-off: <为什么只此一处>`。

## 审查动作

```bash
grep -nE 'SetSizeDelta\(|imageColor *=|fontSize *= *[0-9]' <脚本>
```

逐处核对：命中且**既不在表里、又没有 `TODO(token)` / `one-off` 标注** ⇒ 打回。
