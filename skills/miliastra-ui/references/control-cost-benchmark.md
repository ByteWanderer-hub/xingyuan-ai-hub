# 千星 2D UI 优化经验：控件成本、运行时与存档

本页是经验参考，不是平台限额或通用性能保证。来源包括作者授权沉淀的 2026-10-29 单设备控件 A/B 实测（`ui-bench-6-full-suite`）、气体流动 UI 工程的离线回放，以及编辑器实际保存文件的体积核验。各节分别注明证据，不能相互替代；不收录角色素材、地图标识、账号路径或游戏脚本，原始工件留在项目工作区。

## 先用于决策，再在目标地图复测

| 触发场景 | 优先做法 | 不变量与反例 |
| --- | --- | --- |
| 大量纯色块组成 2D 美术，要在图片与文本之间选型 | 在视觉要求满足时优先试原生图片底片；不要因文本导出小就替换图片 | 本例文字是非等比缩放的 `█`，不代表普通标签、富文本或所有字体都慢；图片仍须遵守素材白名单与同型资产优先 |
| 切关、开面板、粒子爆发时大量创建销毁 | 比较按需分帧创建和有界对象池，避免热路径重复初始化；预热成本也单列测量 | 不把“全部永久驻留”当结论；池容量、内存、初始化延迟、清理责任需要另测 |
| 短时反复出现/消失，控件无需停逻辑 | 优先实验复用 + `SetVisible`；隐藏期间停止不必要的动画 setter | `SetVisible(false)` 不等于停用、不释放内存；脚本、输入和焦点行为必须按目标模板验证 |
| 确实需要停止控件及其挂载脚本 | 保留 `SetActive` 语义；大批恢复激活时测长帧，必要时分帧恢复 | 不能为省时间把必须停用的功能改成隐藏；也不要停用承担测试/调度回调的父容器 |
| 大量位移/缩放/透明度动画 | 先统计更新控件数×setter数×实际频率；缓存不变值、只更新必要对象，按需求比较父节点整体变换 | 本例动画类型差距很小且缩放结果反转；不能从创建优势推导动画优势。父级变换、原生Tween、更多子节点/脚本未在本例测量 |
| 文本替代图片出现缺口或接缝 | 先做一个控件的小样，核对背景形状、字形可见边界、偏移、抗锯齿与缩放 | 文本背景可能为圆角，不能拿控件外框当实心矩形。浏览器字体预览不等于千星实机字形；必须先视觉验收再宣称等效果性能比较 |
| 静态界面仍每帧大量更新 | 缓存不变属性；章节、对象身份、画布或布局变更时刷新静态部分 | 缓存必须覆盖池重绑、暂停恢复、其他输入管理者和外部写入的失效条件 |
| 用户要求动画“控件减半” | 先明确预建总数、预留容量、实际可见控件、逻辑样本与每帧调用分别是多少 | 预留池减半不等于实际绘制减半，逻辑样本减半也不一定让合并后的原生矩形减半 |
| 相邻片段合并后仍有很多细条 | 查共享边界的浮点误差，以足够小且经过验证的容差统一坐标 | 不能跨真实间隙、墙或气体类型合并；容差不是所有地图通用常数 |
| UI 工程存档超体积预算 | 拆分真实存档中的脚本、模板和其他节，再检查脚本内展开数据 | 外部备份大小、运行时池大小、源代码行数都不能直接代表存档占用 |

## 已测条件与证据级别

- 单个角色由 765 个矩形组成；分别测试 765 与 1530 个叶控件，同数量内两种方案共用目标几何、颜色与先后层序。双角色档缩小并排，不能用两档差值反推单控件线性成本。
- 图片：同一基础底片 `100001` 染色。文本：64 号 `█`，128×128 安全排版框再非等比缩放，关闭背景和描边。模板无子节点、无挂载脚本。
- UI 逻辑画布 1600×900。硬件、客户端版本、真实屏幕分辨率、画质和限帧设置未完整记录；多数回调接近 60Hz，疑似受限帧/VSync影响，不能当已核实设置。
- 两档各反序两轮，穿插空白基线，总 72 阶段；每阶段预热 2 秒、采样 6 秒、冷却 2 秒。创建/销毁每帧最多 64 个，不等于一次性创建峰值。每项显隐/激活切换为 5 次关闭、5 次开启；动画目标 30Hz，按真实更新次数计数，不在卡顿后补大量历史步。
- 72 组结果全部完成，16 组切换次数全部正确，结束残留控件 0；无无效 dt、超过1秒中断、采样上限截断或测试脚本错误。
- `evidence_source=observed`（用户实机日志与截图）；运行链通过，但字符仍有细接缝，**视觉不完全等价**。运行数据可信不等于等画质比较通过。
- 脚本 SHA-256：`A0B03B3C0727BF68BEF8E2417CE33ABA7BBE0FD3D2B5B684BC7CA6E7FF56850B`。原始日志 SHA-256：`dbe850b1617fa7557980c1e89969359f9a7a1a43d663fedd09f5f29fbca27c48`。原件不随技能分发。

## 预览到实机的失败经验

1. **序列化体积不等于运行成本。** 较早的配置记录探测曾得到文本比图片小约8%，并非同视觉内容的完整导出对照，不能推出文本运行时更省。
2. **文本背景不是默认直角底片。** 本例空文本框的背景呈圆角/胶囊，小块呈圆点，拼图大量漏底；这组与图片不是同画面，其性能记录不用于同效果优劣结论。
3. **字形边界不能猜。** 先用基础图片参照与单字符截图测可见宽高、中心偏移；保持文本框足够容纳字号，再缩放。某次字体的参数不写成跨地图常量。
4. **实心覆盖与抗锯齿要分别验。** 半透明边界拼接可能留细缝；按实心内区放大可能造成邻块覆盖、颜色渗边。必须同时核对缝隙、细节、轮廓和覆盖面积，不能以“能认出来”代替等视觉验收。

## 父级透明度实验：不能把层级变换等同于Alpha继承

2026-10-29追加实验，目标为“只改父节点一次，让整组角色渐入渐出”。父级位置、缩放或显隐能作用于后代，不证明父图片颜色Alpha或容器存在同样的整体透明度能力。

| 实验 | 设置与结果 | 可以得出的结论 |
| --- | --- | --- |
| 图片作为父节点 | 左侧765图片静止参照，右侧765图片挂在一个图片父节点下，总1531控件。动画只改父图片 `imageColor` Alpha，父图片自身显示为白色参照条。作者实机确认父图片变淡不带动子图片 | 此配置下父图片颜色Alpha没有产生子图片整体淡入淡出；来源为作者实机反馈（provided_unverified），不是对子树渲染机制的完整证明 |
| 容器模板实例 | 角色直接创建在容器实例下；实机日志确认1531控件构建完成。候选 `alpha`、`opacity`、`transparency` 均 `readable=true type=nil value=nil`；`UNSUPPORTED no_numeric_field=true`，`parent_writes=0 child_alpha_setters=0 child_local_alpha_changed=0` | 这些名称没有暴露可用数值属性，因此没有发生透明度写入或动画。nil不等于Alpha为0；不能描述成“改容器透明度后，子控件不跟随” |

容器运行日志来自 `container-alpha-probe-1`，脚本SHA-256 `6DFE8E3EA35283161E4ECA55962D2A158980FC337D170DCBB5549D6D527B077B`；原始日志SHA-256 `9337b978a0b364d203f51093b6d87a79a747a359cc60bd35b7fbb3040a371eb8`。候选名只是探测假设，**不是已确认API列表**。模拟器此前也返回nil，但结论依据另行取得的实机日志。运行链完成、字段探测有证据，不等于整体Alpha功能通过；不排除其他未发现接口、未来版本或不同控件类型。

应用规则：

1. **目前不把“改容器Alpha一次”当作已支持的优化方案。** 公开容器接口未列整体透明度，已测候选也没有数值。先查目标版本API；确需探针时分开记录读取、写入、回读和视觉结果，不能给宽松包装对象创建任意同名字段后宣称有效。
2. **保持已知可执行路径。** 对需要渐入渐出的图片，缓存参与动画的子控件、原始RGBA，以整体系数乘各自原始Alpha，保留RGB和原有半透明。只更新必要控件和变化值，结束后恢复或按需求隐藏；新增/销毁后更新缓存，不在每帧遍历整棵树。
3. **封装调用不等于一次原生写入。** 一个 `fadeGroup` 或库中的 `groupAlpha` 轨道可以展开为多个子控件颜色更新；报告实际setter数量，不称“父级透明度”或常数成本。文本/背景/描边等字段按动画目标单独选择，不能无差别改色。
4. **显隐与渐变仍是不同需求。** `SetVisible`/`SetActive`的二值切换不能代替渐入渐出；是否继承、是否停脚本及输入行为分别验证。不因本次Alpha探测否定已确认的父级位置/缩放能力。

此补充只更新经验与选择边界，不新增平台字段、脚本或部署授权；完整日志和地图信息留项目工作区。

## 气体流动 UI 工程：从重复更新到实际绘制减量

以下来自同日一个先21关、后扩至25关的原生控件工程。使用实际 Lua 与原生控件替身回放，记录调用数、可见矩形及状态；**未取得本轮目标设备 FPS、GPU、内存或耗时改善证据**。保留平台显隐、停用和输入语义，图片控件选择仍受素材与视觉约束。

### 不变状态只更新一次，变化状态保持原节拍

| 改动与固定负载 | 优化前 | 优化后 | 测量对象 |
| --- | ---: | ---: | --- |
| 复杂场景A静置2秒 | 49,320 | 37,724 | 缩放 setter 次数，减少23.5% |
| 复杂场景B静置2秒 | 27,840 | 20,530 | 缩放 setter 次数，减少26.3% |
| 场景A静置2秒 | 49,320 | 960 | 正弦计算次数 |
| 教程停留1秒 | 5,640 | 3 | 显隐调用次数 |
| 启动预建及首页构建 | 3,558 | 2,626 | 缩放 setter 次数 |

负载以60Hz固定回调回放，气体视觉仍为30Hz。43个检查点的几何、颜色、显隐、热区、父级和玩法状态一致，另验跨关复用、动画中间态、教程与暂停恢复。调用量下降不是同幅度 FPS 提升；替身也不能证明原生渲染观感一致。

可迁移做法：

- 将波形不随时间变化的圆弧系数预计算；同一时间、气体类型和波瓣的正弦项复用；经过边界夹取后数值没变，则不再写缩放。保留原表达式与时间推进，避免缓存改变相位或运动周期。
- 教程遮罩分片、框选、箭头、文案属于静态布局；只在章节、布局、画布、棋盘变换或重新显示时重算。脉动圆环与进度点仍更新，不把整个教程冻结。
- 提示/结算按钮的显隐按状态变化更新，同时核对控件身份及当前热区/焦点状态。只缓存一个布尔值会漏掉复用后的新控件，或覆盖弹层、暂停恢复对输入状态的修改。
- 池重新绑定时清除属性缓存；停止写隐藏动画时仍保留必要的任务与取消逻辑。只缓存本模块独占、能够可靠失效的属性。

### 先分清三种数量，再承诺“减半”

1. **预留原生控件。** 流动池最大容量从1,962减到981，再减到490；同步缩减基础启动池8,384→7,403→6,912，才是真正少实例化，而不是把空闲对象换个容器藏起来。容量需覆盖动作峰值、静态桥接和跨关复用，不把本例数字当平台预算。
2. **逻辑运动样本。** 门口静态桥接改用紧凑连续槽位，使几何样本不再与物理槽号一一绑定；完整几何、路径和计时仍可保留。不能只改池上限，留下指向旧高编号的槽位引用。
3. **实际显示控件。** 第一轮只减少预留量，601组动作的绘制几何与数量都未改变；随后只抽掉一半移动样本，实际平均绘制量仅下降约16%。必须逐帧统计显示的原生控件，而不是拿数组长度或申请容量代替。

最终方案结合移动样本减量与浮点碎缝修正：601组动作中333组包含流动，累计控件帧699,482→298,838，按相同回放帧数加权的平均绘制数31.645→13.520（减少57.28%），峰值154→103。两个复杂场景的均值分别减少47.21%和45.21%，说明**平均减半不代表每帧或每关都减半**。这些是显示控件计数，不是 Draw Call 或 GPU 测量。

该阶段属于视觉取舍：移动中的粒子更稀疏；尚未出发与到达后的覆盖、静止气体、路径和时长保留。不能再沿用前一阶段“中间帧完全一致”的结论。回放检查显示计数与原生池可见项一致、起止覆盖、完成后的门口桥接、非流动消散、无热路径实例化、池不溢出和销毁；有限回放不是所有局面的容量证明，稀疏程度与手感仍待真机验收。

### 浮点误差会制造本不需要的控件

独立算出的相邻矩形边界可能只差极小尾数。扫描线合并若完全依赖相等比较，会把完整区域切成许多微小条带。此例在合并前将边界规范到1e-6设计单位，单边位移最多0.5e-6，再按气体类型做不重叠并集。

验证必须同时包含正反例：算术碎缝能合并；0.0001设计单位的真实间隙仍保留；不同气体不合并；重叠部分面积不重复且透明度不加深。选择容差要结合场景尺度、最窄合法通道及原生浮点精度，不能盲用本例数值，也不能把明显漏底或墙角缺口当数值噪声掩盖。

## UI 数据导致存档超限：先拆大小，再无损紧凑化

**证据不同于上节：** 本节最终大小来自作者在编辑器实际保存后，直接读取磁盘存档及其内嵌脚本；体积验收通过。玩法回归仍为实际 Lua 与原生方法替身，真机解码启动耗时、GPU和内存收益未测。

案例存档26,969,139字节，其中当前Lua正文17,758,602、UI节9,022,419、其余188,118。当前脚本完整字节只嵌入1次，排除了多份旧脚本；外部备份已搬走，不在单个存档组成中。源码文件在目录中另有一份，也不能再加到存档内部组成表里重复统计。

脚本的大头是约7.41 MB的波动几何（38,328条）、5.82 MB的模板绑定数据及2.33 MB的流动数据；提示解法表仅约0.19 MB。运行时控件池减小并不会删除这些预计算描述，模板引用减少本地重复美术，也不意味着脚本自动不再携带详细绑定数据。

### 无损存储与运行时所有权分开

- 构建时对重复字面量、字段集合和表结构去重，以紧凑引用保存；启动时还原原接口所需的数据结构。保持数值精度、字符串、布尔值、缺失字段及数组顺序，不通过删玩法或降低画质凑体积。
- **存储去重不允许偷偷引入可变表共享。** 相同描述可以在文件中引用同一份编码，但每个需要独立修改的运行时实例都要独立还原；不能一个气体片段更新缓存，另一个也跟着改变。除非已有可靠只读约定，不默认让共享字典变成共享状态。
- 解码前后逐值比较全部数据块，专门覆盖false/nil、整数/浮点、Unicode、空表与数组，并检查别名与对象独立性。本例8块数据一致，265,497张独立表计数保持，同时通过25关流程、菜单、提示、结算、点击范围和死局回归。
- 大幅减小源码字节不代表启动更快或内存更低；临时编码表、解码分配与GC时机需要目标设备复测。保留既有错误保护，不引入未核实解压API或执行任意数据字符串。

### 真正验收保存文件，而不止候选脚本

1. 分别记录外部Lua、存档内嵌Lua、UI模板节和其他数据的大小/指纹，确认测量对象是实际发布或保存文件。
2. 可在独立工作区重建一个仅替换脚本节的体积验证副本；检查所有非脚本字段与UI记录字节不变。这只证明结构和预期体积，不授权覆盖编辑器打开的活存档。
3. 部署后由编辑器保存，再回读实际存档：嵌入脚本是否等于新活文件、是否被旧内存版本写回、实际字节数是否达标。本例离线副本14,840,659字节，实际保存14,840,660字节，差1字节为保存元数据；不能拿离线数字冒充实际结果。
4. 分开报告“数据还原一致”“存档大小达标”“真机玩法/性能通过”。本例10,933条UI记录实际保存前后字节一致，体积已达标，真机性能仍待验。

## 应用于目标 2D 游戏的验收

固定设备、客户端版本、分辨率、画质、限帧、前后台和操作路径。先在目标模板上测小样显示与生命周期，再比较当前地图原实现和候选优化。分开记录冷创建、热复用、可见/隐藏/停用稳态、显隐/激活转换和每类动画；正反序重复，采样原始有效dt并记录真实调用次数。

报告平均/P95/P99/最大帧间隔、长帧次数和操作批次计时；不能平均瞬时FPS、平均多组分位数或把回调频率称为呈现FPS。若要定位尖峰，另加事件与下一帧dt的对应记录，避免仅按总次数猜因果。
