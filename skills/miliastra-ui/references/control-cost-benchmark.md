# 千星 2D 图片与文本控件：实机成本经验

本页是经验参考，不是平台限额或通用性能保证。来源为作者授权沉淀的 2026-10-29 单设备实机 A/B 测试，版本 `ui-bench-6-full-suite`；没有收录角色素材、地图标识、账号路径或游戏脚本。原始证据由项目工作区保管。

## 先用于决策，再在目标地图复测

| 触发场景 | 优先做法 | 不变量与反例 |
| --- | --- | --- |
| 大量纯色块组成 2D 美术，要在图片与文本之间选型 | 在视觉要求满足时优先试原生图片底片；不要因文本导出小就替换图片 | 本例文字是非等比缩放的 `█`，不代表普通标签、富文本或所有字体都慢；图片仍须遵守素材白名单与同型资产优先 |
| 切关、开面板、粒子爆发时大量创建销毁 | 比较按需分帧创建和有界对象池，避免热路径重复初始化；预热成本也单列测量 | 不把“全部永久驻留”当结论；池容量、内存、初始化延迟、清理责任需要另测 |
| 短时反复出现/消失，控件无需停逻辑 | 优先实验复用 + `SetVisible`；隐藏期间停止不必要的动画 setter | `SetVisible(false)` 不等于停用、不释放内存；脚本、输入和焦点行为必须按目标模板验证 |
| 确实需要停止控件及其挂载脚本 | 保留 `SetActive` 语义；大批恢复激活时测长帧，必要时分帧恢复 | 不能为省时间把必须停用的功能改成隐藏；也不要停用承担测试/调度回调的父容器 |
| 大量位移/缩放/透明度动画 | 先统计更新控件数×setter数×实际频率；缓存不变值、只更新必要对象，按需求比较父节点整体变换 | 本例动画类型差距很小且缩放结果反转；不能从创建优势推导动画优势。父级变换、原生Tween、更多子节点/脚本未在本例测量 |
| 文本替代图片出现缺口或接缝 | 先做一个控件的小样，核对背景形状、字形可见边界、偏移、抗锯齿与缩放 | 文本背景可能为圆角，不能拿控件外框当实心矩形。浏览器字体预览不等于千星实机字形；必须先视觉验收再宣称等效果性能比较 |

## 已测条件与证据级别

- 单个角色由 765 个矩形组成；分别测试 765 与 1530 个叶控件，同数量内两种方案共用目标几何、颜色与先后层序。双角色档缩小并排，不能用两档差值反推单控件线性成本。
- 图片：同一基础底片 `100001` 染色。文本：64 号 `█`，128×128 安全排版框再非等比缩放，关闭背景和描边。模板无子节点、无挂载脚本。
- UI 逻辑画布 1600×900。硬件、客户端版本、真实屏幕分辨率、画质和限帧设置未完整记录；多数回调接近 60Hz，疑似受限帧/VSync影响，不能当已核实设置。
- 两档各反序两轮，穿插空白基线，总 72 阶段；每阶段预热 2 秒、采样 6 秒、冷却 2 秒。创建/销毁每帧最多 64 个，不等于一次性创建峰值。每项显隐/激活切换为 5 次关闭、5 次开启；动画目标 30Hz，按真实更新次数计数，不在卡顿后补大量历史步。
- 72 组结果全部完成，16 组切换次数全部正确，结束残留控件 0；无无效 dt、超过1秒中断、采样上限截断或测试脚本错误。
- `evidence_source=observed`（用户实机日志与截图）；运行链通过，但字符仍有细接缝，**视觉不完全等价**。运行数据可信不等于等画质比较通过。
- 脚本 SHA-256：`A0B03B3C0727BF68BEF8E2417CE33ABA7BBE0FD3D2B5B684BC7CA6E7FF56850B`。原始日志 SHA-256：`dbe850b1617fa7557980c1e89969359f9a7a1a43d663fedd09f5f29fbca27c48`。原件不随技能分发。

## 计时结果

以下均为 **os.clock 差值代理，单位毫秒**；宿主时钟的语义与精度未独立校准，不是 GPU、端到端墙钟或单纯原生 API 成本。创建包括实例化、属性配置和脚本记账；文本初始化 setter 更多，不能把两倍初始化时间称为两倍 Instantiate 成本。

创建/销毁为整组累计计时的均值（每类型每档16份）；其余为一次全组批次的均值，按实际批次数加权。显隐/激活每操作每类型每档10批；动画每类型每档2个采样窗。淡入淡出包含 Color 构造。

| 隐藏整组一次 | 1.500 | 2.300 | 2.700 | 4.300 |
| 显示整组一次 | 1.700 | 2.200 | 2.700 | 4.100 |
| 停用整组一次 | 6.300 | 10.900 | 12.500 | 21.500 |
| 激活整组一次 | 8.400 | 16.100 | 17.100 | 31.000 |

## 预览到实机的失败经验

1. **序列化体积不等于运行成本。** 较早的配置记录探测曾得到文本比图片小约8%，并非同视觉内容的完整导出对照，不能推出文本运行时更省。
2. **文本背景不是默认直角底片。** 本例空文本框的背景呈圆角/胶囊，小块呈圆点，拼图大量漏底；这组与图片不是同画面，其性能记录不用于同效果优劣结论。
3. **字形边界不能猜。** 先用基础图片参照与单字符截图测可见宽高、中心偏移；保持文本框足够容纳字号，再缩放。某次字体的参数不写成跨地图常量。
4. **实心覆盖与抗锯齿要分别验。** 半透明边界拼接可能留细缝；按实心内区放大可能造成邻块覆盖、颜色渗边。必须同时核对缝隙、细节、轮廓和覆盖面积，不能以“能认出来”代替等视觉验收。

## 应用于目标 2D 游戏的验收

固定设备、客户端版本、分辨率、画质、限帧、前后台和操作路径。先在目标模板上测小样显示与生命周期，再比较当前地图原实现和候选优化。分开记录冷创建、热复用、可见/隐藏/停用稳态、显隐/激活转换和每类动画；正反序重复，采样原始有效dt并记录真实调用次数。

报告平均/P95/P99/最大帧间隔、长帧次数和操作批次计时；不能平均瞬时FPS、平均多组分位数或把回调频率称为呈现FPS。若要定位尖峰，另加事件与下一帧dt的对应记录，避免仅按总次数猜因果。

通过标准是目标画面和交互等价、无泄漏/异常、目标场景长帧或耗时改善且跨轮稳定。未测GPU/内存/原生Tween/父容器批量切换时保留未知。此经验不授权改图、部署，也不支持把765/1530当平台上限。
