## 3. 层序（**顺序即层级**，本案例两次事故都在这里）

```
1 背景（4 块拼底 + 光晕 + 星尘）
2 底层美术（格子底、角图素材组）
3 文字（格子编号+简称、HUD、面板正文）
4 面板（结果/结算面板）
5 按钮 / 点击热区（永远最后建）
```

- ⚠️ **事故①**：角图建在格子文字**之后** → 盖住简称 ⇒ 创作者："**翻牌的文字咋还是没有**"。
- ⚠️ **事故②**：结果面板建在按钮**之后** → 盖住按钮 ⇒ 创作者："**下一关按钮呢**"。
- ⚠️ **事故③**：阶段提示条建在 `view`（底层）→ 被 `board` 的格子盖住 ⇒ 创作者："**文字层级不对**"。
  ⇒ 三次都是同一条规律：**"要盖住别人的东西"（弹窗/提示条/按钮/角标）只许建在最上层脚本里**（本工程 = `board`）。
- ⇒ 跨脚本层级不可控 ⇒ **会互压的元素必须放同一个脚本**（本案例把"格子+角图+文字+面板+按钮"全放 `board.lua`）。
- ⇒ **兜底**：关键按钮**在两个脚本里各画一份**（`board` 与 `view` 同位置同文案）—— 任何一侧崩了，按钮还在、点击区仍命中（实测救过一次：`board` 崩了但按钮照常可用）。

## 4. 三条真机渲染怪癖（**模拟器测不出来，只能真机截图发现**）

| # | 怪癖 | 应对 |
|---|---|---|
| 1 | **小尺寸文字控件不渲染**（格子顶部 108×32 的编号条、108×48/70 的两行字 **都不画**；数据全对） | 文字控件一律**整格/整面板大小 + 对齐方式定位**（本案例格子文字用 **108×108 + 顶对齐**） |
| 2 | **整屏单块图片控件不渲染**（1600×1000 写进去无报错、画面空白；480×468 正常） | 全屏底**拼块**（4 块 800×500）+ 逐块设色 |
| 3 | **素材子节点的 `imageId` 多半不能当静态图源**（`SetImage` 后渲染成 `?`） | **用素材本体整组实例化**，别拆图；确证可用的单图资产只有少数（`100001` 底片 / `106004` 光晕 / `105034` 星 / `108009` 波形 / `100202` 丝带 / `106058`） |

### 4.1 附带两条

- **素材里可能有作者遗留的"无图源空图"** → 渲染成大问号 ⇒ 实例化后遍历子树把 `name=="图片" and imageId∈{nil,0}` 的 `SetVisible(false)`。
- **素材原始尺寸常常远大于栏位** ⇒ 先整体 `SetLocalScale` 再摆位；只看摆位会糊满半屏。

## 5. 动效规格（"游戏手感"，全部真机验证过）

| 动效 | 做法 | 参数 |
|---|---|---|
| **翻面 pop** | 新翻开的格子：角图先放大再回弹 | 0.22s，正弦缓动，峰值 +28% |
| **按钮按压回弹** | 按钮尺寸瞬时 +5% 再回落 | 0.16s |
| **翻面金环** | 该格覆盖一层金色图片，边放大边淡出 | 0.45s，尺寸 0.90→1.25，alpha 200→0 |
| **闪效** | 全屏叠加层按事件闪色（成功绿 / 失败红 ×2 / 胜利金 / 调查淡白） | 由状态串 `fx` 变化驱动 |
| **背景** | 4 团柔光呼吸漂移 + 28 颗星尘上浮横摆闪烁 | **限频 ~20fps**（每帧 100+ 次 API 会拖慢） |

### 5.1 动效三条纪律（都是踩出来的）

1. **`dt` 可能是 `nil`，而且兜底不能给 0**（真机事故）：`animTick(dt or 0)` 看着安全，
   但真机**不给 dt（或给 0）**时 ⇒ 动画时间**永不前进** ⇒ 表现是"**提示条一直挂着不消失 / 翻卡停在第一帧**"✗。
   ⇒ **正解：`local d = dt; if d == nil or d <= 0 then d = 1/60 end`**（固定步长兜底，动效照常走完）。
   控件表也要存全 `{c,kind,col,x,y,w,h}`（否则动效里 `a.w` 报错 → 脚本冻结）。
1b. **"兜底副本"要付代价**：为防某脚本崩而加的第二份按钮/面板，**必须与主份完全同源**，否则会出现
   "白十字/错位控件"这类只有它才有的怪东西 ✗（本案例：view 里的兜底按钮渲染成白色十字，创作者一眼看出"是下一关按钮"）。
   ⇒ 兜底只在"主份已知会崩且短期修不好"时才加；**主份修好后立刻删掉兜底** ✓。
2. **官方 Tween 真机可用**（实测）：`game.Tween(obj,{alpha=1},0.3):SetEase(...):Play()`，
   `alpha/opacity/scale/size/position/imageColor/fontSize` **字段名全部认** ⇒ 能用官方缓动就别手搓。
3. **心跳/诊断类写入绝不能顶 `fx`** —— 否则闪效会被每秒重放，表现成"**一直黄光 / 闪两下**"。

## 8. 追加：模态覆盖层规格（标题 / 选关 / 图鉴 / 教程 / 设置菜单）· 

> 这一轮把"标题页 + 选关 + 图鉴 + 教程 + 玩时设置菜单"做齐了，五次真机反馈换来的规格如下。
> 层序的**代码侧**做法（按需创建 / `SetAsLastSibling`）见 `miliastra-code` 的
> `case-detectives-6scripts.md` §8；这里只讲**版面与坐标**。

### 8.1 坐标口径（**这一条不搞清，改任何坐标都会错**）

- 本工程 `view.lua` 一系的 `y` 是 **"从屏幕顶部往下数"**（`toY(dy) = canvasH/2 - dy*sy`），
  与 `add(name,kind,x,y,w,h)` 的 `y` **同一套数**；真机画布实测 `1600×1000`（浮点：`1599.9998×999.9998`，比较要留容差）。
- ⚠️ **`game.GetCursorUIPos()` 是「画布左下角原点」（像素）——不是本工程的 `y` 口径！**
 （真机踩坑后改正：先前这一行写反了，把 `input.lua` **换算后**的值当成了它的原始返回值。）
  换算与本工程 `input.lua` 的点击回调逐字一致：
  ```lua
  local dx, dy = ux / sx, DH - uy / sy     -- DH = 1000（设计稿高）；sx/sy = 画布/设计稿
  ```
  漏了这一步的后果很具体：**鼠标停在最上面那个按钮、高亮却落在往下数第 3 个**——因为纵向被镜像了。
  ⇒ 判据：任何用光标坐标去比"设计坐标矩形"的代码，都要先做上面这次换算；
  排查时给悬停加一行日志（`悬停 → mxB1`）比看截图靠谱（截图里 8px 描边的深浅差肉眼难分）。
- **按"从下往上"的直觉写覆盖层 ⇒ 整个面板会上下颠倒**（标题跑到最下面、关闭按钮跑到最上面）。本轮真发生过一次，
  真机反馈是"选关的关闭绑定了标题面板"——实际是面板整块反了。
- 模拟器里点按要换算（1600×900 画布）：注入值 `y = 900 − y设计 × 0.9`
  （例：点设计 y=780 → 注入 198；注入 198 → Lua 读到 780 ⇒ 换算后 `DH - uy/sy` 得 780 ✓）。

### 8.3 三种模态的底板取舍（创作者口径：**只有标题页铺全屏底**）

| 模态 | 底板 | 理由 |
|---|---|---|

### 8.4 复用一套壳做多页内容（本案例的最优解）

- **图鉴与教程共用同一批控件**（`cxPanel/cxTitle/cxInfo/cxBody/cxPage` + `cxPrev/cxNext/cxClose`），
  只换内容与按钮文案（"上一张/下一张" ↔ "上一页/下一页"）⇒ **零新控件、零新机制**，翻页行为天然一致。
- 设置菜单同理：四个按钮用**一张表**（名字/文字/y）驱动**建、显示、提层、渲染**四处，避免同一份坐标写四遍。
- **教程文本放数据层**（主控片段里的 `TUT_PAGES`，由状态串转发 `tutT*/tutB*`），不放 UI 脚本：
  ① 与"文案属于资料表"的工程惯例一致；② `view.lua` 会因此顶破 **1000 行**（风格门禁 `BIG_FILE` 会红）。

### 8.5 底部按钮排（玩时）

```
y 812..900  ┌ 切换关卡 (32,812,360,88) ┐ ┌ 设置 (620,812,240,88) ┐ ┌ 开始抓人 (1180,812,360,88) ┐
y 764..812  提示行 tip（横跨 1536 宽，紧邻不压）
```

- 「设置」是**后加的第三个按钮**：放底部**中段**，与左右两个零重叠；**任何阶段都显示**（结算页也在）。
- 模态打开时它会被面板盖住 —— **可接受**（模态本来就该吃掉下面的点击：交互侧在 `ui=menu` 分支里
  **整屏吃掉点击**，只认菜单四个按钮，避免穿透到底下的【切换关卡】/【开始抓人】）。

### 8.6 「画在哪 = 点哪算」契约 + 机械校验（**强烈建议每个项目都做**）

- 热区在 `input.lua`（设计坐标矩形），画面在 `view/board.lua`（`add(...)` 坐标）——
  **同一份数字写两处**，改一处忘另一处就是"看得见点不着"。
- 做法：写个二十行的小脚本，把 `view/board` 的 `add("名字", 类型, x,y,w,h)` 与 `input` 的
  `local RECT = {x,y,w,h}` **逐字比对**（本工程 `tmp/check-overlay-rects.mjs`：13 个按钮 + 12 行列表，全对齐才算过）。
- 校验脚本要覆盖**循环建出来的控件**（从驱动表读坐标，别只认字面 `add(...)`）。
  本工程已把它提升为**常驻门禁** `tools/check-ui-contract.mjs`，并连**规范口径**一起机械判：8 的倍数（UI2）、
  字号只 64/52/28/22（UI3）、按钮槽位与 `input.lua` 热区逐字相同 —— **改坐标忘了同步 input 会被它拦下**。

### 8.7 描边的廉价实现：**两片叠**（外框 + 内芯），不是四根边条

- 面板：`add(name.."P", img, x, y, w, h, C_BAR)`（外框·亮一档）+ `add(name.."PBg", img, x+8, y+8, w-16, h-16, C_PANEL)`（内芯·暗）
  ⇒ **2 个控件**就有 8px 描边；四根边条要 5 个控件（还多 3 次 `add`）。
- 按钮同理：外框 `C_LINE` + 内芯 `C_BAR` + 文字（开 `enableOutline`）⇒ **3 个控件**一个按钮。
- **四态（§4.1）用同一套色阶就够**，不需要新颜色：常态内芯 `C_BAR` → 悬停提亮到 `C_LINE` → 按下压回 `C_PANEL`。
- ⚠️ **悬停不要用"光标检测区域"**：那种热区 `raycastTarget=true` 会**吃掉点击**（本工程点击统一由 `input.lua`
  的一块全屏热区派发）⇒ 会把点击逻辑撕成两半。正解：**在自己脚本的 tick 里轮询 `game.GetCursorUIPos()`**，
  拿按钮矩形自己比对（只读，零冲突）；"按下"用"模式变化时把刚悬停的那个按钮压暗 0.15 秒"来表现。

### 8.8 字形坑：**`◀` `▶` 是豆腐块**，箭头只能用 `←` `→`

- 现象：按钮文案 `◀ 上一页` / `下一张 ▶` 在截图里渲染成「**口** 上一页」「下一张 **口**」（U+25C0/U+25B6 缺字形）。
- 同屏对照：棋盘那句「调查完了 **→** 开始抓人」用的是 U+2192，**渲染正常** ⇒ 不是"箭头都不能用"，是**那一族字形缺**。
- 判据：**只信截图**（模拟器与真机都要看），文案里出现符号就复看一次；不确定就退回纯文字（「上一页」）。
- 同理要小心的：`■ □ ● ◇ ★ ☆` 这类几何符号（本工程背景里的方块是**故意**的方块，别混淆）。

### 8.9 关卡横幅：`第 X 关 · 关卡名` = **底图 + 文字**（64 号），不是"面板里一段裸文字"

- 位置：设置菜单面板顶部（`makePanel("mx", 560,192,480,616)` 内），横幅 `add("mxLvBg", img, 576,224,448,120, C_BAR)`
  + `add("mxLv", txt, 576,224,448,120, C_GOLD)`、`fontSize = 64`；**建在 5 个菜单按钮之后**（提层按创建序 ⇒ 它排最上）。
- ⚠️⚠️ **根因（两轮真机排查定的）= 矩形太矮，不是被压住、不是字号、不是描边**：
  文本框 `sizeDeltaY` 容不下行高（CJK ≈ **1.4×fontSize**）时，这个控件**整条什么都不画**。
  实测数据：`52` 号放进 **64** 高 → 空白（19:28 那局）；`64` 号放进 **80** 高 → 空白（19:58 那局）；
  而 09-25 那句 52 号大标题放在 **90** 高里 → 正常。⇒ 现在 64 号配 **120** 高。
- **取证顺序**（照这个走，别先怀疑字号/字体）：
  ① 读这一局 `.gia`：`菜单标题=<lv>/<title> 控件=true` 在 = **文字确实设上了**；`覆盖层提层：menu 共 19 个，失败 0` = 层序正常；
  ② **量像素**：把真机截图裁下来算均值 —— 底图带 `C_BAR` 的均值会精确落在 `59,66,92`（= 底图渲染了），
     若文字区均值与底图**一模一样**（零像素差）⇒ 文字控件什么都没画（而不是被压住：被压住会看到另一块颜色）；
  ③ 到这一步就只可能是"矩形不够高"这类**平台侧截断**，按 `fontSize × 1.4 + 余量` 把高度给足。
- 为什么模拟器抓不到：**模拟器不模拟这个截断**（同代码它画得出来）⇒ 这类问题只能靠真机截图 + 像素比对。
- 文案格式：`"第 " .. lv .. " 关 · " .. title`（与左上角 HUD 的 `hudLv` 同一数据源，两处不会不同步）。
- 同批顺手加高的：阅读型面板标题 `pkT` / `cxT` 从 `(352,152,896,80)` 改 `(352,144,896,96)`（52 号 × 1.4 = 72.8，原来只剩 7px 余量）。

## 附：第四条真机渲染怪癖 —— 文本框「尺寸改得小、复位不回来」（2026-10-05 实测）

**现象**：用 `SetSizeDelta` / `placeAt` 把一个 `newText` 文本框改小，**生效**；但之后无论 `placeAt` 重写多少次算好的矩形，**都回不到原尺寸**。
`newImage`（房间格、门）用同一套 `placeAt` 一直正常 ⇒ **这是文本框特有的**。

**三层原因**（都要知道，否则会反复试错）：
1. **几何读不回来**（§1.3）：`sizeDelta / anchoredPosition / localScale` 读出来是 `nil` ⇒ 无法"比对当前值再纠正"。
2. **两种写法语义不同**：`writeGeometry` 写的是 `SetSizeDelta(sdW, sdH)` = **相对锚框的差值**；手写 `SetSizeDelta(绝对尺寸)` 看着是同一个字段，实际会把控件写歪（实测：跑到画布角落）。
3. **Tween 完成后保持终值**：`Kill(false)` 只停止、不清值 ⇒ 重画时想"被动盖住"盖不住。

**三种正解（按推荐顺序）**：

| # | 做法 | 要点 |
|---|---|---|
| ① | **Tween**：`game.Tween(ctrl, {sizeDeltaX=to, sizeDeltaY=to}, dur):Play()` | `sizeDeltaX/Y` 在 `annotations.lua` 标 `@tweenable`，**真机实测有效**；`to` 用**算好的绝对值** |
| ② | **恢复必须「显式设目标值」**，且放在**状态结束的统一出口**（如 `VIEW.hideFail()` —— 回退/重置都会走那里） | ⛔ 不要指望"重画时被动覆盖" |
| ③ | **双子控件**：预置两套矩形的两个文本框，运行期只 `SetActive` 切换 | 零运行期几何写入 ⇒ 天然可恢复；代价是多占控件 |

**一句话口径**：**几何属"算出来一次写对"的量；要做动画就用 Tween，要恢复就显式设目标值 —— 永远不要依赖"读回当前值"或"重画时被动覆盖"。**
