## 素材优先选型（布局实现前）

涉及千星2D大量控件、文本替代图片、切关创建峰值、显隐/激活策略或动画预算时，先读[图片与文本控件实机成本经验](control-cost-benchmark.md)。选型区分文件大小、创建配置、状态切换与稳态渲染；优先验证目标画面等价，不把单次实验数字当通用预算。

- 将界面拆成面板、按钮、图标、边框、装饰、背景等视觉用途，先查官方素材，再定实现；不要默认用大量微小色块逐点、逐行拼出图案、圆角、光晕或图标。
- 同等适配条件下，优先复用已核实的官方模板/素材组，其次用官方单图或少量素材组合，最后用基础色块补足遮罩、分隔线、进度填充等简单几何。已有合适素材时保留复用，不反复搜索。
- 搜索入口与核对方法统一见 [素材检索与接入](asset-search.md)：图片目录、图标语义搜索、本地图片标注及音效/音乐/特效入口按类型选用。项目内可复用模板另查当前关卡 `clientui` 索引，不全量遍历目录。
- 先核对来源、资产类型、真实 ID 与接入条件；官方图片 ID 与关卡控件模板索引分别记录，不能互换。目录有记录不代表项目已导入，也不代表真机已显示。
- 候选先排除类型不符、无法接入和比例明显不适配者，再比较用途/形状、风格一致性、缩放后清晰度与变形、状态支持及控件/更新开销。不单凭名称判定外观；仅有描述时标注视觉待确认，由用户确认视觉验收。
- 面板尺寸结合素材比例和内容留白确定；避免强拉伸边框。素材组沿用 §1.5 的整体缩放/位移，单图按当前 API 支持方式接入。代码负责布局、内容、状态与交互，尽量复用素材已有的美术细节。
- 在版面表增加「素材来源及 ID/模板索引、复用方式、待确认项」；需要程序绘图的区域写明缺口原因。无需为简单直线或遮罩额外搜索，但不能以可编程为由跳过主要美术的选材。
- 查不到合适素材时，换用途或形状关键词再定向核对；来源不可用或仍无匹配时说明缺口，可用少量基础图形临时占位，素材待接入。不要把占位扩展为高控件数的像素拼图。
- 动效优先作用于已有素材的整体位置、缩放或透明度（以当前 API 为准）；比较实际控件数与每帧属性更新数，不假定素材组一定比基础图形开销更低。

## 铁律（强制，不可违反 · UI1–UI6）

> **说明**：以下六条是客户端界面的硬性底线，**每条都能对着代码 / 截图判定**。细则（为什么 + 怎么做）在 §1–§6；
> 具体**违反示例 / 改进示例 / 审查动作**见 [`references/iron-rules/`](iron-rules/)（`UI1` ~ `UI6`，一条一文件）。
> ⚠️ 外部 GUI 框架（immediate-mode / CSS flex / z-index / 9-slice…）**不适用** —— 不是"实现方式不同"，是平台缺那层管道；**只取概念、别引 API**，见 §1.6。

### UI1　数值只许从脚本顶部常量表取

- 颜色 / 字号 / 间距 / 关键坐标先在脚本顶部写成一张表（`THEME = {...}`），控件创建**只引用表项**。
- 档位里找不到的**不许造值** ⇒ 写 `-- TODO(token): 需要 <语义> 档`；一次性定位必须 `-- one-off: <为什么>` 标注。
- 审查动作：`grep -nE 'SetSizeDelta\(|imageColor *=|fontSize *= *[0-9]' <脚本>` 逐处核对裸写。

> 违反/改进参考 → [`references/iron-rules/UI1-token-table.md`](iron-rules/UI1-token-table.md)

### UI2　栅格档位：坐标 / 尺寸 / 间距取 8 的倍数

- 面板宽只三档 ∈ {480, 720, 960}；外边距 ≥ 32；元素间 ≥ 24、分组间 48。
- 横向 / 纵向分配**必须加得平**（= 1600 / 1000）：先把固定件（侧栏 / 底栏）写死，主区取**剩下的那一份**；算不平就改档位或降边距，**不许随手写个接近的数**。
- 审查动作：**技能自带** `node scripts/gates/check-ui-rules.mjs <脚本>`（8 的倍数；几何是变量会记"判不了"）+ 工程里 `node tools/check-ui-contract.mjs` + 逐行加总校验。

> 违反/改进参考 → [`references/iron-rules/UI2-grid-scale.md`](iron-rules/UI2-grid-scale.md)

### UI3　字号只许 4 档、同屏 ≤3 档、正文 ≥22

- 只取 `64`（关卡横幅，一屏最多一处）· `52`（页面主标题）· `28`（小标题 / 正文）· `22`（说明，**正文下限**）；要新档 ⇒ **同时**改表 + 改校验白名单。
- 层级靠**字号 + 颜色 + 位置**，**不许靠加粗**（客户端字体粗细不可控）。
- ★★ **字号大了矩形必须跟着高**：`sizeDeltaY` 容不下 `字号 × 1.4`（CJK）⇒ 该控件**整条什么都不画**（不裁切、不报错、`visible` 仍 true），**只有真机看得出、模拟器不模拟**。
- 审查动作：**技能自带** `node scripts/gates/check-ui-rules.mjs <脚本>`（字号白名单 + `h ≥ 字号 × 1.4`）+ 工程里 `node tools/check-ui-contract.mjs`。

> 违反/改进参考 → [`references/iron-rules/UI3-font-scale.md`](iron-rules/UI3-font-scale.md)

### UI4　颜色只从语义色表取；对比三条硬规则

- 颜色只从 §3.2 语义色表取（主文字 / 次文字 / 强调 / 成功 / 警告 / 面板底板 / 描边 / 半透明文字底 / 全屏遮罩）。
- 文字与背后**亮度差 ≥ 4 级**；文字**压在素材 / 花图上必须垫半透明暗底**；**亮白大色块不许当面板底板**。
- 审查动作：截图问「读得清吗」+ `grep imageColor` 对照语义色表。

> 违反/改进参考 → [`references/iron-rules/UI4-semantic-color.md`](iron-rules/UI4-semantic-color.md)

### UI5　层序 = 创建顺序

- 定死一条顺序：**背景 → 底层美术 → 文字 → 面板 → 按钮 / 点击热区**（越"该压在最上面"的越晚建）。
- **会互压的必须同脚本**（跨脚本先后不可控）；**要压最上的只许建在最上层脚本**；每个脚本头部写一句"我负责哪几层"。
- **清理兄弟控件必须白名单**（实测：`view` 写"隐藏所有非自己建的" ⇒ 把 `input` 的点击热区一起隐藏 ⇒ **点击彻底失效**）。
- 审查动作：交付前截图上问三句 ——「结算面板在上面吗」「按钮看得见点得着吗」「格子上的字被图盖住了吗」。

> 违反/改进参考 → [`references/iron-rules/UI5-layer-order.md`](iron-rules/UI5-layer-order.md)

### UI6　素材按类型复用；可点元素四态

- 复合模板保留子树并整体缩放、摆位；官方单图可独立使用。旋转按当前 API 的 `SetLocalRotation` 核对，不能用字段 `rotationZ` 赋值失败推断平台无法旋转；效果仍待真机确认。
- **复合模板禁止递归 sanitize 或按空 imageId 批量隐藏子控件**。仅对已确认可清理的单图模板白名单处理空图；不凭 `imageId == nil/0` 判定容器、热区或动态图片无用。遵守 [工程 V2](../../miliastra-code/references/iron-rules/V2-no-sanitize-composite.md)。
- **可点元素四态**：常态 / 悬停（提亮一档）/ 按下（压暗或缩 4~8px）/ 禁用。
- ⚠️ **硬前置**：光标事件要**祖先容器 `showCursor = true`** 才派发（出现那一帧置 true、关掉置 false）。
- 审查动作：`grep showCursor` / `grep rotationZ` + 截图看有无悬停反馈。

> 违反/改进参考 → [`references/iron-rules/UI6-asset-and-states.md`](iron-rules/UI6-asset-and-states.md)

## 工作流选择

仅查素材直接用素材检索参考。布局任务按改动范围核对画布、父级坐标、素材和层序，再实现并验证；整屏设计才需要完整坐标/层序表。已确定的小调整不重做草图或等待再次确认。视觉验收遵循工作区约定，由用户确认。

## 1. 硬口径（代码与坐标）——**错了这一节，后面全白搭**

### 1.1 画布与设计稿

- 本文示例沿用 **1600 × 1000** 参考设计稿（历史本机 PC 16:10 测量），不是所有设备的固定画布或当前真机证据。新布局按目标设备选参考尺寸，并按 [多端适配](ui-ux-workflow.md#多端适配) 核对手机、安全区与焦点；已有项目不因更换参考比例自动重做。
- 运行时按实际画布等比换算并居中留边；读取失败时暂按设计尺寸计算并标注待校准，不能拿空值继续计算：

```lua
local designWidth, designHeight = 1600, 1000
local canvasWidth, canvasHeight = designWidth, designHeight
local canvasOk, actualWidth, actualHeight = pcall(function()
    return game.GetUICanvasSize()
end)
if canvasOk and type(actualWidth) == "number" and type(actualHeight) == "number"
    and actualWidth > 0 and actualHeight > 0
    and actualWidth < math.huge and actualHeight < math.huge then
    canvasWidth, canvasHeight = actualWidth, actualHeight
end
local uiScale = math.min(canvasWidth / designWidth, canvasHeight / designHeight)
```

### 1.2 坐标：**锚点是元素中心，不是左上角**（最容易踩的坑）

以下示例只适用于父级中心与画布中心重合、父级无额外缩放/旋转的子控件。`left, top, width, height` 是设计稿中的左上角与尺寸，先设中心锚点和中心轴心：

```lua
control:SetAnchorMin(0.5, 0.5)
control:SetAnchorMax(0.5, 0.5)
control:SetPivot(0.5, 0.5)
control:SetSizeDelta(width * uiScale, height * uiScale)
control:SetAnchoredPosition(
    (left + width / 2 - designWidth / 2) * uiScale,
    (designHeight / 2 - top - height / 2) * uiScale
)
```

- 这里显式加了半个尺寸，把左上角转换成控件中心；`SetAnchoredPosition` 不会代加。
- 按 [当前 API](../../miliastra-code/references/api-client-ui.md)，无父层级控件的位置以画布左下为原点，上式的 x/y 结果需分别加 `canvasWidth / 2`、`canvasHeight / 2`；嵌套面板需在其父级坐标系计算，不能直接套全屏公式或重复缩放。
- ⚠️ **实测事故**：把"左上角"直接丢给 `SetAnchoredPosition`（少加半个尺寸）→ 元素整体偏移到屏幕角落/外面，表现为"素材根本看不见"。
- 素材组尺寸未核实时先按中心定位。在上述父级条件下：`group:SetAnchoredPosition((centerX - designWidth / 2) * uiScale, (designHeight / 2 - centerY) * uiScale)`；`centerX, centerY` 是设计稿中心坐标，不是左上角。

### 1.3 几何读取：用文档方法，不猜字段

- 字段读取为 nil 不代表没有 getter。[当前 API](../../miliastra-code/references/api-client-ui.md) 提供 `GetAnchoredPosition()`、`GetSizeDelta()`、`GetLocalScale()`、`GetLocalRotation()` 等方法；使用前核对对象类型、返回值及父级坐标系。
- 布局先算表，方法读回可辅助核对写入；不把读回数值当作已显示、无遮挡或文字未裁切的证据。旧案例的字段读取失败不能推广成平台不支持。

### 1.4 层级：**后创建的在上面**

- 想让文字压住素材：**先建素材/背景，后建文字**（顺序即层级）。
- 需要动态调整时用兄弟序号接口（若可用），否则重建。
- **点击热区放最后建**（最上层、透明）——但见 §6 的多脚本纪律：**别用"清理外来控件"的方式去整理层级**。
- ⚠️ **两次真实事故（《侦探杀》真机，都是"顺序=层级"踩的）**：
  ① 角图（素材组）建在**格子文字之后** → 角图盖住文字，创作者看到的是"**翻牌的文字咋还是没有**"；
  ② 结果面板建在**按钮之后** → 面板盖住按钮，创作者看到的是"**下一关按钮呢**"。
  ⇒ 定死一条顺序：**背景 → 底层美术 → 文字 → 面板 → 按钮**（越"该压在最上面"的越晚建）。
- 跨脚本的层级**不可控**（谁后建看脚本执行顺序）→ 需要互压的两类元素**放进同一个脚本**（本工程把"格子+角图+面板+按钮"全放 `调查板 board.lua` 就是这个原因）。
- **全屏动态背景（纯 Lua、不用美术）范本** → [`references/procedural-background.md`](procedural-background.md)（含"整屏单块图片控件不渲染"等四条硬约束 + 可抄代码 + 调参表）。

### 1.4b 层级契约（**写代码前先定，别等真机踩**）

**① 固定绘制顺序**（后建 = 在上，所以照抄这个顺序就不会错）：

```
1 背景（底板拼块 / 光晕 / 粒子）
2 底层美术（格子底、角图、素材组）
3 文字（格子文字、HUD、面板文字）
4 面板（结果页、弹窗）
5 按钮 / 点击热区（永远最后建）
```

**② 同层会互压的元素 → 必须放进同一个脚本。**
跨脚本的先后顺序**不可控**（谁后建看脚本执行顺序）—— 实测事故就是这个：按钮在 `view` 里建、格子由 `board` 建，结果格子把按钮压住；角图与格子文字同理。

**③ 每个脚本头部写一句"我负责哪几层"**（例：`board.lua` = 层 2+3+4+5；`view.lua` = 层 1+3；`input.lua` = 只有透明热区 + 自己的可视反馈）。

**④ 交付前自检（10 秒）**：真机截图上问自己三句 ——
「结算面板在上面吗」「按钮看得见点得着吗」「格子上的字被图盖住了吗」。三句都过 = 层级没错。

**⑤ 反面教材（本项目真机记录）**
| 现象 | 根因 | 修法 |
|---|---|---|
| 「下一关按钮呢」 | 结果面板建在按钮**之后** | 面板先建、按钮最后建 |
| 「翻牌的文字咋还是没有」 | 角图建在格子文字**之后** | 文字建在角图之后 |
| 「**文字层级不对**」（阶段提示条被格子盖住） | 提示条建在 `view`（底层脚本），格子由 `board` 建 | **要压在最上面的，一律建在最上层脚本** |

**⑥ 一句话判定（第三次踩出来的）**：任何"要盖住别人的东西"（弹窗/提示条/按钮/角标）**只许建在本工程最上层的那个脚本里**——本案例最上层是 `board`；建在 `view` 里就是等它被盖住。

### 1.5 素材：**整组用，别拆**

- 素材可以**整组实例化**，并对根节点 `SetLocalScale`（整体缩放）+ `SetAnchoredPosition`（整体位移）**生效**。
- 不直接写未文档化的 `rotationZ` 字段；需要旋转时按当前 API 核对 `SetLocalRotation(x, y, z)`，保留素材组内部关系并验证实际显示。编辑器调整是可选接入方式，不能仅凭字段赋值失败宣称脚本无法旋转。
- ⚠️ **素材的"原始尺寸"通常远大于你的栏位**：实测「人物解释图片」原始约 **740×900**（设计稿 1600×1000 的**半屏**）。
  ⇒ **先整体缩放再摆位**（例：放进 480 宽的栏位 ≈ `SetLocalScale(0.6, 0.6, 1)`）。
  只摆位不缩放 = 素材糊满半屏、把你自己的面板全盖住（实测事故：玩家直接问"这一整块是个啥"）。
- 空图可能显示问号，但复合模板内无图源节点也可能承担容器、动态填充或交互职责；复合模板保持原树，不递归清理。仅在单图模板白名单中核对控件类型、图源和依赖后处理，见 UI6 与工程 V2。
- 结论：**能用素材整组就用整组**（美术自带、效果最好）；只有确实只需要个别图时才取资产号单图重建。

### 1.6 为什么不能套外部 GUI 框架（**先看这条，别白费一轮**）

被问过「SUIT / LUIS 这类 Love2D GUI 库能不能吸收进来」「网页那套 flex / CSS 能不能搬」。答案都是**不能直接迁移**——
它们与千星不是"实现方式不同"，而是**缺了它们赖以工作的底层能力**。逐条对照（每条都对应本技能已有的硬口径）：

| 外部套路 | 它依赖什么 | 千星为什么不行 |
|---|---|---|
| **立即模式 GUI**（SUIT：UI 写在 update 里、每帧重跑、当场返回 `.hit`） | 外部绘制接口及输入循环 | 外部绘制 API 不能直接调用；保留控件并按状态更新，不以每帧销毁重建模拟绘制 |
| **自动布局引擎**（LUIS FlexContainer / CSS flex、grid） | 布局算法与宿主适配 | 平台提供几何 getter（§1.3），但外部库仍需接口适配；现有布局先按本项目坐标表实现 |
| **Z-index / 层管理器** | 动态排序 | 当前 API 提供 `SetSiblingIndex`、`SetAsFirstSibling`、`SetAsLastSibling`；仅作用于同父级，核对返回值与实际遮挡，不能当作跨父级全局 z-index |
| **9-slice / 圆角 / 描边 / 模糊 / 发光装饰器** | 着色器或切片绘制 | `imageType` 只支持 **Stretch**（引擎明确 Slice / Tile 未实现）→ 优先选带所需边界/装饰的官方素材并核对比例；缺少适配素材时才用简单底板与内条（§4） |
| **hover / active 由框架自动画** | 框架自带控件外观 | 只有 **PresetButton** 自带多态，其余要自己在事件回调里改属性（§4.1） |
| **focus / 手柄导航交给框架** | 框架管焦点环与导航序 | 平台有导航事件与 `canControllerFocus`，但**仅靠控件配不齐**、逻辑必须写进脚本；**未真机验证前不许当规范写死** |

⇒ 结论：**外部库真正提供的那层"管道"（事件循环 / 布局器 / 渲染器）在这里都不存在**，这里能用的只有
**控件树 + 属性 + 事件**。所以碰到"要不要吸收某个 GUI 库"，正确做法是：
**只挑它在同层问题上做对的概念**（状态视觉、单一主题表、调试栅格…），用本技能的**可算数字**重写一遍；
**不要引用它的 API**——引用一个平台上不存在的 API，就是让下一个人/AI 去猜（等于违反"API 不许猜"）。

> ⚠️ **许可顺带一提**：这类库的许可不一定能随便搬。实例：**LUIS 是 MIT + 附加条款「禁止用于训练 AI/ML」**——
> 对 AI 参与的项目，**连整段引用其文本/代码都不宜**（只作"思路参考、用自己的话重写"）。搬任何外部代码前先看 LICENSE，别只看是不是 MIT。

## 2. 栅格与安全区（照着摆就不会乱）

| 项 | 值 | 说明 |
|---|---|---|
| 设计稿 | 1600 × 1000 | |
| 外边距 | **32** | 任何内容不越过它（除非是整屏背景） |
| 内容区 | 1536 × 936 | 32 ~ 1568 / 32 ~ 968 |
| 顶部 HUD 带 | y 0 ~ **120** | 星级、声誉、阶段这类状态 |
| 底部提示带 | y **880** ~ 1000 | 操作提示、结果文字 |
| 节奏基数 | **8** | 所有坐标/尺寸/间距都取 **8 的倍数**（8/16/24/32/48/64/96/128） |
| 常用间距 | **24 / 32 / 48** | 元素之间 ≥ 24；不同分组之间 48 |
| 主要面板宽度 | **480 / 720 / 960** 三档 | 高度自选，但同样取 8 的倍数 |
| 面板间距 | ≥ 24 | 相邻面板不许贴在一起 |

**⭐ 常见横向/纵向分配（1600 × 1000，直接抄，别自己凑数 ✗）**

| 布局 | 分配（含边距与间距 ✓） | 校验 |
|---|---|---|
| **三栏**（左/中/右） | `32 + 480 + 48 + 480 + 48 + 480 + 32` | = **1600** ✓ |
| **主区 + 右栏**（侧栏 480 固定） | 边距 32：`32 + 1008 + 48 + 480 + 32` ✓ ｜ 边距 24：`24 + 1024 + 48 + 480 + 24` ✓ | 两种都是 **1600** ✓ |
| **左右双栏** | `32 + 768 + 48 + 720 + 32` | = **1600** ✓ |
| **上主区 + 底栏**（底栏 160 固定） | 纵向 `32 + 728 + 48 + 160 + 32` | = **1000** ✓ |

⚠️ **踩过的坑（实测）**：`桌面 1232 + 右栏 480` 是 **1712** ✗ —— 超宽 112 ✗ ⇒ 真机上会被裁掉/挤变形 ✓。
⇒ 规则：**先把"固定件"（侧栏/底栏）写死，主区取"剩下的那一份"** ✓（`主区 = 1600 − 边距×2 − 间距 − 侧栏` ✓）；
算不平就**改档位或把边距降到 24** ✓ —— **不许随手写一个接近的数** ✗（违反 UI1：宁可写 `-- TODO(token)` 并给**算过的**候选 ✓）。

**三栏常用布局**（本机侦探类界面验证过）：左栏 `x=32 w=480`、中栏 `x=560 w=480`、右栏 `x=1088 w=480`（= 32+480+48+480+48+480+32 = 1600 ✓）。

## 3. 字号、颜色与对比（"看不清"的头号原因）

> ★ **数值只许从一处常量表取**：颜色 / 字号 / 间距 / 关键坐标，先在脚本顶部写成一张表（`THEME = {...}`），
> 控件创建时**只引用表项**——不许在 `SetSizeDelta` / `imageColor` / `fontSize` 里裸写数字。
> 理由：一屏几十个控件，裸写数字改一处漏九处；而且这张表本身就是 §2/§3 的落点——
> "有表"意味着下一个人（或下一次改动的你）能一眼看出**这个颜色/字号属于什么语义**。

### 3.1 字号（只允许 4 档，同屏最多用 3 档）

| 用途 | 字号 |
|---|---|
| 关卡横幅 / 当前关卡条 | **64**（一屏最多一处；配 `C_GOLD` + 底图一条，见 case §8.9） |
| 页面主标题 | **52** |
| 小标题 / 正文 | **28** |
| 说明 / 注释 | **22**（**正文下限，不许更小**） |

> ⚠️ **"字号大一点"= 在这张表里换档，不是随手 +4**：写 60、56 这种数会被 `tools/check-ui-contract.mjs`
> 按 UI3 拦下（白名单 `64/52/28/22`）。要新档就**同时**改表 + 改校验脚本，否则下一个人不知道它算哪一级。
>
> ★★ **字号大了，矩形必须跟着高（真机铁律，实测）**：文本框的 `sizeDeltaY` 容不下字号的行高
> （CJK ≈ **1.4 × fontSize**）时，这个控件**整条什么都不画** —— 不是裁一半、不是变小、也不报错（`visible` 还是 true、
> 日志里 `text` 也确实设上了），只有真机截图能看出来；**模拟器不模拟这个截断**（同样代码画得出来）。
> 实测：`52` 号放进 **64** 高 → 空白；`64` 号放进 **80** 高 → 空白；同字号放进 **90~120** 高 → 正常。
> ⇒ 定字号的同时把矩形高度按 `fontSize × 1.4 + 余量` 给足（64 号建议 ≥ 96、常用 120）。

- 层级靠"字号 + 颜色 + 位置"三者，**不要**靠加粗（客户端字体粗细不可控）。
- 同一屏里字号超过 3 档 = 视觉噪声。

### 3.2 配色（语义色，按用途取，不要随手加）

| 语义 | RGBA | 用途 |
|---|---|---|
| 主文字 | (245, 240, 234) | 正文、标题 |
| 次文字 | (184, 184, 196) | 说明、辅助 |
| 强调 / 数值 | (255, 210, 77) | 分数、星级、关键数字 |
| 成功 | (140, 240, 168) | 指认正确、通过 |
| 警告 / 失败 | (255, 122, 110) | 指认错误、失败 |
| 面板底板 | (28, 32, 48) | 深色底 |
| 面板描边/分层 | (58, 66, 92) | 做边界感 |
| 半透明文字底 | (10, 12, 20, **190**) | **文字压在素材/花色上时必须垫** |
| 全屏遮罩 | (8, 10, 18, **180**) | 弹窗/暂停时压暗场景 |

### 3.3 对比规则（三条硬规则）

1. **文字与背后的亮度差 ≥ 4 级**（深底浅字或浅底深字，不许中间灰对中间灰）。
2. **文字只要压在素材/花图上 → 必须垫一层半透明暗底**。实测教训："证词整理"直接压在素材上，几乎读不出来。
3. **大面积纯白（如 `100001` 白底图）不许当面板底板**——刺眼且盖住一切；要用 §3.2 的深色底板。

## 4. 面板与层级（谁压谁，一眼就懂）

**层序（从下到上）**：

```
① 整屏背景（色块 或 素材整组）
② （若底下是游戏画面）全屏遮罩，压暗到能读字
③ 面板底板（深色块 / 素材整组面板）
④ 面板内容（文字 / 图片）
⑤ HUD（星级、声誉、阶段）
⑥ 弹窗 / 结果层
⑦ 闪效 / 动效层
⑧ 点击热区（透明、最上）
```

- **面板边界**：优先用带现成边界的官方素材面板；缺少适配素材时，用"**底板 + 比底板亮一档的 8px 内条**"补足简单边界，不以大量小色块模拟圆角或复杂描边。
- **一屏一个视觉焦点**：要么是"大标题"，要么是"主体面板"，要么是"结果文字"——**不许两个并列抢**。
- 弹窗要"三层"：遮罩 + 面板 + 内容；否则在花背景上弹窗会糊。

### 4.1 可点元素必须有状态视觉（**否则玩家不知道"这个能点"**）

四态，缺一不可（至少前三态）：

| 状态 | 表现手段（都在控件属性范围内） |
|---|---|
| **常态** | §3.2 面板底板色 + 主文字 |
| **悬停** | `CursorEnter` / `CursorExit` 回调里把底色或文字**提亮一档**（例：底板 (28,32,48) → (58,66,92)） |
| **按下** | `CursorDown` / `CursorUp`（或 PresetButton 自带态）把底板**再压暗**，或 `SetSizeDelta` **缩 4~8px** |
| **禁用** | 底板降到接近面板色 + 文字用次文字色（别用纯灰——会踩 §3.3 第 1 条） |

- 用 **PresetButton** 时它自带多态（编辑器里配好即可）；用**图片 + 文字自绘**时必须在回调里自己改属性。
- ⚠️ **硬前置（实测，引擎与文档同款）**：光标事件要**祖先容器 `showCursor = true`** 才会派发——
  文档原话「CursorEvent 相关方法都需设置该参数为真后才可正常使用」。
  ⇒ 做法：**弹窗/菜单出现的那一帧置 true、关掉时置 false**；常开的话整局挂着一个常驻光标，很难看。
- 热区与视觉分开建时（透明 `光标检测区域` 压在最上层），**状态视觉改的是底下那层图片/文字**，不是改热区。

<a id="pitfalls"></a>

## 5. 丑法黑名单（逐条对照，出现即改）

1. **大块纯色平铺**、没有任何层次（"一整块白板"）。
2. **随手尺寸/间距**（20 / 37 / 53 / 620）→ 一定歪、一定乱。**改成 8 的倍数**。
3. **文字直接压素材/花背景** → 读不出（缺半透明暗底）。
4. **大而模糊的装饰**（比如 620px 的半透明光晕）→ 又脏又抢焦点；装饰只用小尺寸、低对比。
5. **一次亮出所有元素**，没有焦点、没有阶段感。
6. **所有文字同字号同色** → 没有层级。
7. **把素材拆散、随意缩放旋转** → 破坏作者美术（**素材要整组用**）。
8. **用亮白色大色块当面板** → 刺眼（见 §3.3）。
9. **装饰/面板盖住点击热区** → 点不动（见 §6 多脚本纪律）。
10. **同一元素既当背景又当内容**（既做底板又写正文）→ 改一处必花另一处。
11. **可点元素没有任何状态反馈**（悬停/按下跟常态长得一模一样）→ 玩家不知道能点、也不知道点没点上（见 §4.1）。
12. **裸写数值**（`SetSizeDelta(37, 53)`、`imageColor = (120,200,255)`）→ 偏离 §2/§3 档位、日后改不动（见 §3 顶部那条纪律）。

## 6. 干活流程（一次做对，而不是来回猜）

新整屏与交互流程以 [UI/UX 七步流程](ui-ux-workflow.md) 统筹需求、选型、模板、适配、绑定与试玩；本节只承接布局实现，不替代事件契约和跨端验收。明确的小改只做受影响项。

涉及图片填充、遮罩或连续光标交互时，在本节布局流程前先按 [UI交互可靠性](../../miliastra-code/references/ui-interaction-reliability.md) 核对功能所需的编辑器开关、热区父级和中断恢复。数值读回变化不等于效果已渲染；沿用原美术前也要核对这些配置。此检查只加载当前UI需要的资料。

1. **写信息层级**：这一屏要谁先被看到？（主标题 / 主视觉 / 操作提示 / 辅助信息）写成一行行文字。
   按「素材优先选型」核对各主要视觉区域的官方素材或现有模板，再决定尺寸与布局；简单位置调整直接复用已核实素材。
2. 新整屏或布局方向未定时，用 ASCII 草图表达方案；已有明确布局的小改直接执行。
3. 整屏或联动布局用**坐标表**，小改只记录受影响元素： `名称 | x | y | w | h | 字号 | 颜色`，数值**只从 §2/§3 的档位里取**。
4. **写代码**，建控件顺序按 §4 层序（背景 → 遮罩 → 面板 → 内容 → HUD → 弹窗 → 动效 → 热区）。
5. **视觉验收**由用户确认。工作区允许读取现有截图时，用来辅助核对可读性、层级和 §5 相关项；不因验收流程自行生成图片，不将模拟器画面当真机证据。
6. 诊断实验一次控制一个变量；已定位的联动修改可以一起完成，验证受影响行为。

> **对位神器（借鉴外部 GUI 的 debug 模式）**：脚本顶部留一个 `DEBUG_GRID = false`——
> 打开时用**图片控件**画安全区框（32 边距）与 **8 的倍数**横竖辅助线（薄图片控件 = 一条线，低对比描边色 §3.2），
> 截图对位时一眼看出"差了几格"；**验收前置回 `false`**，别把辅助线留在正式画面里。辅助线总数控制在 20 条以内。

### 多脚本纪律（血泪）

- 多个脚本共用一个容器时，**任何"扫描/清理兄弟控件"的操作都必须白名单**。
  实测事故：`view` 脚本写了"隐藏所有非自己建的控件"→ 把 `input` 的**点击热区**和 `fx` 的**闪效层**一起隐藏 ⇒ **点击彻底失效**。
- 正确写法：按**可辨识特征**精确打击（"名为『图片』且图源为空"），并显式**排除** `光标检测区域`（热区）与黑板控件名。
- **改完必须重开一局真机验证交互**——层级/可见性的改动最容易静默破坏点击。

## 统一规范要求（组件统一 + 样式统一）

> 与 `code-vue` 的「统一规范要求」同源，但千星**没有组件库、没有 CSS 变量、没有圆角/阴影参数**——
> 所以这里的"统一"落在**同一脚本内的构造函数 + 同一张常量表**上。

### 组件统一（同一脚本内）
1. **同类元素只用一套构造函数**：面板 / 按钮 / 弹窗 / 列表项各写一个 `makeXxx(...)`，全脚本只调它——禁止同类元素在两处各写一遍尺寸与配色。
2. **按钮形态全局一致**：主 / 次 / 危险三类的底板色、文字色、内边距、按下缩放**取同一组常量**；禁止一处带底色、一处纯文字。
3. **弹窗同类型同尺寸**：宽度取 §2 档位（480/720/960），固定"遮罩 + 面板 + 内容"三层；关闭方式一致（同一按键 / 同一按钮位置）。
4. **列表与空态统一**：行高、行间距、空态文案位置一致；**空态也要有**（别留一片空白）。
5. **复用优先**：新增前先看已有构造函数/模板；纯函数与构造器可按已配置映射使用 `require` 模块，不能用 require 挂载脚本来取得它的实例状态。细节按需见 [已运行工程参考](../../miliastra-code/references/dialog-template-patterns.md)。

### 样式统一
6. **色彩**：只用 §3.2 语义色表；强调色占比约 **10~15%**（一屏别满屏强调色）。
7. **字号**：只用 §3.1 四档，同屏 ≤3 档。
8. **间距**：§2 的 8 基数 + 24/32/48 三档。
9. **边界**：优先统一使用同风格的官方素材面板；无适配素材时统一用"底板 + 亮一档 8px 内条"。同类面板保持一致。
10. **动效**：同类动效参数取同一组常量；**留一个总开关**（如 `ANIM_ON = true`），便于截图验收与低配降级。

## 工程规范与常见坑

### 历史渲染案例与接口注意事项
- **整屏单块图片控件不渲染**：1600×1000 写进去无报错、画面空白（480×468 正常）⇒ 全屏底必须**拼块**（4 块 800×500）。
- **小尺寸文字控件不渲染**：108×32 的编号条、108×48 的行都不画（数据全对）⇒ 文字控件一律**整格/整面板大小 + 用对齐方式定位**。
- **`rotationZ` 字段写入失败**不等于无法旋转：按 §1.5 核对 `SetLocalRotation`，文档支持与真机效果分开报告。

### 层级三坑（同一类：顺序 / 作用域）
面板建在按钮后 → "下一关按钮呢"；角图建在格子文字后 → "翻牌的文字咋还是没有"；提示条建在底层脚本 → 被格子压住。
⇒ 用 §1.4b 的三件套：**固定顺序 + 会互压的同脚本 + 要压最上的只进最上层脚本**。

### 多脚本清理（静默破坏交互）
`view` 里写"隐藏所有非自己建的控件" → 把 `input` 的点击热区与 `fx` 的闪效层一起隐藏 ⇒ **点击彻底失效**。
⇒ 清理必须**白名单**（显式放行 `光标检测区域` 与黑板控件名）；**改完重开一局**验证交互。

### 性能预算（UI 侧的 N+1）
- 每帧改属性的控件越多越卡：实测 **32 星 + 4 光晕 ≈ 每帧 70+ 次 API 调用** ⇒ 动效**限频 ~20fps**（累积 dt，>0.05s 才动）。
- 优化顺序：① 共享父节点整体动 ② 控件池复用 ③ 限频；新增每帧 setter 时报出"**每帧多少次**"。

### 颜色构造（API 口径，已核）
`Color.FromRGB` / `Color.FromRGBA` **都是 0–255**（不是网页那套 0–1）；`FromRGB` **没有 alpha**，要透明度必须 `FromRGBA`；
`a` 传 `nil` = **255 不透明**——"想半透明却忘了传 a"会得到一块实色。

## 门禁（改完按这个顺序过）

> **两条路径别混用**：
> - **技能自带（可携带，任意 `.lua` 都能跑）**：`node scripts/gates/check-ui-rules.mjs <脚本.lua…>` ｜ `--dir <目录>` ｜ `--selftest`。
>   覆盖 **UI2 / UI3 / UI4 / UI5 / UI6 里静态可判的部分**；回执分三档：**error**（真机铁律：字号档位、`h ≥ 字号 × 1.4`）· **warn**（逐处分析与修复；只有影响玩法、范围、权限或验收的决定才集中询问）· **判不了**（几何是变量 ⇒ 静态判不出，**不算通过**）。
>   判据表与边界 → [`scripts/gates/README.md`](../scripts/gates/README.md)。
> - **工程专属（map 驱动，只服务《侦探1》）**：`node tools/check-ui-contract.mjs` —— 判据是那六份脚本的常量（格盘 / 1:2:1 三栏 / 详情纸片 / 按钮热区），**给别的图明确报错**；它跑在**工程工作区**，换机没有。
> ⛔ **error 红 ⇒ 不许 deploy**；正确动作是「**修到过** / **如实标 `pending` 交付**」——**不许回退、删功能、拿空壳顶**（口径见技能 `miliastra-code` §8「门被打回了，怎么动」）。
> ⚠️ **绿 ≠ UI 合格**：本门只判"字面量形状"；运行时行为、真实观感、素材渲染、动效手感需要真机与用户确认；允许取图时截图可辅助取证。

## 7. 交付前验收清单（检查本次受影响项；整屏制作适用全表）

- [ ] 主要美术已优先核对官方素材/模板，版面表记录真实来源与 ID；程序绘图区域有明确缺口原因，没有用大量小色块重复描绘可复用素材。
- [ ] 所有坐标/尺寸/间距都是 **8 的倍数**
- [ ] 主要面板宽度 ∈ {480, 720, 960}；外边距 ≥32；面板间距 ≥24
- [ ] 字号 ≤ 3 档；正文 ≥22
- [ ] 文字与背景亮度差 ≥4 级；压在素材上的文字**有半透明暗底**
- [ ] 没有亮白大色块当底板；没有大而模糊的装饰
- [ ] 一屏只有一个视觉焦点
- [ ] 层序符合 §4；文字在素材之上（后建）
- [ ] 点击热区在最上层、未被任何"清理"逻辑误伤（多脚本必查）
- [ ] 三种语义色（正常/强调/失败）都有用到，且颜色来自 §3.2
- [ ] 复合素材保留原子树，官方单图按需独立使用；无递归清理，旋转采用文档 API 或编辑器配置且实际效果待用户确认
- [ ] 可点元素有**悬停 / 按下**反馈（§4.1）；弹窗出现时容器 `showCursor` 已置 `true`
- [ ] 颜色 / 字号 / 间距来自**脚本顶部常量表**，没有裸写数字
- [ ] 若开过调试栅格，已置回关闭
- [ ] 一次性定位都带 `-- one-off:` 标注；档位缺失处写的是 `-- TODO(token)`，**不是造值**（UI1）
- [ ] 版面表里**每个可见区域都填了「数据来源 / 通道」与「渲染者脚本」**；"刚发生"类文字（消息 / 滚动日志 / 动作提示）走的是 **`Invoke` 直推**（不是异步变量）
- [ ] 删过/要删任何控件前，已确认读方没有 `if <控件> == nil then return end` 这类**整块早退**（否则一删控件整块界面消失）
- [ ] 动效有本次时序或属性变化证据，真实效果待用户真机确认；允许取图时可用已有多帧画面辅助，不把模拟器数据或自报日志当成真机通过
- [ ] 同类面板/按钮/弹窗/列表用的是**同一套构造函数 + 同一组常量**（见「统一规范要求」）

## 8. 环境与降级

- **工作区允许取图且需要辅助视觉取证时**：走 [`references/visual-check.md`](visual-check.md) 的四步闭环（**在允许取图且有验收需要时截 → 读 → 修 → 复截**），只问三件事（§6.5）。
- **不能截图时**：让创作者截图，或**只做"可计算"的部分**（坐标表 + 颜色表 + 层序表），把"看不清/丑"的判断交给创作者。
- **拿不到画布尺寸时**：按 1600×1000 设计，并在代码里保留 `GetUICanvasSize()` 校准（勿写死）。
- **拿不到素材索引/模板索引时**：**不要编造**（铁律）——说明不可用来源，按「素材优先选型」尝试可用入口；仍无法核实时仅用少量色块 + 文字临时占位，把"素材接入"标成待办，不继续细化成像素拼图。
