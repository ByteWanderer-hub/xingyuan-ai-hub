# 网格计算（面板第六页）—— 把"坐标"从"估"变成"查"

> 作者 要求、补锚点与标记。**纯前端计算**：一个工具都不调、不写任何文件、不碰活文件。
> 配套硬口径：§1.1 画布 1600×1000 · §1.2 锚点=元素中心 · §2 栅格 8 的倍数 · §6 对位神器（`DEBUG_GRID`）。
> 本页与那些是**同一件事的两个入口**：规范说"用哪些数"，这一页帮你把"我要摆在哪"**算成**那些数。

## 1. 它回答哪三类问题（一句话路由）

| 你手上是 | 你想要的 | 用哪个 | 回什么 |
|---|---|---|---|
| 屏幕上一个位置（像素） | 它落在第几格 / 是不是**残格** | **像素 → 格** | `in`（在格里）/ `rest`（**残格**：画布内但网格切不到）/ `out`（画布外）+ col,row |
| 格号 (col,row) | 这一格的 **左上 / 覆盖范围 / 中心** | **格 → 像素** | `x0,y0,x1,y1,cx,cy`（越界会告诉你合法范围 `0~cols-1`） |
| 一串要摆的点 | **逐格速查表**（选定的角给 x,y，可复制） | 点格子多选 → 逐行 `x,y` | 每行带该格颜色标记；**网格改小后失效的行留着重说，不静默丢** |

- 换算的**坐标口径 = 设计画布**（**左上原点、y 向下**）——与模拟器内部舞台（**左下原点**）**不是一回事**，跨着用会上下翻。
- 输出 `x,y` 默认取该格**右下角**（`anchor=br`）——因为"摆模型"多数是右下角对齐；可切 `左下/左上/右上`（`GRID_ANCHORS`）。

## 2. 界面与交互（怎么用最快）

- **左 = 参数 + 结论**：画布宽高（默认 1600×1000）、X/Y 步长（默认 100 / 50）、一个参考像素 (px,py)、一个格号 (col,row)、格内灰字标什么（**中心像素** / 格号 / 不显示）、锚点、导出方式。
- **右 = 可点的网格图 + 逐格速查表**：点格子 = 选中（多选）；**右键 = 刷色标记**（有笔刷与颜色，用来标"这一片要放 X"）；**Ctrl/⌘ + 滚轮 = 只缩图不缩面板**；**左键拖动 = 平移**（拖过会把随后的那次 click 吃掉，免得顺手选中一格）。
- **值会缓存**（localStorage）：作者原话「网格计算的值能缓存下，我不想每次打开都要重新输入」。**存不下（隐私模式/配额满/被禁）会说一次**，不静默。
- ⚠️ **老版本存过的缩放要夹取**：曾存过 0.29 这种值，直接读出来表现为"一打开图只有一条小带" ⇒ `gridZoomClamp()` 统一收进当前范围。

## 3. 参数合法性（不合法就**如实报错**，不静默兜底）

| 输入 | 判据 | 报错文案口径 |
|---|---|---|
| 画布宽/高 | 必须是**正数** | `画布宽/高必须是正数：W × H` |
| X/Y 步长 | 必须是**正数** | `步长必须是正数：X sx / Y sy` |
| 步长 vs 画布 | 至少放得下一格 | `步长比画布还大（X sx / Y sy）⇒ 一格都放不下` |
| 格号 | `0 ≤ col ≤ cols-1`、`0 ≤ row ≤ rows-1` | `没有这个格：列 0~N、行 0~M（你给的是 c, r）` |

- 格数 = `floor(画布 / 步长 + 1e-9)` ——**那个 `1e-9` 是给浮点兜底的**：步长 0.1 这类不该因为 15.999999 白丢一格。
- **残格（rest）是这一页最容易被忽略的结论**：画布 1000 / 步长 300 ⇒ 3 格覆盖 900，最后 100 是**切不到的残格** ——
  摆在那里的东西"看起来在网格上"，其实**不在任何格里**（导出时会被算成界外）。看到 `rest` 就该换步长或挪位置。

## 4. 与栅格规范的关系（谁管什么）

| | 管什么 | 数值从哪来 |
|---|---|---|
| **§2 栅格规范** | **该用哪些数**：8 的倍数、边距 32、面板宽 480/720/960、间距 24/32/48 | 规范表（人照着填） |
| **网格计算** | **某个具体位置是几号格 / 那格的角在哪**（把"设计稿上的意思"落成 `SetAnchoredPosition` 的 `dx,dy`） | 算出来的 |
| **§1.2 锚点公式** | 按[坐标与层级](design-guide.md#layout)的唯一公式，把控件左上角及宽高换成中心位置，再减父级中心；不可漏掉半宽高 | 代码里 |

- 典型串法：**网格计算**里把步长设成 **8**（或 8 的常用档 24/32/48），画布 1600×1000 ⇒ 直接查"这块面板的左上角落在 (32,120)"；
  再用 §1.2 的公式写进代码。**步长设成 8 就是"把规范变成可点的尺子"**。
- 反过来：素材组没有已知尺寸、算不出左上角（§1.2）⇒ 素材只能按**中心**给，别拿网格的"左上角"去套素材。

## 5. 纯函数（可被脚本/测试直接引用，别重写一份）

面板里这些是**纯函数**（导出 `__testGrid*` 供渲染测试与外部脚本用）：

| 函数 | 签名 → 返回 |
|---|---|
| `gridPlan({width,height,stepX,stepY})` | `{ok, cols, rows, coverX, coverY, stepX, stepY, width, height}` 或 `{ok:false,error}` |
| `gridCellToPixel(plan,col,row)` | `{ok,col,row,x0,y0,x1,y1,cx,cy,note}` |
| `gridPixelToCell(plan,px,py)` | `{ok,state:'in'\|'rest'\|'out',col,row,…}` |
| `gridLines(plan)` / `gridAxisLine` / `gridSummaryLines` | 画线用的几何（网格图与 ASCII 表） |
| `gridLabels(plan,labelMode,anchor)` | 每格格内灰字（中心像素 / 格号 / 空） |
| `gridSelRows(plan,sel,anchor,colors)` | 多选逐行 `{ok,col,row,x,y,color,note}` |
| `GRID_ANCHORS` | `br(右下,默认) / bl(左下) / tl(左上) / tr(右上)` |

- 要"脚本里算坐标"就 import 这些（`lib/client.js` 是客户端 bundle，服务端脚本引用它只借**纯函数**，不借 React 部分）。

## 6. 坑（都踩过）

1. **别拿这一页的坐标去喂模拟器舞台**：这里 y 向下、左上原点；模拟器内部左下原点（见 UI 参考的模拟器章节）。
2. **别用"看起来对齐"代替残格检查**：`rest` 那一带的东西不在任何格里。
3. **别在代码里裸写算出来的数**（UI1）：算出来的是**一次性定位** ⇒ 标 `-- one-off: 为什么`；能进常量表的就进表。
4. **别把缩放当成"改参数"**：Ctrl/⌘+滚轮只缩**图**，不改格数与步长（避免"我以为改了步长"）。
5. **值缓存 ≠ 全局配置**：它存在浏览器 localStorage，换机器/清缓存就没了 ⇒ 重要版面数字要落到脚本常量表或策划案里。
