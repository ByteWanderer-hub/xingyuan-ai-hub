## 一、采用以下编辑器约束

### **1\.1 这是受编辑器约束的 Lua 运行环境**

编辑器中的 Lua 版本、标准库裁剪范围和额外扩展都可能与通用 Lua 环境不同。判断某个写法是否可用前，从当前 API 文档核对：

- Lua 语言版本和语法边界；

- 可用、被裁剪或被替换的标准库；

- traceback、时间、数学等扩展能力；

- 文件系统、网络、动态模块和原生对象构造是否开放；

- 是否提供计时器，以及计时器属于哪个时间域、如何取消。

文档没有声明的能力一律视为不可用。若没有文档化计时器，需要计时功能时由 Runtime 使用已确认的逐帧时间源和队列实现，不得凭空调用常见框架中的计时器。

### **1\.2 将 Lua 状态映射到编辑器原生 UI 控件**

画面由 Lua 状态驱动编辑器提供的原生 UI 控件。图片、文字、滚动文字、输入区域、按钮和运行时父组分别需要哪种控件，必须根据本次需求在当前 API 文档中查询，README 不保存 subtype 名称。

控件通常来自创作者预先建立的客户端控件模板，Lua 侧只能通过模板“索引”实例化；Lua 如何实例化、父级参数接受对象还是标识、返回什么基类或具体类型，都必须在当前 API 文档中确认。模板索引、运行时实例 ID、父控件和图片资产 ID 是不同概念，不得互换。排查“控件不显示”“属性写不进”这类故障时，先确认没有把其中两个当成同一个。

### **1\.3 按编辑器生命周期组织代码**

脚本由编辑器生命周期驱动，不要从文件顶部启动永久循环。排查与修复前必须查询当前 API 文档列出的初始化、启动、启用、禁用、逐帧更新、关卡时间更新和销毁入口，并核对每个入口的参数、调用条件和时钟语义；README 不保存这些回调的具体名称。

创建控件、注册监听或启用逐帧更新时是否会同步重入，也必须以当前 API 文档和真实运行证据为准。**本项目已在真机上观察到：实例化客户端控件会同步重入挂载脚本的启动回调，重入环境独立，且此时状态机可能仍是 ****`NEW`****，仅靠“只在 ****`NEW`**** 时启动”的状态守卫挡不住。** 因此创建类调用必须同时具备跨实例初始化防线（初始化锁或“宿主控件树里是否已存在本页面”的检测），不能只依赖单一状态标志；除这条已观察到的机制外，文档未说明的重入仍标记为 `unknown`，用状态 guard 防止重复进入，只有真实观察到才标记为 `observed`。

生命周期回调已经发生，只能证明脚本进入了该回调，不能证明编辑器提供的所有外部对象和运行时数据已经同时就绪。挂载容器、脚本查询结果、画布信息和其他启动依赖必须分别判断；某一项此刻取不到，不等于配置错误，也不等于其他依赖同样未就绪。

启动检查必须区分三种结果：配置缺失或格式错误属于确定的配置错误；运行时对象尚未出现或尚未存活属于 `not_ready`；对象已经就绪但身份明确不符属于确定的不匹配。只有第一种和第三种可以立即失败，`not_ready` 必须留在启动状态并经过有界重试，不能被写成“不匹配”。**排查偶发故障时，第一件要确认的就是这三类有没有被混在一起判断。**

### **1\.4 明确编辑器日志行为**

当前版本有哪些普通、警告和错误日志入口，以及它们是否会抛错、停止脚本或只写日志，必须从当前 API 文档确认。本文件只规定第十一节的聚合策略，不声明具体日志函数及其行为。
