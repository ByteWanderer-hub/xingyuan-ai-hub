## 六、施前要求创作者完成以下内容

要求创作者在编辑器中完成这些步骤。不要尝试用 Lua 代码代替编辑器配置。

### **6\.1 先建立客户端脚本入口**

第一阶段必须把“创作者要做什么”和“创作者需要提供什么”分成下面两个部分。在按照下面的段落进行回答时，不要附带其他内容，不要在这两个段落之间插入解释：

> 接下来，我们先完成第一步，请按照下面的步骤进行操作\~

1. 来到「千星沙箱」窗口，点击右上角「窗口」，之后点击「客户端脚本资源管理器」

2. 双击「未分类页签」或是你自己创建的文件夹

3. 右键选择「新建客户端脚本」

4. 在弹出的窗口中，单击上方的路径，确保路径为全选状态，然后按下键盘上的`Ctrl + C`键进行复制。这是**脚本路径**

5. 在下方「文件名」填写框中，填入任意文件名，在无其它脚本文件时推荐用`levelScript`作为脚本名。记得复制此内容，这是**脚本名称**

6. 点击「保存」

7. 回到「原神」窗口，前往「界面控件组管理」

8. 在左上角切换需要挂载客户端控件的「界面布局」

9. 点击左下角「添加界面控件」

10. 展开「预制模板」，创建「客户端控件容器」

11. 选中创建的「客户端控件容器」，在右侧边栏的「画布设置」中点击「前往编辑」

12. 检查当前是否选中了「容器节点」，如果是，请点击右上角「复制」按钮，这是**「容器节点」的索引**

13. 在右侧切换「脚本」页签，点击「添加脚本」，并选择刚才创建的脚本。

> 完成！

> 在操作步骤中，有一些加粗的、要求复制的内容。接下来，请按照下列格式发送刚才复制的内容：

1. 脚本路径

2. 脚本名称

3. 「容器节点」的索引

> 这样我们可以开始下一步。（注意，一定要在「客户端控件容器」的「容器节点」上挂载好这个脚本哦）

第一部分只负责说明操作，第二部分只负责索取两个值。第一阶段不得索取其它普通控件模板索引，不得要求创作者另行回复“客户端脚本已挂载：是”；`levelScript` 只作为已有或可选 Lua 脚本的示例，不作为创作者绝对使用的名称。

创作者提供这几个值不能代替运行时验证。开始正式玩法逻辑前，先在当前 API 文档中查明如何取得当前脚本实例、挂载容器、脚本运行时名称，以及如何从容器查询已挂载脚本。然后确认这些对象均有效、运行时脚本名称与 AI 归一化后的短名称逐字相同、容器查询到的脚本实例就是当前实例。具体字段和方法名只从当前 API 文档取得，不从 README 复制。配置值本身缺失或格式错误时立即停止；运行时对象暂未取得时记录为 `not_ready` 并进入启动就绪重试；只有对象已经就绪且核对结果明确不一致时才判定挂载失败。未通过最终核对前不得声称脚本已经正确挂载，也不得创建玩法资源。

**需要创作者提供内容时，必须先输出完整的索取内容，再结束本轮并等待回复；但不得因为急于推进而跳过“先核对已有结论”这一步。**已经是创作者提供过或本轮对话已经确认的值，直接沿用，不要重复索要。

工程已有合适的客户端控件容器和已挂载脚本时允许复用，但仍要取得容器索引和实际挂载脚本名称；创作者若发来路径，由 AI 自行归一化。

编辑器中的“客户端控件容器”的“容器节点”是脚本挂载入口，“容器节点”是客户端控件容器下的根节点，其索引必须由创作者提供；脚本中使用的动态创建的实例都基于容器节点并以其为父节点。客户端控件容器索引（服务器索引）、容器节点索引（客户端索引）和动态实例的运行时 ID 是三种不同标识，禁止混用。

### **6\.2 按用户语言提出前置要求**

本节是创作者交接格式的唯一权威版本，6\.3 与 6\.4 只做本节的登记与说明，不重复规定格式。

- 当前用户使用中文时，使用 6\.1 和 6\.3 的中文固定格式，控件名称也使用中文，例如“图片控件”。

- 当前用户不使用中文时，用用户语言表达相同内容，但控件名称统一使用英文。无法可靠使用用户语言时，整段使用英文。

- 除非用户需要，不要提前告知用户 API 名称和用途，不要输出控件配置，不要增加用户不需要的信息。

- 第一阶段必须保留“操作段落”和“所需信息段落”的分隔。

- 第二阶段只有控件模板名称使用编号列表；创建操作仍单独放在列表前的一段话中。

非中文用户无法可靠使用其语言时，第一阶段使用英文回复创作者。

只有收到客户端控件容器索引和实际挂载的 Lua 脚本信息后，才允许发送第二阶段的控件模板请求。脚本信息可以是名称或路径，AI 必须自行归一化；任一值缺失时，只简短索取缺失值，不得提前索取普通控件模板索引，也不得重新发送十几个微操作。

下面只规定面向创作者的控件名称。实际 API subtype 必须由 AI 根据当前 API 文档在内部匹配，禁止把 subtype 或用途说明输出给创作者。

|---|---|
|文本框|Text Box|
|图片控件|Image Control|
|光标检测区域|Cursor Event Area|
|预设按钮|Preset Button|

### **6\.3 创建 Lua 可以实例化的 UI 元件**

只有第一阶段的客户端控件容器索引和实际挂载脚本信息都已收到，才发送第二阶段。中文创作者必须收到以下格式：

> 然后进行第二步，请按照下面的步骤进行操作\~

1. 请前往「界面控件组库」

2. 切换左上角为「客户端控件模板」

3. 点击左下角「添加客户端控件」

4. 按照下面顺序，逐个创建并保存本次需要的客户端控件模板

> 请向我提供以下控件模板的索引：

1. 文本框

2. 图片控件

3. 光标检测区域

根据本次真实需求删去不需要的名称，或加入 API 文档确认需要的其他控件模板名称。编号列表只能包含控件名称，不得解释用途，不得在名称后添加配置、备注或预设要求。

当前用户不使用中文时，用用户语言表达相同的两段内容，并使用英文控件名称。

非用户需要，不要说明控件将用于角色、HUD、输入、父组、动画或其他功能；不要让创作者设置文字、图片、颜色、尺寸、位置、锚点、父级、射线、动效或默认值。禁止增加用途说明、表格列或编辑器预设步骤。

常用的控件模板包括：文本框、图片控件、光标检测区域、预设按钮、容器控件、文本视窗、网格视窗、按键提示、界面动效、全屏动效和模板引用控件。只选择本次实际需要的名称；每个名称对应的准确 API subtype 必须在当前 API 文档中查询，不在 README 中维护映射。

### **6\.4 只接收必要的容器、脚本和 UI 元件身份信息**

第一阶段只接收以下两个值：

```Plaintext
容器节点索引：
实际挂载的 Lua 脚本名称：
```

收到这两个值后，第二阶段才接收本次实际所需控件模板的索引，例如：

```Plaintext
1. 文本框索引：
2. 图片控件索引：
3. 光标检测区域索引：
```

不要额外索取“客户端脚本已挂载：是”。创作者只需按第一阶段完成挂载并提供容器索引和脚本信息；名称、相对路径和绝对路径都可以，AI 必须自行提取短名称并使用运行时校验确认挂载关系。不得纠正创作者的回复格式，不得要求创作者重新只发短名称，也不得要求创作者解释目录位置。普通控件只列出本次实际需要的类型。

不要要求创作者补充容器或控件用途、API subtype、默认配置、图片、文字、布局、父级、备注或其他控件编辑信息。索要容器索引和脚本信息是为了核对容器与脚本挂载身份，不得扩展成让创作者编辑控件属性。

**创作者不需要为多端适配做任何手工配置。** 中心点、最小锚点和最大锚点全部由 AI 按第八节推导并在代码中设置；锚定配置表属于 AI 内部产物，禁止作为额外交接表发给创作者，也禁止要求创作者填写设计基准或安全区之外的布局数据。HTML Demo 按 8\.13 交给用户评价与确认，它是开发基准与评审对象，不是交接表——不要让创作者去填它，也不要把它当成交付成果。

### **6\.6 多文件时的脚本批量添加（仅在用户选了“大佬”时执行）**

用户按 5\.5 选择“有动手能力的大佬”、或策划案本身要求多文件时，脚本文件不止一个，逐个在编辑器里新建既慢又容易漏。此时走本节的批量添加流程。

#### **6\.6\.1 先取得代码根目录**

客户端脚本必须先存在于沙箱中，才能被挂载脚本 `require`。因此多文件模式下，代码文件使用用户提供的 `external_lua_file` 文件夹作为根目录。

向用户索取一次，格式固定为：

```Plaintext
external_lua_file 文件夹：
```

约定与边界：

- 所有 Lua 代码文件都放在这个文件夹下，包括入口脚本与各业务模块。

- **可以在该文件夹下新建子文件夹**，用于按模块分组（例如 `core/`、`world/`、`ui/`、`data/`）。

- **之后新创建、需要批量添加的脚本一律放进子文件夹**，不要在根目录散落文件。这样每次批量添加时都能按文件夹一次选中，避免根目录下混着旧脚本被一起添加。

- 这个文件夹路径属于创作者提供的配置，按 6\.5 的规则处理：只用于交接与诊断，不得与运行时实例 ID、控件模板索引混用。

#### **6\.6\.2 发给用户的批量添加步骤**

把下面这段原文发给用户，不要改写步骤名称，不要合并步骤，也不要让用户逐个新建脚本：

> 接下来需要把新写的脚本批量导入沙箱，请按照下面的步骤操作～

1. 转到「千星沙箱」

2. 转到「客户端脚本资源管理器」

3. 任选一个文件夹

4. 右键

5. 选择「批量添加脚本文件」

6. 选择「按文件夹」

7. 选择对应的文件夹

8. 点击「打开」

9. 显示「添加成功」即完成

#### **6\.6\.3 执行纪律**

- **先把脚本文件准备好、再让用户批量添加**：文件没落到 `external_lua_file` 下之前，不要发这段步骤，否则用户添加的是空文件夹。

- **一次只让用户批量添加一批**。分批添加时，先说清这一批包含哪些子文件夹和哪些文件，添加成功后再继续写下一批依赖它们的代码。

- 用户选择的目标文件夹必须是**存放本次新增脚本的那一层子文件夹**；把整个工程根目录作为选择对象会让旧脚本被重复添加。

- 添加成功后不要要求用户提供每个脚本的路径或名称；`require` 使用的是模块路径，主 Agent 自己从 `external_lua_file` 的目录结构推导，必要时按 6\.3 核对入口脚本的挂载关系。

- 用户反馈「添加成功」之后，仍然要按 6\.3 核对入口脚本确实挂在客户端控件容器的容器节点上；批量添加只证明文件进了沙箱，不证明挂载关系正确。

- 用户反馈添加失败或列表为空时，只排查三件事：选择的文件夹里是否确有 `.lua` 文件、脚本是否被放在了子文件夹里、用户是否选到了正确的目录。不要要求用户改用逐个新建的方式绕过。

- 本节是全流程中**唯一**需要创作者动手的操作。除此之外，多文件模式不额外增加创作者负担：模块怎么分、文件怎么组织、`require` 怎么写，全部由 AI 决定。
