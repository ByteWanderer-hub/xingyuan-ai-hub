## 十一、编写前的自查与交付说明

### **11\.1 交付说明的固定结构**

交付说明按下面 12 项输出，缺项就是没写完：

```Plaintext
1. 本次实现了什么（对应哪条需求，逐条对齐）
2. 修改与新增的文件清单，并注明每个文件的角色（入口脚本 / 业务模块 / Demo / 中间产物）
3. HTML Demo：文件路径、版本号、用户确认状态与用户原话摘录
4. 锚定配置表的内容或路径，以及与 Demo 的一致性核对结论
5. 代码目录与文件划分：本次是单文件还是多文件、每个文件负责什么、模块之间怎么互相调用
6. 本次新用到的编辑器 API 标识，以及每个标识在当前 API 文档中的依据
7. 图片资产：用了哪些、ID 来自哪里、用户是否已确认
8. 子 Agent 使用记录：图片查找、语法检查、帧动画还原、像素画重建各自的结论与采纳情况
9. 玩家可见文本清单：关卡里出现的所有玩家可见文字，以及确认它们不含创作者术语的自检结论
10. 仍然 pending 的验证项（真机、多端、设计稿视觉一致性、动画与像素还原误差）
11. 我替用户做的选择（暂定项）、依据与一键改法
12. 未完成项与被记录的既有故障（不做，另起修复流程）
```

第 10 项必须诚实区分：`documented`、`provided_unverified`、`observed`、`inferred`、`unknown` 与真机状态 `passed`、`failed`、`pending`、`not_required` 是两组独立字段，按 10\.1\.2 填写。静态检查通过、子 Agent 报告、HTML Demo 量测与用户确认、本地推演都不能写成真机通过。

### **11\.2 代码骨架的落点对应表**

骨架的职责划分、状态机、启动顺序、控件创建与图片绑定、输入与坐标、运行与可见与命中状态的分离，全部由第九节规定。下面只补充**新增代码时必须落到哪里**：

|要加的东西|落在哪里|
|---|---|
|新的静态配置（容器索引、脚本短名称、锚定配置表、Demo 版本号）|Runtime 配置区，与其他配置并列，不得散落在玩法函数里|
|新的控件|资源创建阶段，按 9\.4\.1 的事务顺序，并在创建成功后立即登记清理动作|
|新的布局数值|只写入锚定配置表，由表生成赋值，不在玩法函数里直接写数字|
|新的监听|注册后立即把回调引用登记进 Runtime，保证能按原引用移除|
|新的逐帧逻辑|只在 `RUNNING` 分支内推进；`STARTING` 分支只允许推进一次启动就绪尝试|
|新的清理动作|统一进清理栈，按创建顺序的反向释放，不单独写一套销毁流程|
|新的日志|按 10\.3 的聚合规则，不逐帧打印、不逐字段分开打印|
|新的图片资源|先按 7\.1 走完四步拿到并确认资产 ID，再按 9\.4\.3 的顺序绑定|
|新的业务模块文件|按第十三节的目录约定放进 `external_lua_file` 下的对应子文件夹，先在入口里 `require` 并登记，再让用户按 6\.6 批量添加|
|新的页面|页面单例与宿主控件树检测按第十三节 13\.6 的写法，放进对应 UI 模块文件，不在入口文件里堆页面代码|
|新的玩法数据（关卡、波次、数值、剧本）|放进数据模块文件（例如 `data/` 下），逻辑模块只解释数据，不把数据写进逻辑|

### **11\.3 新增控件的固定写法**

每一次新增控件，都必须按下面的顺序写，并让注释能对应到锚定配置表的行：

```Plaintext
1. 从锚定配置表取出这一行的：ID、锚点 Min、锚点 Max、中心点、相对尺寸、相对偏移
2. 按 8.7.2 的换算链把相对值换算成本次实际数值
3. 按当前 API 文档声明的入口创建控件，并设置父级
4. 设置中心点 → 设置最小锚点 → 设置最大锚点
5. 设置尺寸与位置（拉伸方向由锚点表达，不要重复写死尺寸）
6. 关闭输入命中、保持不可见
7. 写入该 subtype 已文档化的其他属性（颜色、文本、图片按各自章节的顺序）
8. 启用控件，并按文档或真实证据决定是否需要重提锚点与中心点
9. 读回文档允许读回的状态并核对
10. 显示，需要交互时最后开放输入命中
11. 立即登记清理动作
```

- 第 4 步与第 5 步的顺序不得调换。先写位置再改锚点，位置会按旧锚点解释，换分辨率后整体偏移。

- 代码里禁止出现 1600、900 这类基准像素硬编码，只允许出现在设计基准对照表或换算函数这一处集中位置。

- 同一个数值不得在多个位置各写一份。需要复用时从锚定配置表或换算函数取。

### **11\.4 交付前的自查清单**

逐项勾选。任何一项不通过，先修完再交付：

* [ ] 本次走的是编写流程，没有夹带修 bug 或重构

* [ ] 开工前阻塞项已按第五节追问并得到回答，或已明确记为暂定并给出改法

* [ ] 当前 API 文档已确认，annotations\.lua 已按它生成或更新，并带时间戳

* [ ] 创作者交接的三项信息齐备：容器节点索引、实际挂载脚本、本次所需控件模板索引

* [ ] 用到的图片资产都走完了 7\.1 四步，且用户已确认，不存在猜选的 ID

* [ ] 已按 5\.5 问清用户是萌新还是大佬，并按结论决定单文件或多文件；策划案另有要求时以策划案为准

* [ ] 多文件时，代码文件都放在 external\_lua\_file 下，新增脚本按子文件夹归置，并已按 6\.6 让用户批量添加成功

* [ ] HTML Demo 已真实运行并取回量测结果；未取得时已在交付说明里写明是推导值

* [ ] 已按 8\.13 把 Demo 交给用户评价并取得确认（或已明确标注“未经用户确认”），确认版本号已记录

* [ ] 布局来自设计稿（8\.1 至 8\.6）或 HTML Demo 量测（8\.7 至 8\.10），没有凭想象给坐标

* [ ] 本次属于重大玩法更新或扩展时，已重做 Demo 并重新取得用户确认

* [ ] 每个新增控件的锚点、中心点、尺寸、偏移都来自锚定配置表，且创建顺序正确

* [ ] 锚定配置表与确认版 Demo 逐项一致，没有两边各说一套

* [ ] 代码里没有基准像素硬编码，没有在玩法函数里写坐标，没有未使用的预留代码

* [ ] 多文件时没有循环 require，共享状态只有一处归属，模块装配顺序与依赖方向一致

* [ ] 每个编辑器 API 标识都能在当前文档中找到，且调用形式、参数、返回值、字段读写性、枚举、清理入口逐项一致

* [ ] 每个资源的创建都登记了清理动作，失败路径与销毁路径都能反向释放

* [ ] 启动依赖按“配置错误 / not\_ready / 确定不匹配”分开处理，重试有界且有最后原因

* [ ] 坐标关系仍为 unknown 时，代码里没有自定义命中、绝对位置比较或位移驱动布局

* [ ] 日志按聚合规则输出，没有逐帧打印，没有给每个 getter 单独套保护调用

* [ ] 子 Agent 语法检查已执行并处理完问题清单，结论只记为静态语法证据

* [ ] 用到帧动画或像素画还原时，已按 2\.5\.3、2\.5\.4 交给技能子 Agent，并把规模、误差与未验证项写进交付说明

* [ ] 已按第十四节核对全部玩家可见文本，没有实现原理、内部字段或创作者术语

* [ ] 启动汇总块已按 10\.2 核对，关键运行时字段齐全

* [ ] 交付说明 12 项齐全，pending 项与暂定项都如实写出

### **11\.5 必须停下来的时候**

|情况|处理|
|---|---|
|存在未确认的阻塞项（需求、平台、基准、验收）|按第五节追问，等回答|
|还没有确认用户是萌新还是大佬|按 5\.5 必问，等回答；不得自行决定文件数量|
|当前 API 文档缺失或版本冲突|按第七节处理；缺失时停止所有依赖 API 的实现|
|设计稿缺少 8\.2 列出的必需信息|按第五节追问，不得自行假设尺寸或锚点归属|
|HTML Demo 还没给用户看，或用户还没给出结论|按 8\.13 交付并等待；不得开始写正式代码|
|用户对 Demo 提出布局类意见但还没看到改后版本|改 Demo、重新量测、重新确认，不得直接进入编码|
|本次属于重大玩法更新或扩展|停下来说明，按 8\.13 重做 Demo 并重新确认|
|按锚点无法同时满足多端可读性与不重叠|停下来说明约束冲突，请用户选择改画法还是改基准|
|需要图片但候选未被用户确认|暂停用到该图片的部分，其余部分可以继续|
|创作者交接信息未齐|按第六节索取，不猜值、不填临时 ID|
|批量添加脚本还没成功|按 6\.6 处理；不得改写成逐个新建，也不得先写依赖它们的代码|
|量测无法取得且不能推导|在交付说明写明未量测，并把相关布局标为 pending|
|实现过程中发现既有故障|记录到未完成项，另起 Debug 流程，不在本轮改|
|发现需要改动的范围超出本次需求|停下来说明，请用户确认是否扩大范围|
