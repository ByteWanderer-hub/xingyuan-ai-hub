## 三、子 Agent 使用规范

本节是子 Agent 使用的唯一权威章节。

### 3\.1 必须使用子 Agent 的场景

以下工作**必须**交给子 Agent 执行，不得由主 Agent 亲自完成：

1. **网页检索与资料整理**：为复刻或借鉴玩法检索游戏信息、机制解析、数值资料、玩家评价、攻略与评测。

2. **图片与截图信息整理**：把参考图、截图、视频截图说明整理成结构化清单（界面分区、元素位置、配色、尺寸比例），供设计稿引用。

3. **编辑器图片资产检索**：在图片资产数据标注（如 `Image_sample_by_id.json`）或素材库中检索候选图片资产 ID，返回候选清单与依据。检索规则见 4\.6。

以下工作**不得**交给子 Agent，必须由主 Agent 亲自完成：

- 与用户的任何交流、提问与确认；

- 玩法设计、数值定稿、剧情与文案撰写；

- 设计稿的最终判定与交付；

- 图片资产 ID 的最终采纳（子 Agent 只提供候选，采纳前必须请用户确认）。

**动画还原与像素重建不在创作流程内。** `lua-control-frame-animation` 与 `pixel-lua-reconstruction` 这两个技能属于**代码流程**，由代码 AGENT 在实现阶段调用，创作流程不调用、也不产出动画数据或点阵数据。创作流程只负责把这类需求写清楚：某处需要哪种动画、目标帧率、是否循环、大概用到哪些画面元素。具体怎么还原、控件峰值多少、文件体积多少，由代码流程用技能去算。见 4\.4\.3。

### 3\.2 调用要求

- 每个子 Agent 只承担一件任务，一次只问一个问题。不要把“查资料 \+ 查图片 \+ 顺便找数值”合成一个子 Agent。

- 子 Agent 的提示词必须自包含：它看不到主对话，必须写清目标、输入文件、检索范围、输出格式和禁止事项。

- 必须告知子 Agent：不要修改正式文件，不要对外发言，不要臆造结果，找不到就如实报告“未找到”。

- 同一批次的多项检索可以并行启动多个子 Agent，但结果必须由主 Agent 统一汇总和统一对齐。

- 只接收结论、证据和文件路径。不要把网页原文、图片标注原文或整份资源清单读进主上下文。

- 子 Agent 的结论一律先记为 `provided_unverified` 或 `inferred`。只有主 Agent 亲自核对过的内容，才可以升级为 `documented` 或 `observed`。

- 子 Agent 不得通过与用户对话来补全缺失信息。缺少输入时它应当报告缺口，由主 Agent 决定是否向用户追问。

### 3\.3 子 Agent 提示词的标准结构

每次调用子 Agent，实际发出的提示词都必须由下面七段按顺序拼成，缺一段就不得发出。每段用方括号标题明确标出。方括号中的内容全部由主 Agent 填写，不允许留空，也不允许写“自行判断”“按需要处理”这类把决策推回给子 Agent 的话。

```Plaintext
[角色与目标]
一句话说明这个子 Agent 是什么角色、要交付什么，以及一句话交付标准。
不要写组织的背景介绍，也不要复述本文件规则。

[输入规格]
逐项列出：可用文件与其完整路径、需要读取的字段或结构、检索关键词。
只给路径与条件，不要把文件内容抄进提示词。

[执行步骤]
编号步骤，每步一个动作。首尾固定为“读取并确认数据格式”与“按返回格式输出结果”。
中间步骤按任务类型填写，最多 6 步，且不得包含需要主 Agent 决策的分支。

[返回格式]
给出字段清单与字段名，并给出一行示例或占位行。
说明结论文本的最大长度（默认不超过 30 行），并说明超长时优先保留什么。

[自检清单]
2～4 条，必须是子 Agent 自己可判定的检查。
至少包含一条“未找到 / 未能执行时必须显式写明，不得留空、不得编造”。

[单一结论]
一句话写死：只交付一个结果，不要把多个备选方案、多个版本或未决选项一起交回。

[禁止事项]
逐条列出不得做的事，至少包含：不得与用户交互、不得修改正式文件、不得臆造或补全未读到的内容、
不得把推测写成结论、不得访问分配范围以外的路径。
```

硬性规范：

- 提示词目标字数 600～1200 字。超过 1200 字说明任务混装，应当拆成多个子 Agent。

- 输入只给路径、字段名和筛选条件，不得把网页原文或标注原文贴进提示词。

- 需要精确证据时，要求附上“来源路径或链接 \+ 位置 \+ 不超过 40 字的摘录”。

- 提示词里不得出现“大概”“应该”“尽量”这类模糊措辞；判定阈值必须写成具体数值或明确条件。

### 3\.4 交接记录

每个子 Agent 都必须留一条记录，字段固定如下：

```Plaintext
条目 ID | 场景 | 分配的任务 | 使用的模型档位 | 提示词摘要（不超过 50 字）
→ 返回摘要（不超过 50 字） | 证据来源 | 采纳/驳回 | 驳回原因或返工说明
```

交付设计稿时，只在出现结论冲突、驳回或高风险结论时列出对应条目；其余情况保留记录但不必逐条展示。
