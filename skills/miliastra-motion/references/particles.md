# UI 粒子：机制、参数、配方与预算

> 机制改编自 iart-ai `webgl-animation-skills` 的 particle-system（MIT）；配色与分层原则改编自 adnvli `vfxskill` 的 VFX design（MIT）；预算与池策略**以 `miliastra-code` 的真机实测为准**，本文件不另立数字。

## 1. 心智模型

一颗粒子就是**一个原生图片控件**（矩形 100001 / 圆 100002 / 三角 100003）+ 一份状态：

```
粒子 = { 控件, x, y, vx, vy, life, maxLife, rot, vrot, size, color, alpha }
```

- 控件**建一次**，之后每帧只改字段（位置、旋转、尺寸、颜色）。
- 粒子的"好看"来自三件事：**数量 × 寿命 × 分布（速度/尺寸/颜色的随机范围）**，不是来自贴图多。
- 一个发射器 = 一个循环（OnUpdate），它只负责推进所有存活粒子。

## 2. 每帧循环（核心就是 4 行）

```
for p in particles where life > 0:
    p.vx, p.vy = p.vx + (force.x * dt), p.vy + (force.y * dt)   -- 力
    p.vx, p.vy = p.vx * drag, p.vy * drag                        -- 阻尼
    p.x,  p.y  = p.x + p.vx * dt, p.y + p.vy * dt                -- 积分
    p.life = p.life - dt / p.maxLife                             -- 寿命
    p.size = lerp(startSize, endSize, 1 - p.life)                -- 尺寸曲线
    p.alpha = curve(p.life)                                      -- 淡入淡出
```

要点：

- **dt** 用真实帧间隔（秒），掉帧不会让粒子"变慢/变快"不同步。
- 阻尼按秒做 `v *= drag^(dt*60)`（或直接 `v *= (1 - k*dt)`），不要每帧乘固定 0.99——**帧率一变速度就变**。
- 位置用浮点累加，控件坐标按整数/栅格落点前再取整，避免抖。

## 3. 发射：爆发 vs 连续

| 类型 | 用法 | 关键参数 |
| --- | --- | --- |
| 爆发（burst） | 一次性事件：按下、命中、获得奖励、开袋 | 数量 n、速度区间、角度区间、寿命区间 |
| 连续（continuous） | 环境：蒸汽、冷汽、雨雪、余烬 | **发射率 rate（个/秒）**、寿命、速度、散布角 |

连续发射的稳态数量近似：

```
同屏存活 ≈ rate × lifetime_mean
```

例如 rate=20/s、寿命 1.5s ⇒ 常驻约 30 颗。**先算这个数再决定 rate**，不要写完发现控件爆了。

## 4. 力

| 力 | 作用 | 典型值（相对量，按本工程单位换算） |
| --- | --- | --- |
| 重力 | 碎片、彩纸下落 | 600–1200 px/s²（web 量级） |
| 阻尼 | 空气阻力 | 每秒衰减 10–30% |
| 风力 | 蒸汽横向漂移 | 10–40 px/s²，带正弦摆动 |
| 吸引/排斥 | 光标附近的火花、被吸进容器的气体 | 与距离平方反比，半径内才有 |
| 涡流（curl） | 烟、气流的"有机感" | 不用噪声库也能近似：见下 |

**无噪声库的流场近似**（不依赖第三方，纯数学）：

```
angle = sin(x*0.011 + t*0.7) + cos(y*0.013 - t*0.5)      -- 两个不同频率的相位和
vx += cos(angle) * strength * dt
vy += sin(angle) * strength * dt
```

效果不如 simplex 噪声，但足够让蒸汽/尘埃"不直线"，且无依赖、可控。

## 5. 深度错觉（2D 系统做出 3D 飘雪）

给每颗粒子一个 `depth`（0=远，1=近），用它同时驱动：尺寸、速度、透明度、摆幅。

```
size    = 1 + depth * 3
speed   = 20 + depth * 50
alpha   = 0.4 + depth * 0.6
swayAmp = 10 + depth * 30
```

再加横向正弦摆动 `x += cos(t*swaySpeed + offset) * swayAmp * dt`。
**远的东西小、慢、淡**——这一条就够让平面雪看起来有前后。

## 6. 配方（数值是相对量，按工程尺度换算）

**彩纸爆发（庆祝/奖励）**
- n=120–150｜速度 200–400（随机方向）+ 向上偏置 −250｜尺寸 6–12 × 3–7（扁片）
- 重力 900｜阻尼每秒 ~20%｜寿命 1–1.5s｜旋转 `vrot` ±6 rad/s
- 视觉技巧：`h = h * |cos(rot)|`——片状翻转时高度压缩，像纸片在翻面
- 颜色：限定 4–5 色（暖橙/奶油/砖红/深棕，跟一锅端调色板一致），别随机 H=0–360

**飘雪 / 冷汽（环境）**
- 常驻 300–400 颗｜depth 驱动尺寸 1–4、速度 20–70、透明度 0.4–1.0
- 横向摆动幅度 10–40，速度 0.5–1.5（各自随机相位）
- 出屏即回收重生（不要销毁重建控件）

**蒸汽 / 烟雾（上升 + 膨胀 + 淡出）**
- 起始尺寸 10–20，**膨胀速度 30–60/s**（越升越大）
- 上升速度 30–60，阻尼每秒 ~2%
- 寿命 1–2s，透明度峰值 0.12–0.2（**很淡**，一浓就变糊）
- 每个粒子给不同 `maxLife`，否则会"齐步走"一眼假

**火花 / 碎屑（命中、开盖）**
- 速度 300–600，寿命 0.3–0.6s，尺寸 2–5
- 重力大、阻尼小；颜色从亮到暗的短渐变
- 数量少而快，比"多而慢"更有冲击

## 7. 颜色与分层（让效果"不土"的关键）

- **先定 5 色以内的调色板**，所有粒子/光束/贴图都用它；调色板外多一个颜色，观众说不出哪不对但就是脏。
- **能量饱和、物质去饱和**：光、火、气用高饱和；碎屑、烟、尘用灰/低饱和。两者搭配才有重量感。
- **渐变负责明暗**：一颗粒子的颜色沿寿命从"亮暖 → 饱和 → 暗"走，尾巴变暗，别在末端还是亮色。
- **别自己发明颜色**：有固定规则（如 `kitchen-art-rules.json`）就用规则里的 ARGB；粒子只是"用这几种颜色"。
- 层序：气体/粒子通常在结构之上、可交互物件之下（按项目已定规则），不要在动效里改层序。

## 8. 预算与池（千星最容易翻车的地方）

**先算，再写**：

```
所需控件 ≈ 同屏粒子数(rate × lifetime) + 常驻装饰
帧内工作量 ∝ 存活粒子数（每帧每颗只做几次算术，不要字符串拼接/日志/查表函数）
```

- 固定池：建满即止，池干时**抢最老的那颗**（`head` 指针环形复用），绝不新建。
- 可增长池：必须声明增长上限与补建节奏（分帧补建，一帧别建几百个），上限写进配置。
- 池的读写在热路径上**不打日志**（R7 日志契约），否则本身就成了性能问题。
- 真机上限、池吞吐公式、两种"效果变少"的病因区分，照 **[vfx-particles-and-budget.md](../../miliastra-code/references/vfx-particles-and-budget.md)** 和 **[case-extreme-particles.md](../../miliastra-code/references/case-extreme-particles.md)** 的实测数据走；不要用本文件的相对量当性能结论。

## 9. 千星铁律（摘自工程，别绕）

- 每帧不新建控件、不重建树；建粒子只在"建粒子"那一个函数里。
- OnUpdate 里 pcall（[R1](../../miliastra-code/references/iron-rules/R1-onupdate-pcall.md)）。
- 退页/切关销毁**本脚本拥有的**控件；别人的控件不动。
- 文件体积按 [R11](../../miliastra-code/references/iron-rules/R11-file-size.md)，粒子配置别写成几千行字面量。
- 需要人来点的只有试玩；运行时数据用日志/截图取证，不靠猜。

## 10. 验收

- 控件数：发射前 / 稳态 / 结束后各数一次；稳态符合 `rate × lifetime` 的估算。
- 泄漏：连开连关 3 次，控件数回到基线。
- 时长：稳态后 30 秒位置不漂移（dt 累计）。
- 性能：记录同屏粒子数与最差帧，真机数字才算数。
- 画面：抓"起势 / 稳态 / 消散"三张，确认颜色在调色板内、没有糊成一片。
