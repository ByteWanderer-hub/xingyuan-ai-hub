# 千星自动交付

主聊天负责从范围确认到交付，用户无需搬运路径、提示词或审查记录。

## 原则与边界

- **质量优先于节省。** 先满足效果、正确性、完成度和必要验证，再节省额度、时间及协调成本。不用明显不足的方案换取省额，也不把更多代理、更贵模型或重复检查当作质量本身。
- 遵守当前工作区 AGENTS；在共享技能仓库按根规则定位 `handoffs/active/` 的已有主题。千星业务阶段先确认目标游戏工程，再按其规则读取 `instructions/qianxing/AGENTS.md`（实际存在或已配置时）及所指技能，不把共享仓库当作游戏工程。只讨论、审查或维护规则时，仅做对应部分，不启动业务恢复。
- 用户明确的分工、模型和权限优先。自主分工不扩大任务、素材处理或发布部署授权；不改全局默认模型，不搭建额外 API 服务，不创建用户侧新聊天、持久 Goal 或定时任务。

## 启动与续做

- 拟定方案、派工或建文档前，按工作区规则定向定位同名交接及同主题已有文档，核对对象、当前状态和未完成项，沿用唯一主题入口。纯技能维护只读相关规范，不读取业务交接或启动业务恢复。
- 新文件或新一轮反馈先与已确认范围比对，只处理新增、变化和仍未解决项。遵守指定工作表/资料边界；截图标注要实际查看并关联到具体对象。表中“已完成”、旧截图和口述状态分别作为来源记录，不能代替当前版本证据。新具体反馈可重新打开此前跳过的问题，但只修已明确部分。
- 复用已确认设计、验收与授权；完成需求所必需的关联脚本可纳入同次备份、构建、验证和审查，并说明原因，不因多一个文件重复申请同一授权。改变玩法、删除既有进度、扩大部署对象等仍需单独依据。

## 缩短交付等待

- 开工用一句话确定本轮变更边界和最小验收集；先完成受影响部分，不把历史全套检查自动加入。当前主题状态、相关源文件与所需技能读一次即可；恢复时核对差异，不从头重读历史。
- 局部画面/参数修订默认直接实现、定向检查和一次必要冒烟；新增关卡优先验证新增数据、特殊机制、入口及相邻切换。只有共享规则、公共渲染/状态机改变、依赖无法界定或定向检查暴露跨域故障时扩大回归。具体复用条件见[验证与审查取证](references/verification.md#按改动选择验证与复用)。
- 独立审查依据实际修改的风险触发。新增关卡、调用已验证的胜败流程或按钮文字变化，本身不等于修改“结算触发”；结算条件、去重、奖励、存档和跨端状态链真正改变时仍执行关键审查。
- 候选冻结后，独立的测试与必要审查可以重叠进行；共享同一模拟器、活编辑器或输出文件的操作必须串行。已有原始证据交审查者复用，不安排多方重复跑同一全套；审查通过仍以所需证据齐全为准。
- 把同一轮局部改动合并后构建；先跑便宜的针对性检查再启动昂贵的端到端回归。失败后只重跑修复所影响的检查；无新增变化、失败或疑点时，通过即进入部署，不追加“保险测试”。
- 优先利用现有测试的关卡/用例筛选、就绪信号与报告能力；确因重复手工操作拖慢时才补小型辅助工具，不为提速先建一套框架。耗时异常时记录最慢阶段及实际用时，下一轮优化该瓶颈，不预先承诺提速百分比。

## 自主分工

主聊天负责调度；工作流固定由 Astra 设计与只读验收、Sol 实施、验证、返修及授权内发布。普通问答不启动此工作流；简单任务可缩短设计与验收内容，但不绕过模型分工。

- 简单修改、频繁视觉反馈或拆分收益不足时，由 Sol 直接实施，Astra 简短明确方向和验收条件；应查看参考与成品，最终视觉由用户验收。
- 有清晰独立边界、专门能力需求或可靠并行收益时委派，简短说明目的。同一源码或物料范围只有一个写入者；并行范围必须互不冲突，已有执行者占用时先交接。
- Astra（`gpt-6-astra`）仅负责方案、验收条件、复杂根因分析和只读验收，不编辑文件、不构建、不部署；Sol（`gpt-6.1-sol`）承担全部实际执行。复杂问题由 Astra 调整设计，再交 Sol 修复。
- Sol 完成必要自检后，由 Astra 按冻结候选与设计条件只读验收；简单任务保持验收简短。实际修改存档恢复、奖励去重、结算触发、跨端同步等关键行为时，由未参与实现的 Astra 定向审查关键逻辑及受影响调用链；已覆盖部分不再叠加审查。
- 每个 Astra 必须由根主会话通过原生子代理工具直接创建，不能由 Sol 派生。显式设置 `model=gpt-6-astra`、`fork_turns=none`，省略 `reasoning_effort`，按当前工具字段定义继承主会话；若能读取主会话当次有效值，也可显式传入原值。不得猜固定档位或传入不存在的 `inherit` 枚举。主会话调档后，旧 Astra 不视为同步；无法证明强度相同就创建新的 Astra，Sol 的强度不反向影响它。
- 只在委派时检查原生子代理工具。显式设置所选 `model`，工具要求时用 `fork_turns=none` 并传入必要上下文；角色文案或请求模型不等于实际模型已核实。短暂容量故障可在原代理/原模型上有限重试，同时推进独立工作；持续不可用或必要独立审查无法完成时，如实说明缺口并集中请用户决定，不静默换模型或用后台 shell 绕过。工具或指定模型缺失时保留恢复点并报告待执行/待验收，不静默替换、不谎报通过；不用 API/CLI 代理启动器绕过。

## 执行与返修

1. **明确范围与设计。** 主聊天调度 Astra 给出方案、范围与可观察的验收条件，再交 Sol 执行；仅在影响方向、范围、权限或外部依赖时集中确认。普通技术问题自行解决。
2. **Sol 实施。** 读取当前真源与基线，按项目规则备份、从唯一入口构建。缺陷修复先取足以支持改动的证据，关键或有歧义的问题优先用旧版同操作复现；不能复现时记录静态证据与不确定性，不凭猜测扩大改动。给执行者提供工作区路径、相关 AGENTS 入口、同一主题文档、明确范围、写入边界、验收及部署权限；禁止扩改相邻任务或自行再派代理。
3. **Sol 验证与冻结。** 缺陷、关键状态或验证争议按需读[验证与审查取证](references/verification.md)，选受影响路径的必要检查。先完成关键复现和核心验证，再返回各候选路径、实算 SHA/bytes、实际差异、备份、证据和未验证项；冻结该范围源码、构建入口和产物，停止相关后台写入。只追加不改变候选的证据可与审查并行，所需证据未齐不能放行。
4. **Astra 只读验收。** 绑定候选指纹、范围与实际差异；预先分析固定基线不等于最终候选审查。审查者只产出审查证据，不改源码、部署或另建主题交接。每项阻塞给位置、触发、证据、影响和通过条件；关注实际状态与受影响调用链，不只看按钮显隐或成功分支。复用可信的同版本证据，有疑点再定向复现；结束复核指纹，结论只覆盖所审版本。
5. **返修。** 阻塞交原执行者，通知原审查者后解冻，修完重新构建、验证并冻结；所有实际返修由 Sol 执行。原审查者复核新候选修复点及受影响部分，未变文件/检查可复用，不因轮次变化全量重跑。无证据支持的额外改动应收窄。同一问题两次实质返修仍失败，最迟交 Astra 只读分析根因或调整设计，再由 Sol 修复；已有 Astra 则换取证方法；不把普通调试抛回用户。
6. **外部阻塞。** 只有需要改变产品方向、范围、权限或无法独立解决的外部条件时才集中请用户决定，并保存具体证据与恢复点，不删验收项或虚称通过。

## 发布、部署与验收

- 每轮先由 Sol 完成候选与必要自检，再必经 Astra 验收；风险决定验收深度，不决定是否验收。设计与验收可由同一未参与实现的 Astra 承担。授权已覆盖发布/部署则继续，不重复索要；未覆盖时提供具体可审阅版本再确认。
- Astra 对最终冻结候选验收通过后，由 Sol 按项目规则完成已授权发布/部署；Sol 完成部署前指纹、归属、备份与门禁；发现活文件并发变化先停止并报告，不覆盖。部署中断先核实结果，不盲重试。部署产生必要新事实时，由 Astra 只读核对 Sol 提供的回执。
- 门禁报错先区分实际缺陷、判据误报与工具不可用。已有失败方法不盲重跑；替代检查或例外须符合工程规则并保留依据，不伪造图源、删检查或把未判定项写成通过。工具参数与替代路径留在工程技能/当前证据中，不固化某次环境故障为通用豁免。
- 分别记录部署后 SHA、编辑器存盘、`.gil` 同步及真机试玩。静态或模拟器证据不替代真机，未做项明确标注；纯物料任务不套用游戏部署流程。

## 状态与交付

- 主聊天统筹同一主题文档内容，任务文件、证据落盘和主题文档实际写入均由 Sol 完成；Astra 只返回文字。由 Sol 按工作区 AGENTS 统一回写同一主题文档，顶部保持更新时间、当前状态与下一步；用已完成/未完成事项区分实现、验证、审查、部署、存盘和用户验收，待办写责任方及通过条件。执行者、审查者提交事实和原始证据，不各建一套任务书/交付/交接。共享技能仓库沿用 `handoffs/active/` 的对应主题；只有目标工程明确采用 `work/交接.md` 时才更新其中的本主题摘要和入口。写前核对并发变化，保留其他任务内容。
- 更新对应事项并压缩过期中间状态，不逐轮堆积重复正文。保留有效决定、最新核实指纹、未完成依赖和必要证据入口；原始回执、审查证据与回滚备份可独立存放，不因精简主题文档而删除。
- 调度只在当前聊天活跃期间运行，不承诺关闭后继续。已授权工作持续到实现、必要验证、返修及授权内的部署完成，不停在首版、候选或“已派工”；工具或额度中断时说明恢复点。恢复先核对代理真实状态和当前文件，不重复派工；技能更新不主动中断或重派在途任务。
- 进度沟通优先说明新发现、决定和剩余风险，不为凑更新重复计数或内部过程。最终简报结果、必要验证和未完成项，按工程规则给出指纹、备份及证据入口；必要复查通过即停止。区分规则已写入、制作/实现完成、自检或审查通过、已部署与用户验收；配置或规则校验不等于流程实跑通过。
