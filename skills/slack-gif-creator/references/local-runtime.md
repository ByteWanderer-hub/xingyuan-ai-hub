# 本地运行与通用 GIF 边界

- 上游提供帧合成、缓动和 Slack 检查，不含角色素材、图生视频模型或自动动作迁移。安装不等于已获得视频生成能力。
- 角色画面优先使用当前 imagegen 图像工具或已有合格素材；不要用几何占位替代用户要求的精细角色。动作可按真实可用能力做逐帧绘制或分层动画。生图、图像编辑仍遵守宿主工具规则。
- 本机隔离环境位于 `D:/tools/gif-runtime/Scripts/python.exe`；其他机器按 requirements.txt 在自己的环境安装，不把这个本机路径当可移植依赖。
- QQ/其他用途尺寸跟随用户参考包，不套用 Slack 的 128/480 像素推荐。Slack 校验通过不等于 QQ 上传验收；上传/发送另用 qq-sticker-pack，需相应用户授权。
- 原 GIFBuilder 将 PIL 输入转为 RGB，不能保持透明。需要透明时使用保留 alpha 的导出流程并实测透明索引与 disposal；需要不透明时明确合成背景后再编码。
- 原去重逻辑不累加被删除帧的时长，会缩短停顿。保留源节奏时不要启用 remove_duplicates；另行去重必须累计 duration。
- 逐个核对源文件与输出文件的主题映射、数量、尺寸、帧数、总时长、循环、实际像素变化及体积。逐帧全解码检查损坏；多帧但只有整体平移/缩放不等于完成挥手、打字等关节动作。
- 查看动作的起、中、末帧与循环接缝；参考外观与自设身份分工明确。先验证代表性样片的角色与动作，再批量；不把样片或静态帧表标为全套成品。
- 不自动读取凭据、启动其他代理或切到付费生成服务。外部服务/新依赖以用户范围为准。
