# L2-V2. ★★ 找 bug 顺序：**先日志 → 无报错直接上散布实验**

> 归属：`miliastra-code` 语义铁律（默认不查）｜从 `iron-rules-visual-debug.md` 拆出（内容未改）

1. **先拿日志**：`miliastra_log op=grep`（`首错` / 实例化 / 子控件数）—— 崩溃在日志里是**带行号的精确事实**，不许猜。
2. **日志无报错、状态探针也全正常** ⇒ **停止读代码推理**，直接做**散布实验**：
   > 把**同一个模板**在画布上 **3×3 九点**（如 `x=200/800/1400` × `y=150/500/850`）各实例化一份，**每帧**重设位置 + 重显，一次试玩。
   - 九点里**有显示、原来那份没有** ⇒ 差在**调用差异或位置**（本次真凶 `sanitize` 就是这样被逼出来的：散布份没走 sanitize，原份走了）；
   - 九点**全显示** ⇒ 模板没问题，问题在"那份"的调用链；
   - 九点**全都不显示** ⇒ 与位置无关 ⇒ 100% 层级/遮挡；
   - 九点**部分显示** ⇒ 量出有效区域 ⇒ 坐标口径（父层级中心 vs 画布中心）问题。
3. 散布实验同时能回答"**是不是画到画布外了**"—— 比任何推理都快。
