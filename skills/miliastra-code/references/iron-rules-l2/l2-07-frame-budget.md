# L2-07 每帧 API 调用量要有**预算**（限频 / 池化 / 共享父节点）

> 归属：`miliastra-code` 语义铁律（默认不查）｜从 `iron-rules-lua.md` 拆出（内容未改）


> ★ **修订（创作者裁决：以实战为准）**：本条原来那句"每帧 70+ 次就拖慢"
> **不是硬阈值，已被实战数据的量级推翻**。
> **修订依据（真机实战）**：夏日祭法师 **74 角色同屏** —— 每帧约 **3200 颗粒子** ×
> 位置/尺寸/颜色 3 次 setter，**真机实战跑通**，观感「**小卡、可接受**」，
> 创作者据此把它定为**软上限**（详见 [`vfx-particles-and-budget.md`](../vfx-particles-and-budget.md) §2）。
> ⇒ **判据顺序改为：先数控件（一颗粒子 = 一个控件），再看真机帧率**；别再拿"每帧多少次"当红线。

- **历史事故（保留为记录，但请按上面的修订读它）**：32 星 + 4 光晕 ≈ 每帧 70+ 次
  `SetAnchoredPosition/imageColor` ⇒ 拖慢 ⇒ 当时把背景更新**限频 ~20fps**。
  ⚠️ 该观测**没有 fps 数字**，与上面的实战锚点**量级差 100 倍以上** ⇒ **它是"当年那次是怎么解决的"，不是阈值**。
  两者口径可能不同的地方（**假设，未验证**）：那次是**同帧改大量不同控件**（可能触发布局重算），
  而粒子是**每帧改同一批、只改位置**（无布局重算）。**没有证据，别把这条假设当结论。**
- **判据（修订后，按顺序）**：
  ① **控件数优先** —— 一颗粒子 / 一个形状 = 一个控件 ⇒ 先按
     [`vfx-particles-and-budget.md`](../vfx-particles-and-budget.md) §2 算"需求 vs 供给"和池子大小；
     真机锚点：`~950 控件 @ 58.8fps` ｜ **`5188 控件 / 3200 粒子` = 小卡可接受（实战）**。
  ② 批量动效**仍然优先省调用**（共享父节点整体动 / 控件池复用 / 限频 `>0.05s 才动`）
     —— 这些**零成本、且不会有坏处**，省钱不等于必须省，但省了不亏。
  ③ 新增每帧调用**要报出"每帧多少次"** —— 当作**体检表**，不当红线。
- **过查方法**：`miliastra_sim op=frames`（帧间像素差 + `changedControls`）看动效是否真的在动；
  统计每帧 setter 条数；**真机帧率只能人点试玩**（模拟器不覆盖）⇒ 用 `miliastra_probe template:"perf"` 取数。
