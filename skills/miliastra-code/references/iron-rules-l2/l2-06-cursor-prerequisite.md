# L2-06 光标事件有**两个**硬前置：祖先容器 `showCursor` + 控件类型得对

> 归属：`miliastra-code` 语义铁律（默认不查）｜从 `iron-rules-lua.md` 拆出；**2026-10-13 扩充**（原来只写了第一个维度）

**两个维度都要满足，缺一个事件就不来 —— 而且两个都【不报错】。**

| 维度 | 是什么 | 在哪 | 出处 |
|---|---|---|---|
| **① `showCursor`** | **总开关**（显示常驻光标） | **祖先容器节点**的字段 | `api-client-ui.md` L918 |
| **② 光标方法** | **谁来收事件** | **只有**「预设按钮」`ClientUIPresetButtonControl` 和「光标检测区域」`ClientUICursorEventAreaControl` 有 `AddCursorEventListener` | 方法表 L791-795 / L811-815（11 种控件总表 L584-596） |

- **真实事故 A**（《双相》结束页按钮）：事件注册成功、点击也发生了，**回调永不触发** —— 引擎沿祖先链找 `container.showCursor`。⇒ 这是**维度 ①**。
- **真实事故 B**（《酬礼簿》2026-10-13）：把拖拽三件套绑在**容器**"少女签名"上 ⇒ 报 `attempt to call a nil value (method 'AddCursorEventListener')`。**容器不是"位置不对"，是"类型上就没有这个方法"**。⇒ 这是**维度 ②**。
- **常见误判**：以为"在容器上开了 `showCursor` 就能收事件" —— **不能**。容器提供总开关，但它自己不是事件接收者。
- **判据**：用 `CursorEvent` 的控件，① 其祖先容器必须 `showCursor = true`（弹窗出现时开、关闭时复位）；② **它自己必须是「预设按钮」或「光标检测区域」** —— 容器 / 图片 / 文本框 / 文本视窗都不行。两者分别用 `pcall` 探一下最稳：`ctrl.AddCursorEventListener ~= nil`。
- **惯用解法（推荐）**：**在要交互的容器里放一个「光标检测区域」控件、调成覆盖整块**；事件绑**那个区域**，而**位置改的仍是外层容器** —— 这样分层结构和你"拖动的是谁"都不变。或者干脆把那个控件本身的类型改成「光标检测区域」。
- **过查方法（三步）**：
  1. `grep AddCursorEventListener` 的位置 → 确认**绑定对象是那两类控件之一**；
  2. 顺着它往上找容器 → 确认 `showCursor` 在显示 / 隐藏时**成对开关**（别只开不复位，会让鼠标指针一直常驻显示）；
  3. **模拟器里同样要满足**，否则用例永远不过。
