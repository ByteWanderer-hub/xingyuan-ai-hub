## R 级：代码铁律（机械可查，逐条带命令）

### R1 `OnUpdate` 必须包 `pcall` → 聚合故障块

- **违反长什么样**：`function OnUpdate(dt) tick(dt) end` —— tick 里任何异常直接抛掉整帧。
- **为什么致命**：引擎只调 `OnUpdate`；一次异常后**整脚本不再更新**，表现是"点了没反应 / 字不消失 / 按钮不出现"，
  而日志里**什么都没**（2026-09-25 连续 4 轮把已知会崩的版本带上真机，都是这个）。
- **正确写法**（骨架已内置）：
```lua
function OnUpdate(dt)
    local ok, err = pcall(tick, dt)
    if not ok then
        fail("OnUpdate 异常: " .. tostring(err))   -- fail(): 同一故障只报一次，块内含 首错/尝试数/交接值
    end
end
```
- **审查动作**：`node scripts/lua-check.mjs style <文件>`（error 级 `ONUPDATE_NO_PCALL`）。

### R2 不许漏 `local`（漏了就写到黑板/全局）

- **违反长什么样**：`rawState = ...`（无 `local`）——能跑，但写进了全局；多脚本同容器时等于**污染别人的黑板**。
- **正确写法**：一律 `local`；**只有登记过的跨脚本字段**才写全局（本域其实用"控件黑板"更好，见 L2-04）。
- **审查动作**：`node scripts/lua-check.mjs scope <文件>`（报 `文件:行号`）。

### R3 函数/变量声明必须早于使用（否则闭包读到 nil）

- **真实事故**（2026-09-25，同一天三次）：`local C_PANEL` 写在 `build()` 里、`local curStage/blinkT` 写在 `animTick()` **之后** ⇒
  另一个函数读的是**全局 nil** ⇒ `pcall → fail → failDone=true` ⇒ 此后每帧 tick 第一行就 `return`，
  **一次冻结焊出三个"看起来无关"的 bug**（翻卡不动 + 提示条不消失 + 结算按钮不出现）。
- **正确写法**：每帧要用的状态变量声明在**最早使用它的函数之前**；要"前面调后面"时用**前置声明 + 赋值**：
```lua
local restartToLevel1          -- ① 先声明槽位
local function loadLevel(i)    -- 闭包捕获的是这个槽位
    restartToLevel1()
end
restartToLevel1 = function()   -- ② 再赋值（用 local function 会新建槽位，闭包抓不到）
end
```
- **审查动作**：`node scripts/lua-check.mjs scope <文件>`（`FORWARD_REF` 会报"在第 N 行声明过"）。

### R4 平台调用都包 `pcall`，且**失败必须有去向**

- **违反长什么样**：`pcall(function() c.raycastTarget = true end)` —— 返回值没人接，失败静默。
- **创作者明令**（2026-09-25）：**严禁任何"掩盖报错的兜底"**；`pcall` 吞掉的异常要 `log` 出来（同一原因最多报 3 次）。
- **正确写法**（两档：要命的 `fail()`，可选的"降级 + 不阻断"日志）：
```lua
local ok, err = pcall(function() c.raycastTarget = true end)
if not ok then
    log("热区 raycastTarget 设置失败（点击会失效）: " .. tostring(err))
end
-- 每帧都可能失败的探针 → 用 nonFatal(what, err)：降级 + 最多报 3 次，防刷屏
```
- **审查动作**：`node scripts/lua-check.mjs style <文件>`（`BARE_PCALL` warn —— 逐处确认"失败可以忽略"）。

### R5 无 BOM / LF / 4 空格 / 禁 tab

- **真实事故**：编辑器新建关卡写的活文件**自带 UTF-8 BOM** ⇒ 原神打印
  `Read text file with BOM header may cause Lua error`。判据：文件前 3 字节应是 `2d 2d 20`（`-- `）。
- **⚠️ 另一个坑**：PowerShell 5.1 的 `Get-Content` 默认按 ANSI 解码，**显示成乱码是错觉**，别据此转码。
- **审查动作**：`node scripts/lua-check.mjs style <文件>`（`BOM`/`CRLF`/`TAB`/`INDENT`；`--fix --write` 修前三种）。

### R6 不用 `assert` 引爆；校验走显式检查 + `fail()`

- **为什么**：`assert` 抛错会中断整帧，而且**信息零散**；`fail()` 能把上下文（首错/尝试数/交接值）一次性打全。
- **正确写法**：`if type(x) ~= "string" then return "参数非法: " .. tostring(x) end` → 调用方 `if err then fail(err) end`。
- **审查动作**：`node scripts/lua-check.mjs style <文件>`（`ASSERT` warn，逐处问"这里真会炸吗"）。

### R7 日志：`[标签] 消息` + `k=v`；**单条 ≤10000 字符**（超出静默截断）

- **真实事故**：一次性打印 `Enum.KeyEventType` 全部成员，**第一片就被截断** ⇒ 反向得出"没有这个键"的错误结论。
  ⇒ **长输出必须分片**；数值写成 `k=v`（`miliastra_log op=metrics` 能直接抽）。
- **审查动作**：`grep -n 'print(' <脚本>` 人工过标签与分片；工具不判这条（`lua-check.mjs` 只看机械规则，日志口径靠人工过）。

### R8 交接值必须来自创作者 / `.gil`，**禁止编造**

- **违反长什么样**：模板索引"看着像"就填、控件模板拿画布上的实例号去用 ⇒ `InstantiateClientUIControl` 恒返回 `nil`，**不报错**。
- **正确做法**：先自动读——`miliastra_sim op=handover source=<活文件>`（从源码抽候选）→
  `miliastra_map op=clientui`（从 `.gil` 读模板）→ 都拿不到**才**问创作者（照 §3 两阶段清单）。
- **审查动作**：`miliastra_map op=clientui --summaryOnly`（插件直读 `.gil` 的客户端控件谱系）。⚠️ 历史文档里的 `miliastra_map op=clientui` / `miliastra_map op=script` **不在本技能包里**（是某个项目工作区的私有脚本），多脚本挂载核对改用 `miliastra_map op=script` 的 `mappings[]` + `miliastra_health op=sha`。
- **★ deploy 前必须 diff 活文件（真踩过，见下）**：`node scripts/diff-live-config.mjs <我的源.lua> <活文件.lua> --handover-only`（退出码 1 = 有交接值只在活文件里，先合回源再 deploy）；活文件路径从 `miliastra_health brief:true` 的 `luaDir` 取。
- **★ deploy 前必须 diff「活文件 vs 本地镜像」（2026-09-29 真踩）**：创作者**会在编辑器里直接把交接值填进活文件**
  （本次他填了 `DIALOG_PREFAB`/`BLACKOUT_PREFAB`，活文件比我的镜像**多 18 字节**）。
  我按本地镜像 `op=deploy` ⇒ **把那两个已填的模板索引覆盖回 `0`** ⇒ 真机会直接 `FAILED`/丢弃黑幕，
  而回执一切正常（`verified:true` / `lint ok`）。**deploy 之前**先定位差异：
  `miliastra_health op=sha mirror=<本地目录>`（三方 SHA）或逐行 diff 活文件；把创作者填过的值**合回镜像**再投。
  判据：`op=deploy` 回执里的 `destBeforeBytes` 与本地源大小不一致 ⇒ 活文件被人改过，先看差异再决定要不要覆盖。

### R9 构建产物不许直接改

- **判据**：存在 `tools/build-*.mjs` + `sources/<玩法>/` ⇒ 那个 `.lua` 是**拼出来的产物**。
- **正确做法**：改 `sources/<玩法>/main/*` 片段 → 跑**项目自带的** `tools/build-main.mjs`（带**字段契约断言**：断则拒绝落盘）。项目里**没有** `tools/build-*.mjs` ⇒ 不是构建产物工程，直接改那个 `.lua` 即可。
- **真实事故**：直接改产物，下次构建**被覆盖**（本轮整改里 `main.lua` 的头部就是改 `01_head.lua` 再重建的）。

### R11 文件与函数规模有度

- **判据**：单文件 >1000 行、单函数长到一眼看不完 ⇒ 拆（本工程用 `sources/<玩法>/main/` 片段 + 构建脚本拆）。
- **审查动作**：`node scripts/lua-check.mjs style <文件>`（`BIG_FILE` warn）。

### R12 文本控件的**矩形高度**必须容得下字号行高（`h ≥ fontSize × 1.4`）

- **真实事故（2026-09-26，两次真机白跑）**：设置菜单顶部的「第 X 关 · 关卡名」在真机上**整条空白**——
  `52` 号放进 **64** 高、`64` 号放进 **80** 高，两个版本都不显示；同面板里 28 号的按钮文字一直正常，
  把 `52` 号放进 **90** 高（另一处大标题）也一直正常。
- **机制**：`ClientUITextBoxControl` 的 `sizeDeltaY` 容不下字号行高（CJK 字体 ≈ **1.4 × fontSize**）时，
  该控件**一个像素都不画** —— 不裁切、不缩小、不报错，`visible` 仍为 `true`、`text` 也确实设上了。
- **为什么日志/模拟器都抓不到**：`.gia` 里那行"文字设上了"照样打印；`miliastra_sim` **不模拟这个截断**
  （同一份代码它画得出来）⇒ 只有**真机截图 + 量像素**能看出来。
- **判据（量像素）**：底图区域均值精确等于底图 token；文字区若与底图**一模一样**（零像素差、无深色描边团）
  ⇒ 是"什么都没画"；若是**另一块颜色** ⇒ 才是"被压住"。
- **规矩**：定字号时同时按 `fontSize × 1.4 + 余量` 给高度（64 号 ≥ 96，常用 120）；矩形加高**不会挪动字形**
  （文字垂直居中）⇒ 零视觉代价。
- **审查动作**：`miliastra_code op=lint-ui`（平台级 UI 门禁，第 ④ 条就是这条规则；它能自动配对 `add(... "txt", x,y,w,h)` 与
  `setFont` / `.c.fontSize`，`makeBtn` 的文字按 28 号算）。

### R13 部署前必须先在模拟器里跑一遍（`bind` → 看 `run.logs`）

- **判据**：只要动了 `view` / `board` / `hud` / `input` 任一脚本，`miliastra_code op=deploy` **之前**先
  `miliastra_sim op=bind` 跑一遍，`run.logs` 里**不许**出现 `attempt to call` / `nil value` / `首错=`。
- **为什么**：真机一轮试玩很贵（停试玩 → 部署 → **编辑器存盘** → 重开一局），模拟器 30 秒就能拦住
  "**整块界面消失**"这类崩溃；`last:true` 还能复用上次配方，成本只有一条命令。
- **审查动作**：`miliastra_sim op=bind`（`scripts:[{path, sourceFrom}]` + `templates:[{guid, kind}]`）→ 看
  `run.logs`（脚本自己 print 的字）与 `run.controlCount`（控件数有没有合理增长）。
- **真实证据（2026-09-29）**：给「客户端容器节点.lua」写提示条时，`bind` 一次就确认了 `script.object` 可用、
  宿主解析为 `容器节点`、无 nil 调用；随后 3 条 `op=verify` 用例把「建 / 顶掉最旧 / 到点消失 / 上移补位」全钉住。
- **别误读**：模拟器**不覆盖**官方素材渲染、联机与手感；`controlCount` 没涨也 ≠ 代码没跑
  （合成模板没有子控件、空容器不渲染 ⇒ 控件建出来了但画面是空的，那是模拟器的边界，不是脚本的错）。

### R14 被比较的状态字面量**必须有赋值点**（死条件 = 静默永不执行）

- **真实事故（2026-09-29，真机暴露）**：提示条 v1 用 `if t.appeared and t.phase == "hold" then` 当倒计时门，
  而 `t.phase` 全文件**只被赋过 `"in"` 与 `"out"`，`"hold"` 一次都没出现** ⇒ 倒计时一秒都没走过。
  现象极具迷惑性：**出现、上移全部正常，就是 3 秒后不消失**（补间由引擎推，与那条门无关）。
- **机制**：Lua 里字符串比较永假**不报错**；只要该分支没有日志/断言，整条链就是死的 —— 静态检查、
  作用域检查、模拟器都不会替你发现（除非断言恰好覆盖那条路径）。
- **判据**：任何 `x == "字面量"` 的**状态门**，都要能点名这个字面量的**赋值处**；0 处赋值 = 死条件。
- **审查动作**：`grep -n 'phase *==\|state *==' <脚本>`，再对每个字面量数一遍赋值点（如 `grep -c '"hold"'`）。
- **更稳的写法**：生命周期与计时**别挂补间回调**（`Tween:SetOnComplete` 真机是否必触发未验证），
  用自己 `OnUpdate(dt)` 的时间源推进（记得 `script:EnableUpdate(true)`，否则 OnUpdate 根本不跑）；补间只管"动"。

### R15 控件对象**不能当表键**（每次取回来都是新包装 ⇒ 查表永远落空、且不报错）

- **真实事故（2026-09-29，模拟器 + 探针抓出）**：黑幕对话把「排除名单」与「原色表」两份数据写成
  `skip[控件] = true` / `trueColors[控件] = 原色`，随后用 `skip[node]`、`trueColors[control]` 查 ——
  **两条都查不中**，于是「排除入场淡入」「用真原色当目标」两个修复**整条静默失效**（日志里一个字都没有）。
- **机制**：同一个控件每次从 Lua 拿回来都是**新的绑定对象**（模拟器实现 `runtime.js::pushControl` 每次
  `lua_newuserdata` + `attachHost`；真机绑定同理不能假设会复用包装）。Lua 表以**身份**作键 ⇒ 两次拿到的
  包装不同 ⇒ `t[控件]` 恒为 nil，**查不中不报错**（不像 `nil` 调用会炸）。顺带：`a == b` 两个"同一个控件"
  的包装也可能为假 —— 别拿控件对象做相等判断。
- **判据**：凡是 `t[某控件]` 形式的查表、或 `控件A == 控件B` 的比较，都要能说出**为什么身份稳定**；说不出就换键。
- **正解**：用**控件名**（`GetChild(名字)` 本来就是这个假设，字符串键身份稳定）或运行时 `id` 当键；
  ⚠️ 字段名有差异（官方文档写 `id`，模拟器暴露 `Id`）⇒ **优先用名字**，两端都稳。
- **审查动作**：`grep -n 'GetChild\|GetChildren\|InstantiateClientUIControl' <脚本>`，逐个看返回值有没有被拿去当表键；
  再 `grep -n '\[\(node\|control\|box\|item\)\]' <脚本>` 反查可疑索引入口。

### R16 同一批字段**只能有一个所有者**；"先写透明 → 补间回原色"的目标色必须在**第一次写透明之前**捕获

- **真实事故（2026-09-29，真机反馈「渐入变成了淡出」）**：入场淡入在 `createBox` 里把可达后代的颜色**写成 a=0**
  （渐入的起点），同一帧紧接着 `showLine()` 又**再读一次"当前颜色"当原色** —— 读到的正是刚写进去的 a=0
  ⇒ 「整行渐入」的**目标色成了全透明** ⇒ 补间方向变成 `255 → 0` = 视觉上就是**渐出**，且整行随后永久不可见。
- **判据（两条都要满足）**：
  ① **目标值只源于"任何写透明之前"的一次捕获**（建容器/建控件时抓一次存起来），**绝不**"事后读当前值"；
  ② 同一批字段**不能有两个补间同时跑** —— 谁拥有这批字段，另一个动画（如容器级入场淡入）必须**显式跳过它**
     （跳过名单同样按 R15 用**名字**存）。
- **可判定日志**：写一条 `… 目标α最大=N`（N 应为 255）；真机/预测试里看到 `N=0` 就是又踩了本题。
  等价的自检：**起手停顿期间 α 必须恒为 0**，渐入完成后恒为 255，中间**不允许出现"先亮后灭"**。
- **审查动作**：`grep -n 'ToRGBA\|FromRGBA' <脚本>` 找出所有"读当前色推算透明/原色"的点，确认它们读的是
  **提前捕获的副本**而不是现场值。
- **手边可复用的验证手段（比肉眼看画面强）**：插件自带 Lua 运行时（`fengari`）可在 Node 里直接跑**真实脚本源**——
  `createRuntime()` → `registerTemplate(guid,{kind,children})` 造夹具 → `mountScript` → `sendClientSignal`
  → 循环 `rt.step(0.05)` 读数。本次就是这么把「先亮后灭」钉成数字的（`work/dialog/verify/黑幕渐入_探针.mjs`）。

## L2 级：语义铁律（**默认不查**，用户明说才逐条过）

> 这 8 条的共同点：**每处代码单看都没错**，违规只发生在"跨脚本 / 跨局 / 依赖上下文"的层面，**扫描扫不出来**。
> 写码时照常遵守；专项查询只在"深度审查 / 二级铁律 / 接手摸底 / 重构前过查"时执行。

### L2-01 跨脚本层级：**默认靠"同脚本建"**，要跨脚本压盖就靠"按需创建"
- **真实事故**：`view.lua` 里"隐藏所有非自己建的控件"的清理逻辑，把 `input.lua` 的点击热区与 `fx.lua` 的闪效层**一起隐藏** ⇒ 点击全废。
- **判据**：**创建顺序 = 绘制层级（后建的在上）**；跨脚本**默认**保证不了顺序 ⇒ 互相压盖的元素同脚本建；
  清理遗留控件必须**白名单**（按名字放行黑板/热区）。
- **★ 2026-09-26 补充：跨脚本层级不是"不可控"，而是"必须按创建顺序去控"** —— 状态机在 A 脚本、
  要盖住的棋盘在 B 脚本时，把覆盖层做成**按需创建**：
  ① **第一次要显示时才** `InstantiateClientUIControl`（创建时刻晚于别人 ⇒ 天然在上）；
  ② 创建**再延后一帧**（同一帧里两个脚本的首个 `OnUpdate` 谁先谁后不可靠；实测日志 `[view] 界面已建` → `[board] 调查板已建`）；
  ③ 每次模式切换 **+ 每 ~0.4 秒**再 `SetAsLastSibling()` 补一次（"创建顺序"与"兄弟序号"两条规则都兜住）；
  ④ ⚠️ **`SetSiblingIndex(index)` 越界不抛错、只返回 `false`**（合法范围 `0..父控件子数-1`）——
  传 `9999` 属**静默无效**：日志一个字都没有、画面也没变；判据必须用**返回值**（`ret ~= false`），
  **不能只 `pcall` 看有没有抛异常**。正解优先 `SetAsLastSibling()`。
  完整三层踩坑与修法见 [`case-detectives-6scripts.md`](case-detectives-6scripts.md) §8。
  ⑤ ⚠️ **提层/补序必须按"创建顺序"遍历**：`add()` 时顺手记一份 `order[#order+1] = name`，提层时用 `for i = 1, #order`。
     **绝不能用 `pairs(items)`** —— 那是**哈希序**，而 `SetAsLastSibling()` 会真的改变兄弟序号 ⇒
     层序被打乱（真机表现：四个按钮只有**一个**有字、标题整个不见 —— 文字被自己的内芯压住 / 底板块翻到按钮之上）。
     2026-09-26 真机截图抓到的实例；**模拟器看不出来**（它不判层序，是已知盲区）⇒ 这类改动一定要真机看一眼。
- **过查方法**：grep 每个脚本里"隐藏/删除控件"的代码，确认它**只动自己建的**（有白名单或 `owned` 表）；
  再 grep 覆盖层创建点，确认它**不在 `build()` 里**（在 build 里建 ⇒ 一定被后建的脚本压住）；
  最后 grep 提层循环，确认它**没在用 `pairs`**。

### L2-06 光标事件有**两个**硬前置：祖先容器 `showCursor = true` + 绑定对象的**控件类型**得对

> ★ **2026-10-13 扩充**：原来只写了第一个维度。**两个维度缺一个事件都不来，而且都不报错**。

- **真实事故 A**（2026-09-25《双相》结束页按钮）：事件注册成功、点击也发生了，**回调永不触发**——因为引擎沿祖先链找 `container.showCursor`。
- **真实事故 B**（2026-10-13《酬礼簿》）：拖拽三件套绑在**容器**"少女签名"上 ⇒ `attempt to call a nil value (method 'AddCursorEventListener')`。**不是"位置不对"，是"类型上没有这个方法"** —— `api-client-ui.md` L584-596 列了 11 种控件，**只有**「预设按钮」和「光标检测区域」有光标方法（L791-795 / L811-815）。
- **判据**：用 `CursorEvent` 的控件，① 其祖先容器必须 `showCursor = true`（弹窗出现时开、关闭时复位）；② **它自己必须是「预设按钮」或「光标检测区域」**（容器 / 图片 / 文本框都不行）。**容器上开 `showCursor` 换不来光标方法** —— 那是两个维度（总开关 vs 谁来收）。模拟器里同样要满足，否则用例永远不过。
- **惯用解法**：**在要交互的容器里放一个「光标检测区域」覆盖整块**，事件绑它、**位置改外层容器**（分层与"拖动的是谁"都不变）。
- **过查方法**：grep `AddCursorEventListener` 的位置 → ① 确认绑定对象是那两类控件之一；② 顺它往上找容器、确认 `showCursor` 在显示/隐藏时成对开关。

### L2-07 每帧 API 调用量要有**预算**（限频 / 池化 / 共享父节点）

> ★ **2026-09-30 修订（创作者裁决：以实战为准）**：本条原来那句"每帧 70+ 次就拖慢"
> **不是硬阈值，已被实战数据的量级推翻**。
> **修订依据（真机实战）**：夏日祭法师 **74 角色同屏** —— 每帧约 **3200 颗粒子** ×
> 位置/尺寸/颜色 3 次 setter，**真机实战跑通**，观感「**小卡、可接受**」，
> 创作者据此把它定为**软上限**（详见 [`vfx-particles-and-budget.md`](vfx-particles-and-budget.md) §2）。
> ⇒ **判据顺序改为：先数控件（一颗粒子 = 一个控件），再看真机帧率**；别再拿"每帧多少次"当红线。

- **历史事故（保留为记录，但请按上面的修订读它）**：32 星 + 4 光晕 ≈ 每帧 70+ 次
  `SetAnchoredPosition/imageColor` ⇒ 拖慢 ⇒ 当时把背景更新**限频 ~20fps**。
  ⚠️ 该观测**没有 fps 数字**，与上面的实战锚点**量级差 100 倍以上** ⇒ **它是"当年那次是怎么解决的"，不是阈值**。
  两者口径可能不同的地方（**假设，未验证**）：那次是**同帧改大量不同控件**（可能触发布局重算），
  而粒子是**每帧改同一批、只改位置**（无布局重算）。**没有证据，别把这条假设当结论。**
- **判据（修订后，按顺序）**：
  ① **控件数优先** —— 一颗粒子 / 一个形状 = 一个控件 ⇒ 先按
     [`vfx-particles-and-budget.md`](vfx-particles-and-budget.md) §2 算"需求 vs 供给"和池子大小；
     真机锚点：`~950 控件 @ 58.8fps` ｜ **`5188 控件 / 3200 粒子` = 小卡可接受（实战）**。
  ② 批量动效**仍然优先省调用**（共享父节点整体动 / 控件池复用 / 限频 `>0.05s 才动`）
     —— 这些**零成本、且不会有坏处**，省钱不等于必须省，但省了不亏。
  ③ 新增每帧调用**要报出"每帧多少次"** —— 当作**体检表**，不当红线。
- **过查方法**：`miliastra_sim op=frames`（帧间像素差 + `changedControls`）看动效是否真的在动；
  统计每帧 setter 条数；**真机帧率只能人点试玩**（模拟器不覆盖）⇒ 用 `miliastra_probe template:"perf"` 取数。
