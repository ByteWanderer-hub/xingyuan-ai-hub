# R13 部署前必须先在模拟器里跑一遍

> 归属：`miliastra-code` 机械可查铁律｜立册（此前判定只写在 SKILL.md 铁律区，从未入册）

## 判据（什么算违反）

- 本次改动触及 `view` / `board` / `hud` / `input` **任一脚本**，却在 `deploy` 之前没跑过模拟器 → **违反**。
- 跑过但 `run.logs` 里出现 `attempt to call` / `nil value` / `首错=` 仍照投 → **违反**（等于把崩溃留给真人试玩）。

## 为什么单列

真机一轮试玩很贵：要创作者在编辑器点、要等加载、要人肉观察。而模拟器 30 秒就能拦住"**整块界面消失**"这一类**必然崩**的改动——省下的是别人的时间。

## 正确写法 / 审查动作

- `miliastra_sim op=bind`（`last:true` 复用上次配方）→ 看 `run.logs`（不许有上述错误串）**+** `run.controlCount`（控件数要合理增长，不是 0 也不是暴涨）。
- **有错就修完再 deploy，不许跳。**

## 边界（模拟器不覆盖什么）

官方素材渲染 / 联机 / 手感 / 真实性能 —— 这几类**只能真机**，如实标 `pending`；见 SKILL.md §2「证据双轴」与「验证强度按改动性质定」表。
