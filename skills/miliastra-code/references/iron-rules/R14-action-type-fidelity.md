# R14 严禁歪曲作者意思：说删除就真删、说替换就真换

> 归属：`miliastra-code` 机械可查铁律｜**创作者明令（原话见下）**｜此前判定只写在 SKILL.md 铁律区，从未入册

## 创作者原话（逐字）

> 「**删除就一定要删除　替换就一定要换　不是隐藏不是注释就是直接删除原来的**」

## 判据（什么算违反）

- 说"删除" ⇒ **必须把创建它的代码真的删掉**。
  - ⛔ `SetVisible(false)` 藏起来　⛔ 整段注释掉　⛔ "留着以防万一"
- 说"替换" ⇒ **旧的必须真的消失**（旧控件不再 `add()`／旧分支不再执行），**而且位置、文案、热区由新控件原样接管**。
  - ⛔ "叠一层" / "新旧并存"

## 正确写法

- 把作者原话**逐字抄进任务**，照原话的动作类型执行（删 / 换 / 加 / 改），不做"等价替换"式发挥。
- 完工**逐条回执**：`原话 → 我实际做了什么`，让动作类型可以被一眼核对。

## 附加纪律

- ⛔ **不许用"留在注释里"糊弄门禁字面量** —— 那是骗正则，不是解决问题。正解是**改门禁本身**（工具是我们自己的，改判据比骗检查对）。
- 反例集：藏起来 ≠ 删除 · 叠一层/新旧并存 ≠ 替换 · 注释掉 ≠ 删除 ⇒ 一律打回。

## 门禁打回时怎么办（⚠️ 本条最容易被"门禁"带偏）

- **门禁是证据，不是否决权**。红了只有两个正确动作：**① 修到过**（必要时改的是**门禁判据**——工具是我们自己的）**② 如实标 `pending` 后交付**，让人在真机判。
- ⛔ **三个不许**（都属于"歪曲作者意思"）：
  1. **回退 / 还原成旧实现** —— 门红 ≠ "这改动不该做"；
  2. **删掉 / 藏起作者要的功能**（`SetVisible(false)`、整段注释掉也算）；
  3. **拿空壳 / 占位 / 假数据顶** —— 最典型：门禁说某项"没测 / 判不了"（`ok:null`），就一直交空壳（作者要"3 个状态的按钮模板"，交出来是空按钮）。
- ⛔ **`ok:null` / "没测" / "判不了" ≠ 失败**：那只是"本轮没证据"。**要求照做、证据如实标** —— 别把"没证据"做成"不实现"。
- 门禁确实挡住作者明确要求的实现 ⇒ **保留实现**，把门禁结论当**报告项**列出（红了什么 / 哪一行 / 为什么 / 我怎么修），**绝不改需求、绝不退回旧版**。
- **症状自检**：发现自己在"门一红就撤销改动"或"门说没测就一直交空壳" ⇒ **停**，回到上面。
