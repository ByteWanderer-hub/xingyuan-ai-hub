# 基础案例：《侦探杀》6 客户端脚本工程（真机跑通）

> 来源：关卡 `1073741835`（侦探_多组件），真机多轮验证。
> 价值：这是本域**第一个"多脚本 + 黑板 IPC + 动态 UI + 构建期防错"的完整可运行样本**。
> 规模：**6 个客户端脚本 + 2 块黑板 + 3 个客户端控件模板**，真机跑通"翻格调查 → 逮捕 → 胜负结算 → 切关"。
> 用法：新工程照抄"分工表 + 黑板契约 + 构建流程"三节，**直接跳过坑一节里那 6 个真机事故**。

> 两者**合并**进 `案子/侦探1/2.代码/`，**`code/` 与 `sources/` 都已不存在** ⇒

## 1. 脚本分工（一个 .lua = 一个独立客户端脚本，**互相不能 require**）

| 脚本 | 职责 | 层级（见 `miliastra-ui` §1.4b） |
|---|---|---|
| `主控 main.lua` | **唯一写黑板的人**：规则、状态机（reveal/arrest/result）、板子与状态串 | 无 UI（只写文字控件） |
| `调查板 board.lua` | 16 格网格 + 角图素材 + **结果面板 + 按钮** | 2+3+4+5（底层美术→文字→面板→按钮） |
| `表现 view.lua` | 程序化背景 + HUD + 左右两栏对话框（+ 兜底按钮） | 1+3 |
| `交互 input.lua` | 全屏热区 → 坐标命中 → 发命令 | 只建透明热区 + 自己的反馈 |
| `翻牌 reveal.lua` | 翻面金环高亮 | 7（动效） |
| `效果引擎 fx.lua` | 全屏闪效（成功/失败/胜利…） | 7（动效） |

**分工原则**：① 只有一个脚本写黑板（避免多写者竞争）；② 会互压的元素放同一个脚本（跨脚本层级不可控）；③ 只读脚本出问题不影响主流程。

## 2. 黑板 IPC 契约（本域唯一的"跨脚本通信"手段）

两块**文本框控件**当黑板（名字固定，脚本按名查）：

| 黑板 | 谁写 | 谁读 | 内容 |
|---|---|---|---|
| `t1_kb_state` | **只有主控** | 其余全部 | `stage=…;lv=…;time=…;cells=1:F\|2:H\|…;names=…;msg=…;fx=N` |
| `t1_kb_cmd` | **只有 input** | 只有主控 | `seq=N;evt=flip;target=4` |

### 2.1 三条硬规则

1. **字段名两边必须一致** —— 一边加字段、另一边没跟上 → 表现为"某个格子/某段文字永远不更新"。
   ⇒ **用构建期断言兜住**（见 §4）：主控写出的字段必须 ⊇ 其他脚本读的 `t.xxx`。
2. **`fx` 是"状态变了"的信号** —— 其余脚本可在 `fx` 变化时重渲染。
 ⚠️ **但只比 `fx` 会在跨局时漏画**（真机事故）：新一局的 `fx` 从 0 重新数，
   **很容易和上一局的最后一个 fx 撞上** ⇒ 判定"没变化" ⇒ HUD/提示条/格子**整屏停在上局的画面**，
   创作者看到的是"**黑条一直挂着、时间是上一局的**"✗。
   ⇒ **正解：按"状态串是否变化"重画**（`if rawState ~= lastRaw then render(...) end`）—— 任何变化都重画，跨局也不会漏；
   心跳每秒写一次状态正好充当"至少每秒重画一次"的兜底。
   ⇒ **任何"想让它重画"的动作都必须顶 `fx`**；反之**诊断/心跳之类不该引发重画的东西，绝不能顶 fx**（踩坑记录 §3.6）。
3. **命令用递增序号去重**，但**只挡"相等"**：`if seq == lastSeq then return end`。

### 2.2 状态串的格式纪律

- 字段用 `;`、列表项用 `|`、键值用 `:` —— **不要用 `\n`/`\t`**（平台会转义，读回来就烂）。
- 含换行的展示文本（详情/宣告）在写黑板前 `string.gsub(text, "[\r\n]+", "\\n")`，读侧再还原。
- 中文可以走黑板（不像某些平台的 RPC 会坏），但**判据仍建议用 ASCII**（`F/H/P/A/D` 这类单字母状态码）✓ 本案例就是这么做的。

## 3. 六个真机事故（**照抄这一节的结论，别再踩**）

### 3.1 `deploy ≠ 进游戏`（最贵的一个，白跑 3 轮）

- **现象**：改了脚本、部署、试玩 —— 行为完全没变。
- **真因**：`miliastra_code op=deploy` 只写**本地活文件**；游戏跑的是**地图存盘时嵌进 `.gil` 的快照**。
- **纪律（固定三步）**：`deploy → 在编辑器里存一次盘 → 试玩`；
  试玩前用 **`miliastra_map op=script`** 确认 `embedded.sha256 == live.sha256`（回执 `match:true`）——**不 match 就不要让人试玩**。

### 3.2 `OnStart` 不是每局都跑

- **现象**：第 2 局开局就显示上一局的"时间 4/12、结算中"。
- **真因**：脚本 chunk 在两次试玩之间**不重载** ⇒ `OnStart` 只跑一次，`G` 跨局残留。
- **修法**：把"清局"抽成 `freshStart()`；除了 `OnStart` 调它，**tick 里再加一道"新一局"检测**（见 3.3）。

### 3.3 `seq` 跨局错位 ⇒ **一局只有第一条命令生效**（"点哪里都点不动"）

- **现象**：一局里只有第一格能翻，之后点击全无反应；时间却跨局累加。
- **真因**：`input` 的 `seq` 每局从 1 重来，而主控的 `lastSeq` 跨局留着 ⇒ 命令序号**回退**后，全部被当成"旧命令"丢掉。
- **修法（两处，缺一不可）**：
```lua
-- 主控：序号回退 = 对方是新的一局 → 重新同步 + 清局
local fresh = false
if seq == lastSeq then return false end
if seq < lastSeq then fresh = true; lastSeq = 0 end
lastSeq = seq
...
return fresh
-- tick 里：
if readCmd() then freshStart() return end
```
```lua
-- input：开局主动打招呼（让主控第一帧就知道"新一局开始了"）
function OnStart() seq = 0; send("hello", 0) end
```

### 3.4 状态写入是 `fx` 驱动 ⇒ **通了关却不弹结算**

- **现象**：界面显示"案件已解决"，但**结算面板不出现**。
- **真因**：`checkWin()` 设 `done/win` 的动作发生在 `bumpOnly()`（顶 fx）**之后** ⇒ 这一版状态**没被写出去**。
- **修法**：设完终局状态**自己顶一格 fx**（或把 `checkWin()` 挪到 `bumpOnly()` 之前）。

### 3.5 `dt` 可能是 nil、`items` 表要存全字段 ⇒ 脚本**静默冻结**

- **日志原文**（两次，都精确到行号；⚠️ 行号是**当时那一版**的，规范整改后行号已变——原文保留，便于对号旧日志）：
```
[board] 首错=调查板 board:275: attempt to perform arithmetic on a nil value (local 'dt')
[board] 首错=调查板 board:280: attempt to perform arithmetic on a nil value (field 'w')
```
- **真因**：① `local function tick()` 没接 `dt`，里面却 `animTick(dt)`；② `add()` 存 `{c,kind,col}` 没存 `w/h`，动效里又用 `a.w`。
- **后果**：`pcall` 捕获 → `failDone=true` → **该脚本整局不再更新**（表现就是"格子不刷新 / 按钮不出现"）。
- **纪律**：**动效代码里每个字段都当"可能是 nil"**：`dt or 0`；`add()` 一律存全 `{c,kind,col,x,y,w,h}`。

### 3.5c **用了没定义的常量 / OnStart 里控件还没就绪**（第四、五次，一次一个）


- **`attempt to index a nil value (global 'C_GOLD')`**：动效里用了一个**本文件没定义**的颜色常量 ⇒ Lua 里未定义就是 **全局 nil** ⇒ 建控件时直接报错、**整个 build 崩**（表现：棋盘一格都没出来）。
  ⇒ 纪律：每个脚本的常量**集中定义在文件头**；新增颜色/尺寸常量时**先定义再用**。
 ⇒ 自检：**用 `node tools/check-lua-scope.mjs`**（补的，见 §3.5d）—— 它按 Lua 真实绑定规则扫
  「读了但没绑定到 local、也不是已知全局」的名字。**不必再靠 rg 人工对眼。**
- **`attempt to index a nil value (upvalue 'boardCmd')`（在 `OnStart` 里）**：想"开局发一条握手命令"，但 `OnStart` 时黑板控件**还没拿到**（`ROOT:GetChild` 还是 nil）⇒ 整个 input 脚本在 OnStart 就死了 ⇒ **点击全废**。
  ⇒ 纪律：**任何"开机就要发东西"的逻辑，一律延后到 tick 里等依赖就绪再发**（用一个 pending 标志），并且 `send()` 里**对 nil 直接丢弃而不是崩**。
### 3.5b **`local` 声明位置**（第三次同类事故，最隐蔽的一个）

- **现象**：某个动效卡住不消失（例：阶段提示条一直挂在屏幕上 ✗），而且**该脚本的所有动效一起停**。
- **真因**：把 `local tipT = -1` 声明放在了**使用它的函数之后**（`animTick` 在前面、声明在渲染段后面）⇒
  函数里那个 `tipT` 是**全局变量（nil）**，`if tipT >= 0 then` 直接报错 → `pcall` 捕获 → `failDone` → **整脚本冻结**。
- **纪律**：**凡是"每帧要用的状态变量"，声明必须放在最早使用它的函数之前**（本工程全部集中在文件上部）；
  改顺序时**别把声明留在调用点之后**。
- 同源三连（都表现成"脚本静默冻结"）：`dt` 未兜底 / 控件表缺字段 / **`local` 声明晚于使用**。▶ 一条通用解法：
  **`OnUpdate` 一定包 `pcall` 并把首错写进黑板**（见 §5），这样"冻结"永远会留下可读的证据，而不是静默不动。

### 3.5d **一次冻结 = 三个"看起来无关"的 bug**（当天第六次同类；这次终于做成了检查器）

- **创作者的原话**是三个 bug：「① 翻面按钮点第二次没翻页效果 ② 中间文字一直存在 ③ 结算了『下一关』按钮不出现」。
- **日志只有一行**（`.gia`，一局结束后落盘；行号为整改前版本）：
```
[侦探1/board] 首错=调查板 board:299: attempt to index a nil value (global 'C_PANEL')
```
- **根因**：`local C_PANEL` 写在 `build()` 里，而 `animTick()`（另一个函数）用它做提示条淡出 ⇒ 读的是**全局 nil** ⇒
  第一次"阶段变化"（翻面→抓捕，正是提示条要弹的那一刻）就报错 ⇒ `pcall → fail() → failDone=true` ⇒
  **此后每帧 `tick` 第一行 `if failDone then return end` 直接返回，整块板子冻结**：
  翻卡动画（在 animTick 里）不动 = ①；提示条不淡出 = ②；`render()` 再也不跑、`show("btnNext", isRes)` 永不执行 = ③。
- **同一次扫描还挖出一个"连报错都没有"的同源 bug**：`local curStage, curCells, blinkT, blinkOn` 声明在 `animTick` **之后**
  ⇒ animTick 里读的是全局：`curStage` 恰被 render 的**全局写**填上所以判断能过，但 `blinkT` 是 nil ⇒
  「抓捕呼吸高亮」整段**静默死代码**（真机表现：编辑里看不出任何异常，功能就是不生效）。
- **纪律（三条）**：
  1. **每帧用的状态变量、颜色常量，一律声明在文件上部 / 最早的调用点之前**（§3.5b 的同一条，这次是它的加强版）。
  2. **部署前跑 `node tools/check-lua-scope.mjs`**（工作区新增，纯 Node，复用插件的注释/字符串剥离器）：
     按 Lua 的真实绑定规则模拟词法作用域（含"声明晚于读 = 全局"），报 `文件:行号 + 这个名字在第 N 行声明过`，
     `--selftest` 自带 4 个正反例（**它自己就先抓出了 2 个假阳性**：函数名被当成读、`{ alpha = 1 }` 的表键被当成全局写）。
     实测在本工程一次命中 13 条（board 11 / view 3），修完全绿。
  3. **`pcall` 只用来"报错"，不要用来"吞错"**：`fail()` 只报一次是有意的（防刷屏），但**它意味着那次崩溃之后整个脚本就停摆了** ——
     所以"冻结"必须当成 P0，不能当"某个动效不灵"去猜。▶ 通用取证顺序：`miliastra_log op=runs` 找 `首错=` → 修 → 再跑。
- **配套的"别把 bug 带到真机"流程（本次补上，此前一直靠人肉试玩）**：
  `miliastra_sim`（内置模拟器，不吃真机、不用人点试玩）→ `op=bind`（6 个脚本 + 3 个模板 + containerId）
  → `op=patch` 补两个黑板文本框 `t1_kb_state` / `t1_kb_cmd` → `op=verify`（steps 打点击 + expect 断言）
  → **回执里的 `snapshot.logs` 就是证据**：本次直接跑通「翻 4 格 → 结束翻面 → 逮捕 → 胜利」整局，零首错。
  ⚠️ 模拟器拦不住官方素材渲染/联机/手感（角图模板没搬进去时会打印"实例化失败"，那是**预期**，不是 bug）；
  它拦的是"脚本跑没跑、控件建没建、逻辑崩没崩" —— 这正好覆盖上面这一整类事故。
- **给创作者的验收清单**用 `op=cases action=add` 存成回归用例（自动项 + `manual:true` 人工项），本次存了「侦探杀-回归」三条。



### 3.6 心跳诊断：**能用，但绝不能顶 fx**；屏幕上的诊断行已废弃

- **心跳写法**：每秒 `G.beat = G.beat + 1` 然后**直接 `writeState()`** ——
  ⚠️ **不要 `bumpOnly()`**：顶 fx 会让 `fx.lua` 把上一个闪效**每秒重放一次**，创作者看到的是"**抓到嫌疑犯一直黄光 / 翻牌闪两下**"。
- ⚠️ **，屏幕上那行「状态> 时间…翻面…心跳…fx」诊断行已删除**：它原本是"日志还不通"时的唯一取证手段；
  现在 `.gia` 稳定落盘、且有 `miliastra_sim`，**往玩家画面里塞诊断行属于"掩盖报错的兜底显示"**（创作者明令禁止）。
  ⇒ 诊断走 `print`（`miliastra_log op=runs`）与模拟器的 `op=verify` → `snapshot.logs`；画面只放该给玩家看的东西。

## 4. 工程化：构建期防错（本案例最值得抄的部分）

主控单文件会长到 **~37.6KB**（整改后：38536 字节 / 815 行），改一处容易看错行；而本域**一个 .lua 就是一个独立脚本、不能 require** ⇒ 只能**构建期拼接**：

```
sources/<玩法>/main/
  01_head.lua      头部 + 日志/兜错
  02_roles.lua     角色表（由策划案表格生成）
  03_core.lua      数值 / 关卡 / 状态 / 板初始化
  04_rules.lua     判定规则 + 行动
  05_commands.lua  命令路由
  06_board.lua     黑板读写 + tick + 挂载钩子
→ node tools/build-main.mjs → code/<玩法>/主控 main.lua（运行时仍是**单个**脚本）
```

**三条防错线（都实测有效）**：

| 线 | 做什么 | 实测效果 |
|---|---|---|
| **字段契约断言** | 构建时比对"主控 `writeState` 写出的字段" ⊇ "其他脚本读的 `t.xxx` / `t["xxx"]`"，断了**直接报错不落盘** | 上线第一次跑就暴露"首字段 `"stage="` 没有前导 `;`"的正则盲区；能拦住 3.1/3.5 这类"字段对不上" |
| **切分器逐字节校验** | `split-main.mjs` 切完**重建一遍**，与旧构建产物**逐字节比对**，不一致拒绝落盘 | 本案例切分后产物 SHA 与线上活文件**完全一致**（重构零风险） |
| **作用域检查 `tools/check-lua-scope.mjs`**（加） | 按 Lua 真实绑定规则扫「读了但没绑定到 local、也不是已知全局」的名字；`--selftest` 自带正反例 | 一次命中 13 条（含 §3.5d 的 C_PANEL / curStage），修完全绿；它自己也被自检抓出 2 个假阳性 |
| **风格门禁 `tools/check-lua-style.mjs`**（加） | 机械可判的风格规则：**error 级**（BOM / CRLF / TAB / `OnUpdate` 少 pcall / 吞错 pcall）拦部署；**warn 级**走**基线**（`--baseline`：新代码不许比基线差）。附带 `--fix`（BOM/CRLF/TAB/分号，行为等价）与 `--fix-blocks`（单行 if 展开，带**关键字计数不变**硬校验） | 用它 + `--fix` 把本案例 **184 warn → 0 warn**；基线随之钉成 **0/0**，此后任何新增 warn 都会被拦下（见 §7） |

## 5. 验收口径（本案例实际走的流程）

0. **静态两道门**：`node tools/check-lua-scope.mjs`（作用域）+ `node tools/check-lua-style.mjs --baseline`（风格，见 §4）→ **两道都绿**才往下走；主控另跑 `node tools/build-main.mjs`（带契约断言）
0b. **模拟器预测试（deploy 之前，补）**：`miliastra_sim op=bind`（scripts + templates + containerId）
   → `op=patch` 补黑板文本控件 → `op=verify`（steps + expect）→ 读 `snapshot.logs`：
   **零 `首错=` 才算过**；整局主路径（翻面 → 抓捕 → 逮捕 → 胜利）能跑通再谈真机。
1. `miliastra_code op=deploy`（自动备份 + SHA + BOM 检查 + 结构 lint）
2. `miliastra_map op=script` → **`match: true`**（否则先让创作者存盘）
3. 人点试玩 → **`miliastra_shot op=burst awaitPlaytest:true untilGone:true`** 自己抓图（⚠️ 开局前 ~14 秒是**加载画面**，要看进图后的帧）
4. **`miliastra_log op=runs` / `op=tail tag=...`**：`errorSample` 里的行号就是崩溃点（本案例 5 个 bug 全靠它定位）
5. 每次都在回复里写清"改了哪、为什么、证据是什么"；**没真机跑过的写 `pending`**
   ⚠️ **模拟器通过 ≠ 真机通过**（官方素材渲染、联机、手感都不覆盖）。

## 8. 追加事故：覆盖层"看不见" + 状态被覆盖 + 返回栈 + 全局 nil + 工具把文件压成一行

> 这一轮的主线是给标题页/选关/图鉴加"覆盖层"，顺带把玩时设置菜单做出来。
> **五个事故里有两个是"测试自己抓出来的"** —— 值得抄的不是修法，是"每改一步就跑端到端判定"这个习惯。

### 8.1 覆盖层"看不见"（三层原因叠在一起，最贵的一个）

**现象**：点【选择关卡】后日志完全正常（`ui=title→pick` 来回切、`jump 目标=7` 都发出去了），
但**面板就是不在画面上** —— 玩家只能盲点。

**三层原因**（要按顺序理解，缺一条都会误判）：
1. **越界 `SetSiblingIndex` 静默无效**：API 文档写 `index 范围是 0..父控件子控件数-1`，传 `9999` 越界 ⇒
   **返回 `false`、不抛错**。当时只 `pcall` 看"有没有抛异常" ⇒ 静默通过、日志零线索。
   ⇒ 判据要用**返回值**（`ret ~= false`），正解优先 `SetAsLastSibling()`。
2. **创建顺序 = 绘制层级**：`board.lua` 顶部早有一条创作者实测注记「翻牌文字被角图盖住 / 下一关按钮被结果面板盖住」
   ⇒ **后建的在上**。而日志顺序是 `[view] 界面已建` → `[board] 调查板已建` ⇒ 在 `build()` 里建的覆盖层**必然**被棋盘压住。
3. **同帧顺序不可靠**：view 与 board 的首个 `OnUpdate` 在同一帧，谁先谁后不能假定。

**修法（三层叠起来，两条规则都兜住）**：
- 覆盖层**按需创建**（第一次要显示时才建）：`if ovMode ~= "" and items["ovTitle"] == nil and tickN >= 2 then buildOverlay() end`；
- **延后到第 2 帧**才允许建，并在 `tick` 里**强制重画一次**（否则"只在状态串变化时渲染"的写法会让覆盖层永远建不出来）；
- 每次模式切换 **+ 每 0.4 秒**再 `SetAsLastSibling()`（quiet，不刷屏）；
- 提层**必须打日志带数字**：`覆盖层提层：pick 共 17 个，失败 0`（失败数 > 0 就是平台语义变了，能立刻看出来）。

### 8.2 `ui` 状态被 `initBoard` 覆盖 ⇒「点开始调查没反应」

**现象**：标题页点【开始调查】，日志显示 `发出指令 start` 也到了主控，但**画面毫无变化**。

**根因（代码级，不靠猜）**：`start` 处理器是 `G.ui = "" → initBoard()`，而 `initBoard()` 里写着 `G.ui = "title"`
⇒ 刚清掉的 ui **又被设回去**。同类还有 `jump`（它把 `G.ui=""` 写在 `initBoard` 之后 ⇒ 侥幸没坏）。

**纪律（= L2-04 的实例）**：**一个字段只允许一个写入方**。`ui` 只由命令层（`start`/`jump`/`pick`/`codex`/`help`/`menu`）
与 `freshStart()` 写；`initBoard()` 这种"被 4 条路径调用"的重建函数**不许碰它**（写进去就是 4 个隐藏覆盖源）。
每次切换都 `log("覆盖层 → xxx；关掉后回 xxx")` —— 真机再遇"点了没反应"，这一行直接给答案。

### 8.3 返回栈只记一层 ⇒ 菜单→图鉴→关闭之后掉回标题页

**现象**：玩着 → 设置菜单 → 角色图鉴 → 关闭（回菜单）→ 再关菜单 ⇒ **掉回标题页**（不是回游戏）。

**根因**：`G.uiBack`（单层）在"关闭图鉴"那一步被消耗掉了（`G.uiBack = nil`）。

**修法**：改成**栈**（`G.uiStack`：打开压栈、关闭弹栈、`freshStart`/`start`/`jump`/`restart` 清空）。
**判据**：`back = table.remove(G.uiStack) or "title"`。
> 这条是**端到端判定自己抓出来的**（6 条断言过了 5 条，第 6 条把它暴露出来）。

### 8.4 `local` 声明写在使用者之后 ⇒ 全文件"没有它的 local 声明"（作用域门禁抓到）

**现象**：`MENU_BTNS`（菜单四个按钮的表）声明在 `buildOverlay`/`raiseOverlay` **之后** ⇒
函数体里读到的是**全局 `nil`**（Lua 编译期绑定）⇒ 菜单按钮一个都建不出来，而且**不报错**。

**判据/门禁**：`node tools/check-lua-scope.mjs` 报 `UNDEF_READ 读 MENU_BTNS：全文件都没有它的 local 声明`。
**修法**：把这类"多函数共用的表"声明到**所有使用者之前**（本工程放在模块级局部变量区）。

### 8.5 工具事故：`Set-Content -NoNewline` 把整个 `.lua` 压成一行

**现象**：用 PowerShell 做一次文本替换（`(Get-Content x) -replace a,b | Set-Content x -NoNewline`）⇒
**LF 全没了（LF=0）**，整个文件变成一行；而 Lua 的 `--` 注释会吞掉该行后面的一切 ⇒ **文件语义全废**（且 `-Encoding UTF8` 还加了 BOM）。

**两个禁令**（已写进工作区 `AGENTS.md §3`）：
- ⛔ **不要用 PowerShell 的 `Set-Content`/`Out-File` 写 `.lua`**（哪怕只是片段）：BOM + 压行双坑；
- 改 `.lua` 一律用 `edit`/`write` 工具或 node 的 `fs`，写完查前 3 字节 = `2d 2d 20`。

**恢复手法（值得抄）**：**构建产物 = 片段原文的完整备份**。该工程的 `code/侦探1/主控 main.lua` 是
`01_head…06_board` 六片段**逐字拼接**的 ⇒ 从活文件备份目录里取一份**上一个能跑的产物**，
按标记切回对应片段（`-- ★★ …实测反馈②` 到 `-- ── 黑板 ─`），再把当轮编辑重打一遍即可。
（同轮还确认了：`node tools/check-lua-scope.mjs` 会在下一步立刻报 `UNDEF_READ 读 handleCmd`——
**门禁比人先发现文件坏了**，所以"改完必跑门禁"这条纪律的收益是实打实的。）

### 8.6 UI 统一（覆盖层五屏同一套版式）：**前缀可见性 + 一键构造器**，净减 39 行

**背景**：创作者要求「图鉴 / 教程 / 选关 要精致、要描边」。改这类"外观统一"需求时，**最大的坑是文件行数**：
本工程 `view.lua` 当时 **999 行**，而风格门禁有 `BIG_FILE > 1000 行` ⇒ **加 2 行就红**。

**两个"更好 + 更短"的改法**（外观规则本身见 `miliastra-ui` 的 `case-detectives-ui.md` §8）：
1. **显示 / 提层改成"前缀驱动"**：五个覆盖层各占一个前缀（`ov` 标题 / `pk` 选关 / `cx` 图鉴·教程 / `mx` 菜单），
   `showOverlay(mode)` 与 `raiseOverlay(mode)` 都只按前缀遍历 `items` ⇒
   原来 **45 行逐控件 `show("xxx", isXxx)` 清单 + 14 行 `names = {...}` 提层清单，合并成约 15 行**。
   副产品：**再也不会"新增一屏忘了加进显示清单"**（那正是覆盖层"看不见"的来源）。
   同理，`tick` 里"首次构建后把 48 个控件逐个 `show`"换成"**非覆盖层前缀一律显示**"（−40 行）。
2. **UI 构造器**：`makePanel(pre, x, y, w, h)` / `makeBtn(name, x, y, w, h, txt)` 一次把
   「外框 + 内芯 + 带描边的文字 + 登记按钮矩形（给悬停用）」做完 ⇒ 五屏版式只写一遍。
   ⚠️ 两条硬约束：① 构造器里**不要用**后面才 `local` 的函数（`setText`/`setFont`）——改成用 `add` 的返回值直接设属性，
   否则又踩 §3.5b 那条"编译成全局读 = nil"；② 构造器必须声明在**所有调用者之前**。

**顺带修了工具**：`tools/check-lua-scope.mjs` 的控件名检查原本只认 `add("名字"`，
名字被构造器藏进参数后就**假报 `UNDEF_CONTROL`** ⇒ 给它加了"认识 `makePanel`/`makeBtn`、并把派生名
（`<name>` / `<name>Bg` / `<name>Tx` / `<name>P` / `<name>PBg`）算作已建"，动态写法（`makeBtn("mxB" .. i, …)`）
归入"DYN 前缀，自己确认"。**门禁假报比漏报更危险**（会逼人绕过门禁），发现就当场修。


### 8.7 「同一人说法固定」这条规则**漏了一个入口** ⇒ 真机表现为"同一人前后说法不一样"

**现象（创作者反馈）**：第 11 关点开「搭档」，他先说「7 号是恶棍 —— 我早查过了」，等板上身份都翻完再点，
变成「嗨，搭档」。创作者原话：「既然搭档是第一个，咋会出现"所有人都查完了"」。

**根因（两层）**：
1. **说法是"点击那一刻"才算的**，不是开局算的：`04_rules.lua` 里
   `elseif c.flipped then G.stmt = c.said or declareFor(c, lying)`（重看分支）与
   `else G.stmt = declareFor(c, lying); c.said = G.stmt`（首次翻牌分支 + **只有这里写缓存**）。
2. **"开局即已调查"的角色永远走不到写缓存那条分支**（`03_core.lua` ⑤ `buddy.flipped = true`）⇒
   他的 `c.said` **永远是 nil** ⇒ **每点一次重掷一次**，说法随翻开进度变 —— 直接违反代码里 431 行
   自己写的注释「说法要**固定**（同一人每次问都说同一句）」。

**判据（可机械查）**：grep 每个"缓存字段"（`c.said` 这类）的**写入点**，再看**所有产生该语义的入口**是否都写了。
本例两个入口只写了一个，而"另一条路"的那批实例（开局就处于该状态、被技能提前改过状态的）**永远只走不写的那条**。
⇒ 共同形状：**"状态可以被别处预先设置" + "缓存只在主路径写" = 预置状态的那批人行为不一致**。

**修法（创作者选方案①）**：`04_rules.lua` 末尾加 `settleSaid()`：遍历 16 格，对
`c.flipped and not c.place and c.said == nil` 的实例 `c.said = declareFor(c, isLying(c))` 并打日志，
**在每次 `initBoard(...)` 之后调用**（05_commands 的 restart/start/jump/next 四处 + 06_board 的 freshStart 一处）。
⚠️ 声明顺序：`declareFor`/`isLying` 在 04_rules、`initBoard` 在 03_core ⇒ **调用点只能放 04 之后的片段**（05/06），
放 03 里会编译成全局读（nil）—— 正是 §3.5b 那个坑。

**副作用（要跟创作者说清）**：说法开局定死后，「嗨，搭档」那条"所有人都查完了"的兜底**基本不会再出现**
（开局总有未翻的身份）。这是取舍：宁可"说法固定、且真的指一个人"，也不要"每次点都变"。
另：「说谎时取不到不在场名字 ⇒ 嗨,搭档」那条兜底是**死代码**（`absentName()` 从 26 角色里挑不在板的，
12 身份局恒有 14 个候选 ⇒ 永不 nil）。

**真机取证**：`开局说法：14 号 搭档 = 9 号是 恶棍 —— 我早查过了。`（与板初始化同帧打印；模拟器确定性重放 3/3 通过）
