# 规范扫描整改工作流（千星 Lua）

> **触发**：创作者说「按规范扫一遍《XX》并整改」。
> **三步固定，一步都不许跳**：**① 先备份 → ② 贪婪模式理解项目 → ③ 结合项目实际改造**。
> 每一步都有**可核对产物**（快照清单 / 摸底表 / 改动前后数字）——不是"我觉得改好了"。
>
> 与 `references/lua-style.md`（规则正文）的关系：那份说**改成什么样**，这份说**怎么改才不出事**。

---

## 0. 总览

| 步 | 干什么 | 产物 / 证据 | 工具 |
|---|---|---|---|
| **① 备份** | 项目文件 + 构建源片段**一次快照**（带 SHA 清单、拒绝覆盖） | `案子/<地图>/2.代码/_snapshots/<ts>/manifest.json` | `tools/snapshot-lua-project.mjs` |
| **② 贪婪理解** | 结构 / 契约 / 构建关系 / 不能动的行 ——**全量摸底，不抽样** | 一张摸底表（脚本分工 + 黑板契约 + 构建关系 + 禁区） | `check-lua-scope --map <地图>` · `check-lua-style --map <地图> --summary` · `miliastra_health` · `miliastra_code op=inspect` · 定向 grep |
| **③ 结合项目实际改造** | 机械的交给工具、要判断的逐条改、**每一档都有验证闸门** | "整改前→后"数字 + 各闸门回执 | `check-lua-style --fix` · 手工改 · `build-main` · `miliastra_sim op=verify` · `--update-baseline` |

> ★ **工作区只有一个代码根**：`案子/<地图>/2.代码/`（**成品与构建源同目录**）。
> 老的 `code/<玩法>/` + `sources/<玩法>/` 两个根**都已不存在** ⇒ 所有 `tools/` 脚本改成**按地图名解析路径**：
> 统一加 **`--map <地图名>`**（默认 `侦探1`），根解析收敛在 **`tools/_paths.mjs`**。下方命令都已按这个口径更新。

## 1. 先备份（不许跳过，也不许"我改完再备份"）

```powershell
node tools/snapshot-lua-project.mjs --map 侦探1 --label "规范整改前"
```

- **为什么"连构建片段一起"**：`main.lua` 是**构建产物**，它的头部/角色表来自 `案子/侦探1/2.代码/main/*`——
  只备份成品会把"真正要改的地方"漏在快照外（这正是本工具第一次跑就暴露的缺口）。
 ★ **片段与成品同目录** ⇒ 默认 `--map <地图>` 一次就把两边都装进同一份快照（不再需要给两个路径）；
  给显式路径仍然认（`node tools/snapshot-lua-project.mjs "案子/侦探1/2.代码" --label …`）。
- **拒绝覆盖**：目录带时间戳，同秒撞名自动加 `-2/-3`；每次整改留一个**独立撤销点**。
- **分区**：项目目录（那个 `2.代码/`）内的文件进 `project/`（片段在它的子目录里，天然含在内），
  项目目录之外的落单文件进 `_outside/`（并在回执里点名）。
- **还原**：按 `manifest.json` 逐文件二进制拷回（回执里直接给了 `Copy-Item` 模板）。
- ✅ **完成判据**：回执给出快照目录 + 文件数/字节数；清单里每个文件都有 SHA-256。

> 顺带：`check-lua-style --fix --write` 在写盘前**会自己再快照一份**（标签 `风格整改前（--fix 自动快照）`）——
> 机械修复这一档不存在"忘了备份"的可能；手工改档请务必先跑第 1 步。

## 2. 贪婪模式理解项目（全量摸底，不抽样）

**目标**：在动任何一行之前，把"这个项目是什么形状"摸到底——尤其是**不能被机械规则误伤的结构**。

### 2.1 先跑现成工具（数字与明细，别凭印象）

```powershell
node tools/check-lua-scope.mjs             # 作用域现状（漏 local / 闭包顺序）——整改期间的对照基线
node tools/check-lua-style.mjs --summary   # 风格直方图：先看"哪类规则、各多少条"
node tools/check-lua-style.mjs             # 逐行明细：要判断的那批到底长什么样
miliastra_health {}                        # 当前关卡 / 活文件 / 日志目录（路径随换图变化，别写死）
miliastra_code op=inspect                  # 活文件 SHA + 部署指纹（有没有被编辑器写回过旧版）
```

### 2.2 再定向检索（"贪婪"= 把全量事实捞出来）

| 要摸什么 | 怎么摸 | 为什么必须先摸 |
|---|---|---|
| **每个脚本的角色** | 读各文件头部注释块 → 一句话分工（如 `主控/调查板/表现/交互/翻牌/效果引擎`） | 改错文件 = 白干；跨脚本改动要同时改 |
| **黑板字段契约** | grep 无 `local` 的赋值（写入者）与 `t.xxx` / `t["xxx"]`（读取者） | 字段是**单向写**的：改读取方要确认写入方还在供 |
| **控件名契约** | `add("名字")` 的集合 vs `show/setText/...` 用到的名字 | 名字打错在严格模式下直接冻结整脚本 |
| **构建产物 vs 源片段** | 存在 `tools/build-main.mjs`（或 `build-shuangxiang` / `build-mage-battle`）⇒ 那份 `.lua` 是产物；片段在**同一个 `2.代码/`** 里（侦探1 是 `main/`，双相是 `{main,input,view,…}/`） | **改产物会被下次构建覆盖** |
| **平台约束现状** | `OnUpdate` 是否包 `pcall`、有没有 `assert`、有没有"掩盖报错的兜底" | 创作者明令禁止掩盖报错；整改正是补这个的时机 |
| **日志格式覆盖** | `[标签]` 前缀与 `k=v` 的覆盖率 | 能被 `miliastra_log op=metrics` 抽 = 后续排障省事 |
| **历史/参考文件** | `main.engine.lua`、`roles.lua`、`_探针_*`、`*_备份.lua`、`_snapshots/` | 这些**不进 sandbox、不该整改**（只在报告里点一句） |

### 2.3 产出：摸底表（第 3 步的依据）

| 脚本 | 角色 | 写哪些黑板字段 | 读哪些 | 是否构建产物 | 禁区（不能动的行/结构） |
|---|---|---|---|---|---|
| 主控 main.lua | … | `t1_kb_state` … | … | **是**（改 `案子/<地图>/2.代码/main/*`） | 头部版本块来自 `01_head` |
| 调查板 board.lua | 层 2+3+4+5 … | … | … | 否 | 点击热区/层序 |
| … | | | | | |

## 3. 结合项目实际改造（分三档，档档有验证）

### 档 A · 机械安全 —— 交给工具（行为等价）

```powershell
node tools/check-lua-style.mjs --fix            # 预览：只列要改什么、不写盘
node tools/check-lua-style.mjs --fix --write    # 落盘：写前自动快照 + 逐文件校验
```

只做四件**不改变语义**的事：**BOM 去掉 · CRLF→LF · TAB→4 空格 · 分号（行尾删／行中拆成两行、保缩进）**。
分号只在**代码位置**处理——字符串与注释里的 `;` 一个都不碰（`codeMask` 逐字符判定，自检里有专例）。

> 记账口径：`--fix` 按**字符**计数，扫描报告按**行**计数——同一批分号可能显示 `SEMICOLON×102（字符）`
> vs 报告里 `69（行）`。两个都对，别当成矛盾。

### 档 B · 要判断 —— AI 逐条改，改完必跑验证

| 规则 | 怎么改 | 容易踩的坑 |
|---|---|---|
| `ONE_LINE_IF` | 展开成多行块（`then`/`end` 配对） | 别把 `then return end` 这种**允许**的单行也展开 |
| `BARE_PCALL` / 吞错 pcall | 按"失败去向"补 `log`（同一原因最多 3 次）或 `fail()` | 这正是创作者明令要堵的"掩盖报错"，必改 |
| `LONG_LINE` >120 | 拆出命名子表达式 | **不许改变求值顺序或副作用**（有副作用的调用别挪位） |
| `INDENT` | 确认真是缩进错、不是续行对齐 | 工具对续行会误报，先看原文再动 |
| `SINGLE_QUOTE` | 换双引号 | 串内含 `"` 或 `\'` 的先跳过（要选转义策略） |
| `ASSERT` | 换显式检查 + 返回错误串/`fail()` | 保留"绝不该发生"的自检语义，别把校验删掉 |
| `HDR` 缺版本块 | 补写：日期 + **依据**（谁提的/哪条日志）+ 改动 | **只加不覆盖**历史版本行；日志里的版本行要对得上 |

### 档 C · 不许碰（先说清楚再动）

- ⚠️ **构建产物**：`main.lua` 要改就改 **`案子/<地图>/2.代码/main/*` 片段** → `node tools/build-main.mjs --map <地图>`
  （构建脚本带**字段契约断言**：主控写出的字段必须覆盖其它脚本读的，断了直接报错、不落盘）。
- **历史/参考文件**：`main.engine.lua` / `roles.lua` / `_探针_*` / `*_备份.lua` → 不整改，报告里点一句即可。
- **玩法本体（铁律）**：规则、判定、胜负、**数值**、组件位置——整改**只动形状不动语义**；拿不准就先问。
- **命名类**（`FUNC_UPPER` 等）：改名字会波及调用点——要么**同批一起改**（改完必过 scope 检查），要么不动。

### 3.1 验证闸门（每档改完都要过）

| 改动范围 | 必过的闸门 |
|---|---|
| 任何脚本 | `node tools/check-lua-scope.mjs` + `node tools/check-lua-style.mjs` |
| 动过 main 片段 | `node tools/build-main.mjs`（契约断言）→ 产物 diff 合理 |
| 牵涉逻辑/日志 | `miliastra_sim`：`op=bind` → `op=verify`（或 `op=cases action=run`）看 `snapshot.logs` |
| 准备上真机 | `miliastra_code op=deploy` → 编辑器**存盘** → `miliastra_map op=script` 看 `match: true` → **人**点试玩 |
| 整改收尾 | `node tools/check-lua-style.mjs --update-baseline`（把清掉的存量从基线里扣掉） |

## 4. 收尾清单（逐条勾）

- [ ] 快照在（`_snapshots/<ts>/`），清单 SHA 与磁盘文件一致
- [ ] `check-lua-scope.mjs` 绿
- [ ] `check-lua-style.mjs --baseline` 绿（error 0 + 无回归）
- [ ] 动过 `main` ⇒ 片段改了、重新构建了、字段契约断言过了
- [ ] 模拟器 `verify`/`cases` 过；`miliastra_log op=runs` 无首错
- [ ] 基线已 `--update-baseline`，报告里给出"整改前 → 后"的数字
- [ ] 报告**如实分档**：机械修了哪些 / 判断改了哪些 / **明确没碰哪些 + 理由**
