## 1 · 《侦探杀》的四类变量桥接通道

| 基础类型 | 标量 | **列表**（优先 ✓） | 追加变体 |
|---|---|---|---|
| 整数 | `侦_整数` | `侦_整数列表` | `侦_整数列表_新增` |
| 字符串 | `侦_字符串` | `侦_字符串列表` | `侦_字符串列表_新增` |
| 布尔值 | `侦_布尔值` | `侦_布尔值列表` | （同上规律 ✓） |
| **浮点数** | `侦_浮点数` | `侦_浮点数列表` | `侦_浮点数列表_新增` |

⇒ 真机信号管理器里就是这 4 × (标量 / 列表 / 列表·新增) 一整套 ✓（截图见会话记录 ✓）。

上表是该项目的桥接协议，不是平台全部参数类型。服务器信号须按当前 API 与服务端契约选择 AddInt/AddGuid/AddVector3/列表等接口；不能由此推导“自定义变量不能读字典/结构体”。客户端读取复杂变量见 §3。

## 2 · ⭐ 做项目**优先用列表**

**为什么** ✓（不是风格偏好 ✓ 是通道经济学 ✓）：

| 用标量 | 用列表 |
|---|---|
| 每个字段一条信号 + 一个变量 ✗ | **一类数据一条列表** ✓ |
| 字段数一涨，信号/变量/节点图**跟着涨** ✗ | **通道数恒定** ✓ |
| 契约面 = 字段数 ✗ | 契约面 = **类型数（4）** ✓ |

⇒ 口诀 ✓：**"能进列表就进列表"** ✓ —— 一局内的排行榜、手牌、点位、日志、状态行，**都用列表** ✓；
只有当那个值**真的只有一个**（时间 / 阶段 / 开关 ✓）才用标量 ✓。

⚠️ **两条列表纪律** ✓：
1. **列表只走"覆盖"** ✓ —— `_新增` 是**追加** ✓，会**累积** ✗（用它就别再"覆盖式"刷同一条 ✓ 二者选一 ✓）；
2. 长度有上限 ✓ ⇒ 超长的东西（大段文本）走**字符串**或**拆段** ✓，别硬塞列表 ✓。

## 3 · 自定义变量可以读取列表、字典与结构体

`annotations.lua` 的 `GetGlobalCustomVariableValue` 明确支持复杂变量结构。2026-10-18 用户确认运行的范例通过 `QuestService` / `SceneService` 读取 PlayerSelf 嵌套字典；通过 `CustomVariable` 保留数字、布尔、字符串与表原值。无需为了读取复杂变量强行拆成并行列表或字符串。

字符串路径先查原字符串键，缺失时再尝试整数键；显式键数组保留键类型，不对字典键进行 index+1。false/0 均为有效值；使用 nil 与错误返回区分缺失。枚举、变量名称、配置结构都以当前工程为准。

这不证明服务器信号可以 AddTable，也不证明每个 AvatarSelf 分支实际读取成功。字典键增删不一定触发变化回调，仍遵循 engine-boundaries #43 的刷新规则。

## 4 · 按数据归属选择实体

客户端 `PlayerSelf` 可读：已有《侦探杀》记录，且 2026-10-18 用户确认运行的对话/任务工程多处实际使用；`AvatarSelf` 在通用解析器中有支持分支，具体角色变量读值仍需实例证据。按数据归属选 Level / PlayerSelf / AvatarSelf，不能把“只验过 Level”当限制。详见 [对话工程参考](dialog-template-patterns.md)。

客户端无自定义变量写入 API；写入仍由服务端约定完成。多人数据不能默认全部改挂 Level。任意空模型不属于这三个相对作用域，不应推荐为客户端可直接查询的数据表。

## 5 · 信号 → 变量 的**节点图形状**（导出的那份就是标准答案 ✓）

真机那份（`assets/信号节点图_4类型整改_侦探杀_20260929.gia` ✓）每个类型一对节点 ✓：

```
[监听信号]  信号名 = 侦_整数          ──┐
            名称 ← (字符串参数)          │
            数值 ← (该类型参数)          │
                                        ▼
                            [设置自定义变量]
                              目标实体  = 关卡实体 ✓
                              变量名    ← 监听信号·名称   ⭐ 按名字写 ⇒ 加字段不用改图 ✓
                              变量值    ← 监听信号·数值
                              是否触发事件 = 是 ✓
```

⇒ ⭐ **这套形状的红利** ✓：图里**没有具体字段名** ✓ ⇒ 以后加字段**只动客户端一行** ✓ 节点图**永远不动** ✓
（《侦探杀》那轮就是靠这个，从"每字段一对节点"缩成"每类型一对" ✓）

### 安装建议（**推荐但可选** ✓ —— 让用户选 ✓）

| 选项 | 做法 | 代价 |
|---|---|---|
| **① 导入现成的（推荐 ✓）** | 用千星的节点图导入功能导入上面那份 `.gia` ✓ | 依赖创作者会导入 ✓；导入后仍要**在编辑器里核一遍**它与本图的实体/变量名对得上 ✓ |

采用创作者手工操作方案时，可提供现成图的导入方法或逐节点搭建步骤。当前工具能实施的部分按已确认的授权继续。

## 原生声明、ID 域与字典维护

以下来自本机项目复盘，依据包括原生字段解码、离线回放和编辑器重存取证。不同存档版本或编码分支先找同域样本。

- 迁移变量、信号、复合或 UI 绑定时，记下每个数字的记录类型、字段、作用域和生产/消费对象。同一个数字可以同时标识一个信号壳与另一个私有复合；解析完整节点类型、版本、注册和执行边后才能判定调用。在载荷里以普通整数传输的 UI 索引同样需要追生产端、接收端及布局查表，迁移时只替换重定位的 ID 域。
- 原生服务端实体声明样本的 `VarType` 中，1 为 Entity、2 为 GUID、7 为 GUIDList、12 为 Vector。按服务端同域原生样本验证声明类型、实际值分支和默认值。客户端 `ClientVarType` 与客户端默认值编码是不同语义。现场曾因把实体变量写成错误的默认值分支而造成坐标输入不成立，需同时核服务端写入和客户端读取类型。
- 玩家变量先核对模板，再逐个核对实际参与的全部玩家实例与挂载。按当前关卡枚举实例数量。补全声明后同步 Lua 读写和默认值，比较实际声明和读写传播，不能仅凭模板里出现同名变量或某个玩家槽可读就判定全员可用。
- 组件字典原生分支 37 的运行时项在字段 1，编辑器键和值镜像在 501、502，503、504 保存键和值类型元数据。修改同一逻辑键时联动运行时值和编辑镜像，对齐键、顺序、类型和每条已有条目身份。用原生解码回读后再编辑器重存复核。脱敏项目中候选值 3 在重存后恢复为旧镜像值 300，重存后的运行时项整体精确匹配原镜像，确认漏同步镜像。条目身份仍需唯一且稳定，将回旧归因于复制身份是旧推测，不能当已证原因。
- 用 Excel 编辑地图字典时，导出完整目录并写清图、对象、字段和同名项的覆盖范围。可对齐的原生简单项开放现有键值，空字典、原生引用、嵌套结构或镜像不对齐项标成只读。整数按原生位宽和符号范围做无损校验，超出 Excel 精确表示范围时用文本。把以 `=` 开头的字面文本保留为文本，不能让工作簿将其计算成公式。回导前先证明无修改往返逐字节一致，单项修改只影响目标键及其镜像，保持原生条目身份。源指纹漂移时拒绝旧包覆盖，从最新源重新导出和检视变更。

## 双端信号从真实输入验证

按真实输入、客户端发出、服务端接收对象、业务状态/余额、客户端回执顺序取证。以当前 API 和原生信号注册核实发送方向、参数类型、接收对象与客户端回传路由。玩家接收样本只证明该链，不足以判定 Lua 只能向玩家发送。也别用脚本成功启动或掩膜框变化推断购买成功。

UI 按钮与原生技能若会触发同一状态转移，复用同一后端判据和幂等门，检查两条入口各自、交错和重复到达时的归属、计时、扣费或奖励及回执。最新本机复盘中该合流已有原生回放和活档回读，完整真机输入链仍待复验。
