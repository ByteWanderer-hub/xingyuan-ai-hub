## 1 · 《侦探杀》的四类变量桥接通道

| 基础类型 | 标量 | **列表**（优先 ✓） | 追加变体 |
|---|---|---|---|
| 整数 | `侦_整数` | `侦_整数列表` | `侦_整数列表_新增` |
| 字符串 | `侦_字符串` | `侦_字符串列表` | `侦_字符串列表_新增` |
| 布尔值 | `侦_布尔值` | `侦_布尔值列表` | （同上规律 ✓） |
| **浮点数** | `侦_浮点数` | `侦_浮点数列表` | `侦_浮点数列表_新增` |

⇒ 真机信号管理器里就是这 4 × (标量 / 列表 / 列表·新增) 一整套 ✓（截图见会话记录 ✓）。

上表是该项目的桥接协议，不是平台全部参数类型。服务器信号须按当前 API 与服务端契约选择 AddInt/AddGuid/AddVector3/列表等接口；不能由此推导“自定义变量不能读字典/结构体”。客户端读取复杂变量见 §3。

## 2 · ⭐ 做项目**优先用列表**

**为什么** ✓（不是风格偏好 ✓ 是通道经济学 ✓）：

| 用标量 | 用列表 |
|---|---|
| 每个字段一条信号 + 一个变量 ✗ | **一类数据一条列表** ✓ |
| 字段数一涨，信号/变量/节点图**跟着涨** ✗ | **通道数恒定** ✓ |
| 契约面 = 字段数 ✗ | 契约面 = **类型数（4）** ✓ |

⇒ 口诀 ✓：**"能进列表就进列表"** ✓ —— 一局内的排行榜、手牌、点位、日志、状态行，**都用列表** ✓；
只有当那个值**真的只有一个**（时间 / 阶段 / 开关 ✓）才用标量 ✓。

⚠️ **两条列表纪律** ✓：
1. **列表只走"覆盖"** ✓ —— `_新增` 是**追加** ✓，会**累积** ✗（用它就别再"覆盖式"刷同一条 ✓ 二者选一 ✓）；
2. 长度有上限 ✓ ⇒ 超长的东西（大段文本）走**字符串**或**拆段** ✓，别硬塞列表 ✓。

## 3 · 自定义变量可以读取列表、字典与结构体

`annotations.lua` 的 `GetGlobalCustomVariableValue` 明确支持复杂变量结构。2026-10-18 用户确认运行的范例通过 `QuestService` / `SceneService` 读取 PlayerSelf 嵌套字典；通过 `CustomVariable` 保留数字、布尔、字符串与表原值。无需为了读取复杂变量强行拆成并行列表或字符串。

字符串路径先查原字符串键，缺失时再尝试整数键；显式键数组保留键类型，不对字典键进行 index+1。false/0 均为有效值；使用 nil 与错误返回区分缺失。枚举、变量名称、配置结构都以当前工程为准。

这不证明服务器信号可以 AddTable，也不证明每个 AvatarSelf 分支实际读取成功。字典键增删不一定触发变化回调，仍遵循 engine-boundaries #43 的刷新规则。

## 4 · 按数据归属选择实体

客户端 `PlayerSelf` 可读：已有《侦探杀》记录，且 2026-10-18 用户确认运行的对话/任务工程多处实际使用；`AvatarSelf` 在通用解析器中有支持分支，具体角色变量读值仍需实例证据。按数据归属选 Level / PlayerSelf / AvatarSelf，不能把“只验过 Level”当限制。详见 [对话工程参考](dialog-template-patterns.md)。

客户端无自定义变量写入 API；写入仍由服务端约定完成。多人数据不能默认全部改挂 Level。任意空模型不属于这三个相对作用域，不应推荐为客户端可直接查询的数据表。

## 5 · 信号 → 变量 的**节点图形状**（导出的那份就是标准答案 ✓）

真机那份（`assets/信号节点图_4类型整改_侦探杀_20260929.gia` ✓）每个类型一对节点 ✓：

```
[监听信号]  信号名 = 侦_整数          ──┐
            名称 ← (字符串参数)          │
            数值 ← (该类型参数)          │
                                        ▼
                            [设置自定义变量]
                              目标实体  = 关卡实体 ✓
                              变量名    ← 监听信号·名称   ⭐ 按名字写 ⇒ 加字段不用改图 ✓
                              变量值    ← 监听信号·数值
                              是否触发事件 = 是 ✓
```

⇒ ⭐ **这套形状的红利** ✓：图里**没有具体字段名** ✓ ⇒ 以后加字段**只动客户端一行** ✓ 节点图**永远不动** ✓
（《侦探杀》那轮就是靠这个，从"每字段一对节点"缩成"每类型一对" ✓）

### 安装建议（**推荐但可选** ✓ —— 让用户选 ✓）

| 选项 | 做法 | 代价 |
|---|---|---|
| **① 导入现成的（推荐 ✓）** | 用千星的节点图导入功能导入上面那份 `.gia` ✓ | 依赖创作者会导入 ✓；导入后仍要**在编辑器里核一遍**它与本图的实体/变量名对得上 ✓ |
| **② 自己搭（不导入时 ✓）** | 按上面的形状，**每种类型一对节点**手搭一遍 ✓（4 类型 × 2 节点 = 8 个 ✓ 列表版再各一对 ✓） | 手工活 ✓ 但要不了几分钟 ✓ 且不依赖外部文件 ✓ |

⚠️ 两种方式都必须**由创作者在编辑器里做** ✓（AI 够不到节点图 ✓）
⇒ 我们的说法固定 ✓：**"推荐导入现成的那份；不方便导入我也可以给你逐节点的手搭步骤"** ✓ 让人二选一 ✓。
