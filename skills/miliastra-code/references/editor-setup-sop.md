# 千星奇域 客户端 UI 配置 SOP（容器 / 模板 / 多脚本 / 黑板）

> **来源**：《侦探_多组件》（关卡 1073741835）首次配置 **6 脚本 + 2 黑板 + 3 模板**，
> 全程照着官方使用指南走了一遍，并把每一步的坑记下来。带 ⚠️ 的都是**本次真实踩到**的。
> 证据等级：`observed`（真实环境观察到）/ `observed(模拟器)`（模拟器确定性重放）。

## 0. 总览：生效链（缺一环即**静默失效**）

```
界面控件组管理：新建客户端控件容器
  → ⚠️ 界面布局：添加界面控件，把该容器加进来     ← 最容易漏的一步（AI 教程漏过）
  → 客户端脚本资源管理器：新建客户端脚本（= 映射 + 本地文件 + 自动关联）
  → 选中容器节点 → 「脚本」页签 → 添加脚本（可挂多个）
  → 存为模板：脚本要动态创建的控件类型，各存一条独立模板
  → 保存脚本 → 千星沙箱侧保存 → Ctrl+S 存图
  → 试玩（改动脚本内容后：stop → 部署 → 重新试玩）
```

## 1. 建容器

- 路径：**界面控件组管理 → 新增客户端控件容器**（指南 §一 2.(1)）。
- ⚠️ **漏步实证**：只在界面控件组管理里建好**不够**，还必须到**界面布局**里「添加界面控件」把该容器加入本关卡布局——
 否则运行时没有任何控件/脚本生效（这正是硬边界 #1 的实际触发方式）。由创作者发现并补齐。
- 工具校验：`miliastra_map op=clientui level=<id>` 的 `structural` 里出现 `客户端控件容器`。

## 2. 存模板（脚本要动态创建什么，就存什么）

- 路径：**界面控件组管理 → 界面控件组库 → 客户端控件模板 →【添加客户端控件】→ 存为模板**。
- ⚠️ **画布上摆的实例 ≠ 模板**：摆出来的 图片/文本框/光标检测区域 实例，`game.InstantiateClientUIControl` **恒返回 nil**。
  本文件必须各存**一条独立模板**才能被脚本创建。
- 工具校验：`miliastra_map op=clientui` 的 `likelyTemplates` 应出现「**无父节点 + 名字是控件类型**」的记录；
  工具若告警 `dynamicCreateLikelyBroken: true` = 没存对（原话：对任何索引号都会返回 nil）。
- 《侦探_多组件》实测可用索引：**图片 1073742580 / 文本框 1073742587 / 光标检测区域 1073742589**。

## 3. 建脚本 + 挂载（多脚本逐个来）

- 建脚本：**千星沙箱 → 窗口 → 客户端脚本资源管理器 → 新建客户端脚本**
  （一键 = 建映射 + 建本地文件 + 自动关联；**映射与文件同名**）。也可用「新建脚本映射」手动关联已有文件。
- 挂载：**选中容器节点 → 右侧「脚本」页签 → 添加脚本**（一个容器可挂多个，实测 6 个并存）。
- 校验：
  - 沙箱 `external_lua_file\` 下文件存在且**字节数 > 0**（0 字节 ≠ 有内容）。
  - ⚠️ **插件的 `mount` 检查在"多脚本"地图上是假阴性**：它只读存档里单个嵌入脚本名，
    读到旧占位「新建客户端脚本」就报 `mounted: false`。
    **正确验法**：`node tools/scan-gil-ids.mjs <gil> <映射索引…>` 看映射索引在不在存档里命中；
    或直接试玩看每个脚本的就绪行。

## 4. 黑板（脚本间共享状态）——**必须编辑器预置命名控件**

- **运行期创建控件后再改名，能力未验证** → 跨脚本共享的控件不要在运行期造：
  在**容器画布下预置**并命名（本项目：`t1_kb_state` 主控写 / `t1_kb_cmd` 交互写）。
- 同容器脚本用 **`script.object:GetChild("名字")`** 互读，读写 `.text` ——**模拟器已端到端实测**（A 写 `A写-1`，B 读到）。
- 契约先行：单写者原则（一块黑板只有一个文件写）+ 单调序号（`seq`/`fx` 令牌）避免"谁清空"的协商。

## 5. 脚本间通信通道（模拟器实测）

| 通道 | 结论 | 证据 |
|---|---|---|
| 共享命名控件（黑板） | ✅ **端到端可用（推荐）** | 模拟器 E0：B 读到 A 写的值 |
| `ServerSignal` 上报到服务器 | ✅ 到达服务器 | server `inbound` 记录到 `e0_ping Int42` |
| 服务器→客户端**回环** | ❌ 单机无节点图时**不回环** | 注册成功但回调零触发；指南 §一 2.(3)：回传要靠**服务器节点【发送客户端脚本信号】** |
| `require` | 引擎侧存在（`require=function`）；**设备侧文档查无** → `unknown` | 模拟器 E0 |
| 运行期给控件改名 | 未验证 → **不依赖** | —— |

## 6. 每个脚本强制三件事（否则"静默不跑"）

1. `OnInit` 里 **`script:EnableUpdate(true)`** —— ⚠️ 漏了 `OnUpdate` **永不执行**（不是慢，是根本不跑）。
2. `OnUpdate` 全体 **`pcall → fail`** 聚合故障块（一文件崩不拖累其他文件）。
3. `OnStart` 打**就绪行**（含 `script.path`）——一局日志里一眼看出哪个脚本没挂上/没跑。
4. ⚠️ **多脚本工程里，任何"清理/扫描兄弟控件"的操作必须先白名单保护**：绝不要"把容器里所有不是自己建的控件都隐藏"——
 实测事故：`view` 加了"隐藏遗留控件"的扫描后，**连兄弟脚本建的东西一起隐藏**：
   - `input` 的**光标检测区域**（点击热区）被隐藏 ⇒ **点击彻底失效**（玩家反馈"点不动"）；
   - `fx` 的闪效覆盖层被隐藏 ⇒ 闪效失效。
   正确写法：**按可辨识特征精确打击**（如"名为『图片』且 `imageId` 为空"、"名为『文本框』且 `text` 为空"），
   并把已知的兄弟脚本控件名（`光标检测区域` / 黑板 `t1_kb_*`）**显式排除**。
   > 推论（可复用）：多脚本工程里，"谁建的控件"在运行时**不可靠可判**（模板名会重复、运行期改名未验证）——
   > 凡是会影响全局的批量操作，都要有白名单，且**改完必须重开一局真机验证交互**。


## 6.5 素材（界面控件组库）怎么才能被脚本用上（实测）

**先认清三个"容器"不是一回事**：

| 名称 | 在哪 | 运行时可达吗 |
|---|---|---|
| **界面控件组库**里的素材组（封面/门1/角图…） | 界面控件组管理里以"组"形式存在 | ❌ **不在运行时 UI 树里**——`game.FindClientUIRoot("封面")` 实测返回 nil |
| **客户端控件容器画布**（进了界面布局的那个） | 运行时 UI 根 | ✅ `game.GetClientUIRoots()` 返回它；`GetChildren()` 可遍历 |
| **存为模板**的控件 | 客户端控件模板库 | ✅ `game.InstantiateClientUIControl` 可创建 |

⇒ 素材进游戏的**可行路径**：
1. **素材索引直接实例化整组（推荐）**：`game.InstantiateClientUIControl(<素材索引>, ROOT)` —— 实测**可直接用**（`1073742070 / 1073742296 / 1073742234 / 1073742110 / 1073742201 / 1073742409 / 1073742543 / 1073742519`）；
   实例化后对**整组根节点** `SetLocalScale` / `SetAnchoredPosition` **生效**（见 §6.6）；只有 `封面 1073741866` 实例化失败（待查）。
2. **把素材组拖进容器画布**：脚本 `script.object:GetChild("封面")` 直接按名字显隐/位移，**保留创作者的布局**（适合"素材本来就摆好了"的情况）。
3. **素材组存为模板**：⚠️ 实测**组模板不可实例化**（`1073742558/2566` → nil），只有**单控件**模板能创建。

**配套能力（实测可用）**：
- `GetChildren()` 能列出**运行时动态创建的控件**（本次 5 个编辑期 + 9 个脚本建的 = 14 个）；
- 图片控件 `imageId` / `imageSource` **只读可读**（`SetImage(100001)` 后读回 `100001`）→ **可做运行时资产盘点**，不用让创作者抄资产号。

### 6.6 ★ 素材使用原则（**创作者口径为准** · 已复测通过）

> 创作者原话：**"模板都是拼凑好的素材，没必要单独拆开用，可以共同放大缩小。"**

- **默认姿势：素材整组用** —— 实例化整组 → 对整组做 **`SetLocalScale` 整体缩放 / `SetAnchoredPosition` 位移 / `SetVisible` 显隐**。
- ✅ **复测结论（真机，干净对照）**：只实例化一个素材（`声望值 1073742543`），仅对它调 `SetLocalScale(0.35,0.35,1)` + `SetAnchoredPosition(toX(1180), toY(560))` → 截图前后对比：**面板明显变小、并移到右下** ⇒ **整组变换确实生效**。
  AI 此前"素材组整体不可变换 / 必须拆成单图"的结论是**脏实验误判**（当时多素材叠加 + 遗留"?"控件干扰），**已作废**。
- ⚠️ **唯一仍不行的**：`rotationZ` 写不进去（返回 false）→ 素材保持**作者摆放时的旋转**；要摆正**得在编辑器里把素材转正**。
- 复测方法（**下次再验别的控件族时照此，别再犯脏实验的错**）：
  1. 只放 **一个** 被验对象（场景里别有其它未隐藏控件干扰）；
  2. **只**做你想验的那一个变换；
  3. 截图**前后各一张**对比——不要凭"叠在一起看不清"下结论。

## 7. 部署与迭代（AI 侧）

1. 本地写码 → `miliastra_code op=deploy level=<id> file=<活文件名> source=<本地绝对路径>`
   （自动：备份 + Lua 结构校验 + SHA 校验 + 无 BOM + 部署指纹）。
2. ⚠️ **部署后不要让人在编辑器里点「保存脚本」**——脚本面板里的旧（空）内容会覆盖部署结果。
   指纹能抓到（`op=inspect` 会报不一致），但别给它机会。
3. 改内容 → **stop 试玩 → deploy → 重新试玩**（部署**不会**热更正在进行的试玩）。
