# 黑板 → 自定义变量 + 服务器信号：完整实践（《侦探杀》大改造案例）

> **一句话结论**：**拿"黑板文本框"当 Lua 之间的交互通道是不合适的** ✗ ——
> 它本该是"给人看的调试板" ✓，不该是"脚本之间的总线" ✗。
> 正确做法：**状态走自定义变量 + 服务器信号（推模式）**；**即时反馈 / 指令走 `Invoke` 直推**。

---

## 1. 为什么黑板不适合做 Lua 交互（三条硬理由，都是真机实测）

| # | 理由 | 实测证据 |
|---|---|---|
| ① | **长度上限** ✗ | 状态串涨到 **4424** 字符时平台每帧刷 `主控 main:NNNN: 文本长度超出限制` ✓（缩到 **1758** 后一行都没有 ✓） |
| ② | **有"多来源歧义"** ✗✗ | 黑板控件挂在**别的容器**时，读方得加"本容器为空就换另一份"的兜底 ✗ ⇒ **两份交替** ⇒ 值一会儿有一会儿没有 ✓（表现为「隔一条才显示」✓ 查了两轮才定位 ✓） |
| ③ | **异步 / 时机不可控** ✗ | 黑板是"写控件 → 别人来读"✓ ⇒ **谁先谁后不定** ✓；实测「消息落后渲染一条」✗「点一下才对齐」✗ —— 数据早到了，只是**重画没跟上** ✓ |

**附加成本**：每帧要"解析字符串" ✓ + 字段靠**字符串约定**（`key=value;` ✓ 拼错不报错 ✓）+ 40 个字段全挤一条串 ✓。
⇒ **结论**：黑板适合**调试期给人看** ✓；**生产期的脚本交互必须换通道** ✓。

## 2. 三条通道的选型（今天全部真机验证过 ✓）

| 通道 | 方向 | 时机 | 适用 | 不适用 |
|---|---|---|---|---|
| **自定义变量 + 服务器信号** | 客户端 Lua → 节点图 → 变量 | **异步**（1 帧起 ✓） | **状态类**：时间/名声/关卡/剩余邪恶/技能开关/名单… ✓ | 即时反馈 ✗ |
| ⭐ **`Invoke`** | 客户端 Lua ↔ 客户端 Lua | ⭐ **当帧同步** | **即时反馈**（消息/滚动日志/提示条 ✓）· **指令**（点击→主控 ✓）· **整条状态串** ✓ | 需要"控件自动绑定"的场合 ✗ |
| **黑板文本框** | 客户端 → 客户端 | 当帧（但**重画时机不定** ✗） | 调试观察 ✓ | 生产期交互 ✗ |

> **选型口诀**：**"要当帧看到"⇒ `Invoke`** ✓；**"状态够用"⇒ 变量+信号** ✓；**"只是给人看"⇒ 黑板** ✓。

## 3. ⭐ 节点图信号联动（重点 —— 后续会有"全数据类型基准图" ✓）

### 3.1 服务端信号管理器：**按"数据类型"建信号**（不是按字段 ✗）

《侦探杀》里最终建了 7 条（真机 `.gil` 字符串核对 ✓）：

```
侦_整数          参数：名称(字符串) + 数值(整数)
侦_字符串        参数：名称(字符串) + 数值(字符串)
侦_布尔值        参数：名称(字符串) + 数值(布尔)
侦_整数列表      参数：名称(字符串) + 数值(整数列表)      ← 覆盖（一次设完）
侦_整数列表_新增 参数：名称(字符串) + 数值(整数)          ← 追加
侦_字符串列表    参数：名称(字符串) + 数值(字符串列表)    ← 覆盖
侦_字符串列表_新增 参数：名称(字符串) + 数值(字符串)      ← 追加
```

### 3.2 节点图：**通用"按名字设变量"**（最大的红利 ✓✓）

```
监听信号(侦_整数) ─┬─ 名称 ─→ 设置自定义变量.变量名
                   └─ 数值 ─→ 设置自定义变量.变量值
                              目标实体 = 关卡实体（写死 ✓ 别用"事件源实体" ✗）
                              是否触发事件 = 是 ✓
```

⇒ ⭐ **加字段完全不用改节点图** ✓：只要①变量在组件里建好 ✓ ②发送端发"名字+值" ✓ 即可 ✓
（我们靠它一次把 **3 → 12 个字段**搬完 ✓ **零编辑器改动** ✓✓）

### 3.3 五条必须做对的细节（错一条就静默失效 ✗）

| # | 细节 | 错法 |
|---|---|---|
| 1 | **参数顺序**与服务端信号管理器**逐字一致** | 顺序反了 ⇒ 名称/值互换 ⇒ 静默写错变量 ✓ |
| 2 | **目标实体 = 关卡实体** | 用「事件源实体」⇒ 客户端脚本发的信号**没有事件源** ⇒ 写不进去 ✗ |
| 3 | **是否触发事件 = 是** | 关了 ⇒ Lua 的 `RegisterCustomVariableChangedHandler` **不响** ✗ |
| 4 | 客户端发的信号**没有"事件源实体"** | ⇒ 图上要么直接指定关卡实体 ✓、要么用**「以 GUID 查询实体」**(GUID 硬编码 ✓ 但**换图会变** ✗ ⇒ 图上留注释 ✓) |
| 5 | 列表**只用"覆盖"** | "新增"是**追加**⇒ 每帧追加会**越滚越长** ✗✗ ⇒ 要么先清空再追加 ✓ 要么用覆盖 ✓ |

### 3.4 客户端发送 / 读取（API 零猜测 ✓）

```lua
-- 发（参数顺序 = 名称 → 数值）
local sig = game.ServerSignal("侦_整数")
sig:AddString("侦_关卡")      -- 名称（字符串）
sig:AddInt(3)                 -- 数值（整数）
sig:SendSignal()
-- 其他：AddFloat / AddBool / AddString / AddIntList / AddStringList / AddVector3
--       （列表用 AddIntList / AddStringList ✓ 一次带走一整组 ✓ 必须是"每次发完整表"✓）

-- 读（客户端**能读不能写** ✓ 读到的是**带类型**的值 ✓）
local v = game.GetGlobalCustomVariableValue(Enum.CustomVariableEntityType.Level, "侦_关卡")

-- 监听变化（真机：**回调确实实时响** ✓ 但 **不带值** ✗ ⇒ 回调里再读一次 ✓）
script:RegisterCustomVariableChangedHandler(Enum.CustomVariableEntityType.Level, "侦_关卡",
    function(et, name) local now = game.GetGlobalCustomVariableValue(et, name) end)
```

**真机确认的事实**：
- ⭐ 客户端 Lua **能读** ✓ **不能写** ✗（8 个候选 setter 名全 nil ✓）
- ⭐ `Enum.CustomVariableEntityType` 有**三个成员**：`Level` / `PlayerSelf` / `AvatarSelf`（依 `api-client-ui.md` ✓）
  客户端 `PlayerSelf` 可读：已有《侦探杀》记录，且 2026-10-18 用户确认运行的对话/任务工程多处实际使用；`AvatarSelf` 在通用解析器中有支持分支，具体角色变量读值仍需实例证据。按数据归属选 Level / PlayerSelf / AvatarSelf，不能把“只验过 Level”当限制。详见 [对话工程参考](dialog-template-patterns.md)。
- 整数取不到 = **−2147483648** ✓；同一实体**不许重名** ✓；单实体运行时变量上限 **500** ✓
- ⭐ **控件可以直接绑变量** ✓（文本框插 `{1:lv.变量名}` ✓ / 进度条 ✓ / 开关(布尔 ✓) / 按钮次数 ✓ / 计分板 ✓）⇒ **零代码刷新** ✓
  ⚠️ `{` `}` 是特殊字符 ⇒ 脚本往文本框写字时别混花括号 ✓

## 4. ⭐ `Invoke` 直推（即时反馈与指令的正解）

```lua
-- 发送方（任意客户端脚本 ✓ 只要拿得到对方脚本对象）
local c = ROOT:GetScript(1073741838)          -- mappingId（从 .gil 的 mappings[] 读 ✓ 别手抄 ✗）
if c ~= nil and c.alive then
    c:Invoke("SetMsg", msg)                    -- ⚠️ 被调函数必须是**全局**（不加 local ✗）
end
```
```lua
-- 接收方：全局函数（Invoke 才能找到 ✓）
local msgPush = nil
function SetMsg(s) if type(s) == "string" and s ~= "" then msgPush = s end end
-- 渲染时**直推优先**（兜底保留旧来源 ✓ 删控件也不坏 ✓）
local mnow = msgPush or tostring(t.msg or "")
```

**真机验证**：指令通道 8/8 全 `Invoke 直达 ✓` 零失败 ✓（`t1_kb_cmd` 因此可退休 ✓）。
**收益**：**当帧生效** ✓（黑板是"每帧轮询控件"⇒ 最快 1 帧 ✗）。

### ⚠️ 两个"静默失效"级坑（今天各烧掉一轮以上，务必照抄规矩）

**坑 A：守卫读了一个不存在的名字 ⇒ 整段功能静默死掉** ✗✗
```lua
local elog = ...            -- ← 凭记忆写的名字；本作用域根本没有它 ✗
if elog ~= nil and elog ~= "" then    -- Lua 读未定义名 = nil ✓ **不报错**
    ...推送...                          -- ⇒ 永远不执行 ✗✗
end
```
- **症状**：功能**完全没用** ✓ 而其余日志/门禁**全绿** ✗（`check-lua-scope.mjs` 只能抓"声明在后面的 local" ✓ 抓不到未定义全局 ✗）
- **规矩**：守卫里的名字**必须是本作用域真有的** ✓；要拼就 `local x = <现算>` ✓
- **一秒定位法**：在**守卫内侧**打一行日志 ✓（这次就是靠"该出现的那行**一行都没有**"破的 ✓）

**坑 B：`Invoke` 必须推给**真正的渲染者** ✗
- 我们按模块名猜（board / view 都可能画日志 ✗）推了过去 ✓ ⇒ **不报错也不生效** ✗（推送日志还都正常 ✓ 更容易误判成"修好了" ✗）
- **规矩**：先 `grep` **渲染点**（`t.elog` / `setText(` / 字段名 ✓）**确认真身** ✓ 再决定推给谁 ✓ —— **不按模块名猜** ✗
- **多推几个无害** ✓（哪怕不是渲染者 ✓）但**必须包含那个正主** ✓

## 5. 状态串的终极形态（让黑板控件彻底退休 ✓）

黑板**不必**逐字段搬 ✓ —— 把**整条状态串**换成 `Invoke` 推过去即可 ✓：

```
① 三个读端各装接收端：  local statePush = nil
                        function SetState(s) if type(s)=="string" and s~="" then statePush = s end end
② 读端解析源换成：      raw = statePush or boardState.text or ""     ← 控件只当兜底 ✓
③ main 推送：           Invoke("SetState", txt) 推给三个读端（只在串变化时 ✓ 失败只打日志 ✓）
④ 创作者删控件：        t1_kb_state ✓ + t1_kb_cmd ✓
```
⇒ 一次到位 ✓：**名单 / 格文案 / cells / judge / camp / state… 全部一起脱离黑板** ✓（它们在串里 ✓）

⚠️ **删控件前必须补的护栏** ✗：读端常有 `if boardState == nil then return end` ✓ ⇒ 一删控件就**整块不渲染** ✗✗
⇒ 改成 `if boardState == nil and statePush == nil then return end` ✓

## 6. 安全迁移顺序（每一步都可回滚 ✓，别跳步 ✗）

1. **加新路**（变量声明 + 节点图分支 + 发送端 ✓）—— 读端**不动** ✓
2. **真机验证**（日志里"命中数"应上升 ✓）⇒ 不通过就地回退 ✓
3. **读端"提前布点"**：新值**优先**、旧值**兜底** ✓（变量/直推不存在 = 纯 no-op ✓ 零风险 ✓）
4. **即时类字段改直推** ✓（消息 / 滚动列表 / 提示条 ✓）
5. **换成"整串直推"** ✓ + 补删控件护栏 ✓
6. **创作者删控件** → 再跑一局确认 ✓
7. **最后**才删旧代码 ✗（回退能力保住到最后一步 ✓）

## 7. 验收判据 / 取证纪律（今天踩过的）

| 项 | 口径 |
|---|---|
| **命中数** | 读端打 `变量通道命中 N 个字段`（只在**命中数变化**时打 ✓ 不刷屏 ✓）—— **N 从 0 跳起来 = 通道真的通了** ✓ |
| **推送是否到达** | 接收端打一行（如 `直推 事件日志 N 条`）✓ —— "该出现却没出现"是最强的定位信号 ✓ |
| **deploy ≠ 进游戏** | 必须 `deploy → 编辑器存盘 → 试玩` ✓；用 `.gil` 的 mtime vs 活文件 mtime 判"存没存盘" ✓ |
| **`.gia` 落盘不稳** | 实测 5 次里 3 次没落 ✗ ⇒ **"日志里没有"不能当"功能没跑"** ✓；用 `miliastra_playtest op=status` 的 `localGia` 判 ✓ + **截图**兜底 ✓ |
| **部署必带 `level`** | 否则会写错关卡（真发生过：差点覆盖别的玩法的同名脚本 ✗） |
| **门禁** | 改完先跑 `check-lua-scope` / `check-lua-style --baseline` / `check-ui-contract` ✓，error 红或基线变差 **不许 deploy** ✗ |
