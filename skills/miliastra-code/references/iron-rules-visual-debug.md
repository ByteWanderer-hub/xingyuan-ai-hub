## 一级铁律（可机械判定）

### V1. 图片资产 id 与控件模板 id 严禁混用
- `6 位数字`（如 `100001` / `105034`）= **图片资产** → `SetImage(Enum.ImageSource.StaticReference, id)`。
- `1073742xxx`（10 位）= **客户端控件模板** → 必须 `game.InstantiateClientUIControl(id, parent)`。
- **症状**：用 `SetImage` 塞模板 id ⇒ 画面上出现 **「?」占位符**（不报错、不警告）。
- **扫描动作**：产物里 `grep -n "SetImage"`，第二个参数 ≥ 6 位即打回。

### V2. ★ 复合模板（带子控件的模板）实例化后**禁止 `sanitize()`**
- 真机实测（`1073742519` 场上所有人数比例，11 个子控件）：
  | 是否 sanitize | 结果 |
  |---|---|
  | **调用** `sanitize(node, 1)` | **整卡不显示**（子控件 11 个全在、`visible=true`、`active=true`、`scale=1`、位置尺寸正确、`sibling` 正常 —— **就是不画**） |
  | **不调用** | 正常显示 ✓ |
- 单图角图（如 `1073742182`）加不加都正常 ⇒ 历史代码里"全量 sanitize"一直没暴露问题。
- **扫描动作**：`grep -n "sanitize("`，若它作用在 `pairs(ROLE_ART)` 这类**混合集合**上 ⇒ 打回，改成**白名单：只对单图模板调用**。

### V3. 几何只按官方 API 读，别用编辑器字段名
- 正确：`GetAnchoredPosition()`（返回 x, y）、`GetSizeDelta()`、`GetSiblingIndex()`。
- **`posX / posY / width / height` 是编辑器字段，真机 Lua 侧为 `nil`** —— 读到 `nil` **不代表没设置**（本人为此白查两轮）。

### V4. 位置口径：有父层级 = 相对**父层级中心**的偏移
- 文档原文：`无父层级时，以画布左下为原点；存在父层级时，设置与父层级中心的相对偏移`。
- 全部控件都在容器节点下 ⇒ **默认就是"相对父中心"**。（设计坐标 → 引擎坐标的换算函数必须先确认父容器中心与画布中心是否重合。）

### V5. 层级：索引越大越靠上（文档写"通常"）
- `SetSiblingIndex(i)`：`i` 越大通常越靠上；**要精确插位就用它**。
- `SetAsLastSibling()` = 移到同级末位（**别拿它当"显示不出来就提层"的万能药**）。
- 文档明写：**"复用列表生成的列表项不保证同级排序结果稳定"**、**"使用组合布局时应验证实际显示结果"**。

### V6. 画布上摆的实例：**建不了，但找得到**
- `InstantiateClientUIControl` 只能建**模板（存为模板的那条）**；摆出来的实例是作者内容，脚本建不出来。
- 但脚本可以：遍历 `parent:GetChildren()` → 按 `name` 匹配 → `GetChild("子控件名")` → 改 `.text`。
- ⇒ **复合模板最稳的落地方式**：创作者摆实例 + 脚本按名字找到并填数据（真机验证通过）。

### V7. 画布实例默认在**脚本控件之下**
- 作者内容先生成、脚本控件后生成 ⇒ 脚本的全屏底板会把画布实例盖住。
- 修法：找到它之后 `SetAsLastSibling()` / `SetSiblingIndex(...)` 提层（真机验证：提了立刻可见）。

### V8. 一批同款控件要显示不同内容 ⇒ 改**引用实例内部**（2026-10-01 真机通过）
- **结构**：`ClientUIReferenceControl`（引用模板 X）→ `ClientUIPresetButtonControl` → **4 个状态容器**（`不可用 / 按下 / 悬停 / 默认`）→ 每个状态一套 `[图片 + 文本框]`。
- **能进去**：`GetChildren()` 能拿到被引用模板的实例子树、`referencedPrefabIndex` 可读（原 `unknown` ⇒ 转 `observed`）。⇒ 一批同款控件**可以各自显示不同内容**。
- **三条规矩（缺一条就是真机 `total=10 done=0`）**：① 递归深度 **≥3（给 4）**；② **整棵子树全刷**（四态各一套文本框，只刷一套 ⇒ 一按/一悬停就变回原值）；③ **每条写入读回校验**（给没有 `text` 字段的控件写 text 是**静默无效**）。
- 反面教材：v2 用 `INNER_DEPTH=2` + "找到第一个能写 text 的就停" ⇒ 一个都没刷上。
- 完整案例与可照抄代码：[`case-reference-control-numkey.md`](case-reference-control-numkey.md)；代码形状：[`code-patterns.md`](code-patterns.md) §11。

### V9. 建不出来的**永远是子节点**，不是"组" —— 模板号怎么认（2026-10-01 真机）
- `.gil` 里 **无父节点**的客户端控件组 / 模板 ⇒ **可建**（实测 `1073742456`「密码解密」创建成功）；**组内的子节点** ⇒ `InstantiateClientUIControl` **返回 `nil`**（不抛异常，只返回 nil）。
- ⚠️ `miliastra_map op=clientui` 的 `likelyTemplates` **只列"无父节点 + 名字是控件类型名"**的记录 ⇒ 自定义名的组（`密码解密` / `数字键`）**一条都不会出现**，**别据此判"不能建"**；要看 `records` 里的 `parent` / `children`。
- 失败必须分两种记：`ok=false`（调用异常）vs **`返回 nil`**（号不对 / 没存为模板）—— 后者零报错，**只有日志能区分**。
