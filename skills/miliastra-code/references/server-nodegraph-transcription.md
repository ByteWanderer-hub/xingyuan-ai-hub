# 千星服务端节点图转写与原位注入

适用于把已保存的千星奇域服务端节点图转写成可维护代码，并在已确认范围内生成或更新节点图。单点常量修复通常可直接改编辑器或做可验证的单字段补丁。只有任务要求转写整图时才重建节点数组。

## 1. 固定目标和原行为

- 先核创作者指定的地图与目标图。分别记录地图 ID、图名与图 ID、图类别、挂载位置和当前保存指纹。区分编辑器提示、最近活文件推断、导入副本和真正在跑的地图。状态图需要核状态配置与挂载，实体挂载表没找到不能判作未挂载。
- 以编辑器实际存盘为基线，读取来源、SHA-256、大小和必要依赖。分别备份源 GIL、目标图原始记录和相关声明证据。导入或另存可能重分配图、状态、信号、实体及界面 ID，按新存档逐项核对，不能沿用旧 ID 猜测。节点壳、类型特化的内核 ID、复合对外声明与实际实现图使用不同身份。
- 从所有入口沿实际执行与数据引脚追可达行为，再决定是否展开复合。记录动作次序、执行扇出、实体归属、显式读写、通知、信号参数及返回、字典原地变更、状态/计时器边界和无外部消费者的孤立逻辑。名称、界面和业务文案仅用来定位。
- 把依赖读取的时机写进合同。原执行边的深度优先次序与异步运动的完成次序要分开。连续添加运动器的执行口返回时，运动可以尚在进行。数据引脚可能在消费时求值，TS 的 `const` 不保证生成局部快照。付款、广播或其他可能影响后续读取的动作前，需要按原图在执行流中显式保存值。保留随机抽样次数、顺序、阈值等号分支，以及玩家全局计数和单实体状态的差别。

## 2. 编译并保留原生契约

- 可选用 [genshin-ts](https://github.com/josStorer/genshin-ts) 等外部编译器。先核本机可用版本、安装包来源、目标图类型、经典或超限模式和实际可编译节点。版本号相同也要核对已安装包的实现，分支源码里的能力不能直接当作本机能力。固定版本，用同类别的最小事件图跑通 TS → 中间产物 → GIA，读取生成类别和节点。不要自动升级；常规 Lua 工作与只读图检查无需该编译器。按锁定版本核验 GIL → TS 的逆向能力和保真范围。未证实可无损转写时，先写好原行为合同。
- 将入口分派、业务判定、效果和结算分模块编译到同一张图。能从复合实现确认等价的逻辑可转写成常规 TS。编译器无法等价表达的部分，先保留失败证据，再用当前原生样本做窄适配，例如未连的空实体输入，或现有信号的节点声明、版本和复合引脚编号。按名称、节点类型、引脚契约和预期数量校验，避免按可能变化的节点序号猜模板。发现不符停止构建；回读确认无探针、占位和悬空引用。
- 新增图内状态要合并到图黑板并回读名称、类型、初始值和公开性。保留原图变量、挂载、图类别及仍有消费者的元数据。先核玩家和关卡是否已有变量或声明，禁止以编译占位代替原生声明。按业务区排版，检查节点数限制和节点框而非只检查坐标原点。使用当前版本或样本的保存边界，重开回读能补证编辑器是否截断。
- 修改已有图时只替换经批准的图记录。保留图外原始字段；有未知字段时，普通解析再编码不能证明无损。区分编译器生成的 GIA、包含适配的交付 GIA、离线候选 GIL 和实际活文件。生成图与候选图的解码内容一致，不等于二者字节序列一致。

## 3. 用候选图验证差异

- 固定原图、候选图和地图指纹。校验编译产物、交付 GIA 和候选 GIL 的目标类别、执行和数据连线、常量与声明、变量、挂载、数目和布局边界；逐字段确认目标记录之外的数据原样保留。
- 对照最终二进制的引脚或等价解析，使用可控的输入、随机和事件时序重放原图与候选图。逐条比较动作、执行次序、目标实体、通知开关与参数。给不同查询路径不同实体或不同初始值，避免同一个测试替身把归属错配遮住。包含错误入口、阈值边缘、重复触发、取消和可有多种次序的同帧事件。预期差异由本轮需求明确列出。
- 将类型检查、编译、静态回读、离线轨迹、实际写入、编辑器重开和真机验收分别记录。受控替身中的重入与通知扰动可证明快照和分支对这些输入的反应，宿主是否以同样方式调度仍需观察。原位写入与磁盘回读成功不能推出真机玩法通过。

## 4. 更新已存在的图

- 已存在且身份明确的普通测试副本，在已授权且流程支持时优先更新对应图，避免每次把整张地图作为新存档导入。新图的官方注册、声明或挂载另按编辑器或经验证的工具流程办理。说明使用的是官方或已接入的工具 API，还是在用户授权下直接改写本地存档记录。两种写入方式均须验证。
- 写入前备份目标目录的实际依赖，包括 GIL、存在时的 GILH/GIS 或切片、外部 Lua 和其他必要文件。对协作或带切片的存档，先核哪个文件会被编辑器或协作系统采用，不能只替换 GIL 推断已生效。
- 按当前 GUI 授权，由创作者或助手保存并切出目标地图或关闭编辑器。已明确授权且条件持续满足时直接执行。保存后重新读取活文件指纹。若与审核基线不同，冻结最新版本，检查目标图与依赖变化，从最新源移植已审内容并复核差异。目标图有新编辑时先判断能否安全合并，避免覆盖创作者变化。
- 写入时显式约束地图路径、图 ID、源和候选指纹。采用同目录临时文件和原子替换，替换前再次校验活源。落盘后回读目标图及地图指纹、校验图外记录和需保护文件，留下清单与显式回滚路径。回滚同样验证当前指纹，防止把后续改动回退。
- GUI 操作只在创作者授权范围内进行。若目标由创作者操作，则交付重新打开同一存档的步骤；尚未试玩时记录待验。

## 脱敏案例：翻币的视觉和运动时序

硬币显示同一面时，先看模型本体和饰件平面的法向，并区分真实读到的角度和肉眼推测。平躺硬币绕竖直轴旋转 180° 只改变图案朝向，无法交换正反。将收益状态与可见姿态分别核对，修正视觉映射时保留原收益规则。

同一实体的匀速旋转与朝向目标旋转互斥，改名无法绕开。可按初始转向、匀速翻转、落地校正串行推进，线性运动仅在平台允许的组合中并行。检查停止事件是否也由冲突或删除触发。用阶段门控抑制重复回调，取消前保存旧阶段并先失效，再停本图拥有的运动器。预算以实际状态寿命和效率为准，保证关键回调可达，保留原位移、总转角及收益时点。该案例有原位写入和离线回读证据，最终视觉和宿主时序仍需真机复验。
