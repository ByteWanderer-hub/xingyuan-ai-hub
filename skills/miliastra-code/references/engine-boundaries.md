# 千星奇域 引擎实测边界清单

> **性质**：历史真机记录与后续修正按行标来源；用户确认运行的外部范例不是本轮现场实测。冲突时保留旧现象，撤销过度推广的结论。
> 证据等级标注：`observed`（真实运行观察到）/ `observed-弱`（观察到但样本少）。
> 用途：写任何千星域 UI 脚本前过一遍——这些全是"文档不会写、代码不报错、只是不工作"的类型。

## 实现模式备忘（同批实测沉淀）

- **行段合并渲染**：同色连续格合并为一个拉伸矩形（Stretch + tintable 资产 100001 染色），110 控件跑通俄罗斯方块全程——像素画/帧动画的同一技术底座。
- **槽位缓存**：每槽位缓存 {vis,x,y,w,h,colorIndex}，只对变化调 setter——移动/旋转一次只碰少数控件。
- **故障聚合**：OnUpdate 全体包 pcall，任何异常转 `GAME FAULT BEGIN/END` 块（带行号），**绝不静默死亡**——本次 3 轮排障全部靠它一轮定位。
- **按键监听**：`宿主控件:AddKeyEventListener(事件值, callback)`，callback 返回 true 表示消费；注册失败要报出试过的枚举候选（枚举不可枚举，报错信息就是唯一的勘探手段）。
- **状态重置清单**：换关卡 / 重开 / 重生时逐项过——**位置 / 速度 / 相位 / 计时器 / 布尔标志 / 分数语义**。实测教训：loadLevel 换了关卡数据却没重置玩家位置 → 出口判定连续命中、4 关瞬间串过（2026-09-16 连关 bug，用户报告"到终点直接4关全过"）。
- **调用与定义同步**：给脚本加"调用"时确认**函数定义在同一文件里**——实测教训：双相版重写时丢了 sendScore 函数定义却留下调用，nil 调用故障（pcall 保险接住，一轮定位）。

## 附：客户端控件实例**不允许挂自定义字段**（2026-10-05 实测）

**现象**：`ctrl.myField = anything` ⇒ 真机直接报错并中断该帧：

```
game_01:1720: cannot set animTween, no such field
stack traceback:
    game_01:1720: in function 'grow'
    game_01:1733: in function 'playGasAnim'
    game_01:2227: in function 'onDoorActivated'
```

**性质**：控件是**受控对象**（不是普通 Lua table）⇒ 只能读写**平台声明的字段与方法**，**不能**当黑板用。

**正确做法**：把"与某个控件相关的自定义状态"（Tween 句柄、动画进度、缓存矩形…）存在**自己的表**里，用槽位 / 房间下标索引：

```lua
-- ✗ 错：往控件上挂
ctrl.animTween = game.Tween(ctrl, { sizeDeltaX = 0, sizeDeltaY = 0 }, 0.35)

-- ✓ 对：存在自己的表里
VIEW.gasTween = VIEW.gasTween or {}
VIEW.gasTween[ri] = game.Tween(ctrl, { sizeDeltaX = 0, sizeDeltaY = 0 }, 0.35)
```

**为什么容易误判**：把状态存在**自己 new 出来的槽表**里（如 `VIEW.shapeSlots[s] = { text = c, tween = t }`）是**合法**的
⇒ 同一份代码里"有的地方能存、有的地方不能存"，看起来像玄学。**判据是：宿主是不是控件本身。**

**同源条目**：与 §V3（几何只用官方 API 读）、`miliastra-ui` §1.3（几何读不回来，布局只能算）属于同一类事实 —— **控件是受控对象，不是普通 table**。
