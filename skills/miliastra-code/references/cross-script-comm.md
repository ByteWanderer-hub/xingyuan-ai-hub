# 跨脚本通信（客户端脚本之间怎么传数据）

> 归属：`miliastra-code`｜依据：官方《客户端控件和客户端脚本》八(2) ＋ 本机 `api-client-ui.md`
> ＋ 2026-10-08 两次踩坑｜＋ 2026-10-11 **官方 `GetScript` + `Invoke` 真机走通**（§5）
> **结论一句话：官方通道可用（两个硬条件见 §2）；「控件黑板」仍是工程首选 —— 不依赖挂载点匹配、不受脚本数限制。**

## 1. 官方怎么说的（先摆依据）

> 《客户端控件和客户端脚本》**八、客户端脚本的使用规则 → (2) 调用脚本映射 ID**：
> **可以通过脚本映射 ID 在脚本中调用其他脚本**，可通过 `scriptMappingId` 在 API 文档中查询接口

⇒ **跨脚本调用是官方支持的** ✓（所以"做不到"这个结论是错的）

## 2. 这两个接口的实测边界（两次踩 + 一次走通）

### △ `GetScript(scriptMappingId)` —— 只取得到「挂在这个控件上」的脚本

API §(4)「脚本访问」（**这一段是"控件的方法"**）：

| 接口 | 官方说明 |
|---|---|
| `GetScriptByPath(scriptPath)` | 按路径获取**挂载**脚本 |
| `GetScript(scriptMappingId)` | 按脚本映射 ID 获取脚本 |
| `GetScripts()` | **获取控件上全部脚本** |

关键看 `GetScripts()` 的措辞："**控件上**全部脚本" ⇒ 这一组都是**"挂在这个控件上的脚本"**。

⇒ 真机实测：`面板控件:GetScript(常驻脚本的映射id)` → **返回 `nil`**（常驻脚本不挂在面板上，取不到是**正确行为**）。

★ **2026-10-11 正向实测补充**：`GetScript(mappingId)` **对「挂在同一个控件上的另一个脚本」确实有效** ——
`根控件:GetScript(常驻脚本的映射id)` **成功返回实例**，且 `.alive == true`（§5 有完整证据链）。
⇒ 所以这条要写准：**不是「取不到别的脚本」，而是「只取得到挂在这个控件上的脚本」**。
想取到 ⇒ **先拿对控件**：找到那个脚本真正挂载的控件，再对它 `GetScript`。

### △ `script:Invoke(funcName, …)` —— 找的是「**本脚本内环境**的全局函数」

文档原文："在 UI 脚本内定义的全局方法（**脚本内环境**）中调用**当前脚本**中名称为 funcName 的函数"。

⇒ 真机实测（2026-10-08）：在**自己的 `script`** 上传**别的脚本**里的函数名时，`pcall` **成功、什么都不做**（**静默**）。
⚠️ **这比报错危险**：调用端看到 `pcall` 成功就以为自己成功了，**连降级都不走**。
⇒ **判据必须是"接收端有没有反应"**，不是"调用端有没有报错"。

★ **但它能调通别的脚本 —— 前提是「先拿到那个脚本的实例」**（2026-10-11 真机走通，见 §5）：

```lua
local sc = 目标控件:GetScript(目标脚本的 mappingId)   -- ① 先取到 Script 实例
sc:Invoke("全局函数名", 参数…)                        -- ② 再对这个实例 Invoke
```

**两个硬条件，缺一即静默失败**：

1. **`GetScript` 的接收控件，必须真的挂着那个脚本**（§2 上一条：只取得到挂在这个控件上的脚本）
2. **目标函数必须是【全局函数】** —— 写成 `function 名字()`，**不带 `local`、也不是表的字段**
   （文档口径就是"脚本内环境的**全局**方法"；写成 `UI.某函数` 或 `local function` 都找不到）
   ⚠️ 这一条件**目前是"与观测一致"的最优解释，尚未单独做对照实验**（§5.4）。

## 3. ✓ 正解：控件黑板

**前提接口**（`api-client-ui.md` L171-172，`game` 表）：

```
game.GetClientUIRoots()  → ClientUIBaseControl[]  获取全部 UI 根控件
                                                   （= 客户端控件容器画布中的**默认容器节点**）
game.FindClientUIRoot(nodeName) → ClientUIBaseControl   按名字查 UI 根控件
```

⇒ **两个脚本都能拿到同一个"根"** ⇒ 在根下面按名字找到**同一个文本框** ⇒ 就能互传字符串 ✓
（这也是本域**唯一有真机先例**的跨脚本通道 —— `case-detectives-6scripts.md` 的 6 脚本工程用的就是它）

### 落地形状

```lua
-- 两个脚本里各放一份（同一个名字！）
local BLACKBOARD_NAME = "天赋黑板"

local function findBlackboard()
    local ok, roots = pcall(function() return game.GetClientUIRoots() end)
    if not ok or type(roots) ~= "table" then return nil, "GetClientUIRoots 失败" end
    for i = 1, #roots do
        local r = roots[i]
        if r ~= nil then
            local c = directChild(r, BLACKBOARD_NAME)
            if c == nil then c = findByChild(r, BLACKBOARD_NAME, 4) end
            if c ~= nil then return c, nil end
        end
    end
    return nil, "没找到控件「" .. BLACKBOARD_NAME .. "」"
end
```

- **写者**（会被销毁的那个脚本）：`bb.text = "键=值;键=值"`
- **读者**（常驻脚本）：每帧读 `bb.text`，非空 → 解析 → 处理 → **清空**

### 七条纪律

1. **一个黑板只有一个写者** —— 两个脚本抢着写会互相覆盖（`case-detectives` 的分工原则）
2. **必须是编辑器预置的控件** —— 跨脚本按名字找，运行期动态建的改名**不保证**能被别的脚本找到（`engine-boundaries` #18）
3. **读完要清空**，并处理"清空失败"（失败时记住内容，别重复处理）
4. **数据用字符串**（`键=值;键=值`），别赌复杂类型能过界面边界
5. **解析要 pcall**，坏数据不能把读者搞死
6. ★ **`local` 不跨脚本共享** —— 别指望"A 脚本里定义的工具函数，B 脚本能直接用"。
   每个脚本**各写各的**（复制一份工具函数是正常的）。真机现场：我在**全局脚本**里直接用了
   **面板脚本**里的 `directChild` / `findByChild` ⇒ 在本脚本里全是 `nil`
   ⇒ `OnUpdate` 每帧 `attempt to call a nil value`，一局撞了 **960 次**。
   （这条同时解释了为什么"Lua 全局变量跨脚本共享"的传闻**不可依赖** —— 真机禁止运行期给全局赋值。）
7. ★ **`game.GetClientUIRoots()` 在 `OnInit` 时可能返回空表** —— 真机第一次实测：**能调、不报错、数=0**
   （那时 UI 还没就绪）。⇒ **别在 OnInit 里下结论**，要**每秒重试**：
   拿到根 ⇒ 可用；试满若干次仍为 0 ⇒ 才判定"够不到 UI 树"。
   ⚠️ 顺带：判据别写成 `if 调用成功 then 打印"成功"` —— "数=0"也是调用成功，
   我第一版日志就把它写成"成功 ⇒ 方案可行"，**措辞直接误导了后面的判断**。

## 4. 什么时候需要它

典型场景：**界面脚本会随界面销毁，而数据要在那之后还活着**。
客户端**写不了任何持久地方**（真机禁止运行期给全局赋值）⇒
把"保管 + 重发"交给一个**常驻脚本**（挂在不会销毁的控件上，例如客户端控件容器的容器节点），
两个脚本之间用黑板对接。

## 5. 实验记录：官方 `GetScript` + `Invoke` 跨脚本调用（2026-10-11）

> **目的**：验证官方那句「**可以通过脚本映射 ID 在脚本中调用其他脚本**」到底能不能用、能用到哪一步。
> **工程**：关卡 `1074397191` · 账号 `341622797` · 6 条脚本映射
> **日志**：`.gia 2026-10-11_16-57-52_6128_341622797`（44 条记录，零 `首错=`）

### 5.1 实验装置

| 角色 | 文件 | `scriptMappingId` | 说明 |
|---|---|---|---|
| **调用方** | `开始游戏按钮.lua` | 1073741831 | 脚本挂在预设按钮「开始游戏」上 |
| **目标** | `监听信号开关UI.lua` | **1073741829** | 由调用方按**根控件**去取 |

调用方（`开始游戏按钮.lua`，`onClick` 内）：

```lua
local roots = getRoot()                     -- = game.GetClientUIRoots()[1]
local sc = roots:GetScript(1073741829)      -- ★ 目标脚本的 scriptMappingId
if sc == nil then
    fail("取脚本失败", "根控件没有挂 1073741829")
    return
end
if sc.alive then print('脚本已挂载') else print('脚本未挂载') end
local ok, panel = pcall(function() return sc:Invoke('SetActive', 1073742456, true) end)
print('开始游戏按钮执行了')                  -- ⚠️ 无条件打印，零鉴别力（见 5.3）
```

目标端（`监听信号开关UI.lua`）—— **★ 关键差异：写成【全局函数】**（`function` 前没有 `local`，也不是表的字段）：

```lua
function SetActive(index, active)   -- 全局函数；同文件里另有一份同义的 UI.SetActive 副本
    ...
end
```

### 5.2 观测结果

| 观测 | 判定 |
|---|---|
| 日志 `i=19` → `脚本已挂载` | ✅ `GetScript(1073741829)` **返回了实例**，且 `.alive == true` ⇒ 不是 nil |
| `1073741829` 与 `.gil` 映射表逐字对上 | ✅ 证明取到的**确实是目标脚本**，不是碰巧拿到了别的 |
| **创作者真机点按钮 → 目标 UI 真的打开了** | ✅ **接收端的行为结果** ⇒ 这次 `Invoke` **确实执行到了目标脚本的全局函数** |
| 归因排查：`1073742456` 还有谁在建？ | ✅ 另一个用它的是 `数字键测试.lua`，但它注释明写「**自己不建**」、只在收到服务器信号「盒子解密」时才建（`数字键测试.lua` L7 / L43 / L230）；点按钮不发那个信号 ⇒ **唯一来源就是 `监听信号开关UI` 的 `SetActive`** |
| 日志 `i=38` → `开始游戏按钮执行了` | ⚠️ **无鉴别力** —— 它写在 `Invoke` **之后且无条件**，成功失败都会打印（**别拿它当证据**） |
| 目标端 `SetActive` 全程无日志 | ⚠️ 机器可读证据缺失 —— 该函数**成功路径不打任何日志**，本次靠**画面**定案 |

### 5.3 结论（**严格分轴，不许合并**）

| 结论 | 证据等级 |
|---|---|
| `控件:GetScript(mappingId)` 能取到**挂在这个控件上**的其他脚本实例，返回对象可用（`.alive` 可读） | **observed**（5.2 前两行互证） |
| 取不到 ⇒ 那个脚本**不挂在这个控件上**（§2 那次 `面板:GetScript(常驻脚本id)` → `nil` 即属此类） | observed |
| `Script:Invoke('全局函数名', …)` **能执行到目标脚本** | **observed**（创作者真机画面：目标 UI 真的打开了；归因已排除，见 5.2） |

⇒ **官方那条路走得通**：`控件:GetScript(目标mappingId)` → `实例:Invoke("全局函数名", …)`，两个硬条件见 §2。
⛔ 但**判据仍然在接收端** —— 别把「调用端 `pcall` 成功」当成成功证据（§2 实测过它**静默成功、什么都不做**）。

★ **它和「控件黑板」怎么选**：

| | `GetScript` + `Invoke` | 控件黑板 |
|---|---|---|
| 官方依据 | ✅ 八(2) 明写 | ➖ 属工程实践 |
| 真机先例 | ✅ 本条（2026-10-11） | ✅ 6 脚本工程（`case-detectives-6scripts.md`） |
| 硬前提 | 得知道目标 `mappingId`，**且**脚本挂在你能拿到的控件上 | 需要一个编辑器预置的黑板控件 |
| 传参 | 直接传参、可拿返回值 | 只能传字符串（`键=值;键=值`） |
| 静默失败风险 | ⚠️ **高**（找不到函数不报错） | 低（读不到就是空串） |
| 适用 | **少量脚本、结构已知**的点对点调用 | **多脚本、要解耦**、界面会销毁而数据要活着 |

### 5.4 如果要留【机器可读】的证据（可选，一行）

本次是靠**画面**定案的。若要把 `Invoke` 也做成日志可查，在目标函数的**成功路径**加一行即可：

```lua
function SetActive(index, active)
    print("[目标] SetActive 被调到了 index=" .. tostring(index) .. " active=" .. tostring(active))
    ...
end
```

| 日志表现 | 结论 |
|---|---|
| 出现 `[目标] SetActive 被调到了` | ✅ 与本次画面观察互证 |
| 调用端 `ok=true`、目标端**没动静** | 那就是 §2 那条「**静默成功**」 |

★ **纪律**：
1. **跨脚本调用的判据永远在接收端** —— 调用端的 `pcall` 返回值**不能当证据**（§2 已证）。
2. ★ **待做的对照实验**：「目标函数必须是全局函数」这条**目前只是与观测一致的最优解释**，还没单独验证。
   要做就**保持其它一切不变、只改这一个变量**（`L2-V3`）：把 `function SetActive` 改成 `local function SetActive`，
   看是否变成静默失败。**在做成之前，别把它写成"已证"。**
3. **`GetScript` 要拿对控件**：先确认目标脚本挂在哪个控件上，再对它调 `GetScript`（§2 补充条）。
