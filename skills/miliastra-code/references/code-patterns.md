## 1. 音效（SFX）：平台只给你三个动作

**API 事实（2026-09-27 全文核对，不是推断）**：

```
game.PlayAudio2D(audioId: integer) -> integer   播放，返回音效实例 ID
game.StopAudio(audioInstanceId: integer)        停止指定实例
game.IsAudioAlive(audioInstanceId) -> boolean   查询实例存活
```
- **没有音量、没有音高、没有起止时间参数**（搜 `音量/Volume/Pitch/衰减/SetAudio` = 0 命中）。
- ⇒ 想"**只播 0~1 秒**"：播完**存实例 ID**，到点 `StopAudio` 掐断。
- ⇒ 想"**音量减半**"：脚本**做不到** ⇒ 只有两条路：① 创作者在编辑器里调**音效资源**本身的音量；② 换更轻的资产。
- 另外：预设按钮控件有 `clickAudioId` 字段、动效控件有 `playSoundEffect` —— 只想"点击有音"时比自定义播放更省事。

```lua
-- ⚠️ 位置铁律：任何会调 sfx() 的助手，必须写在 sfx **之后**。
--    写在前面 ⇒ `sfx` 解析成**全局 nil**（不是后面声明的那个 local）⇒ 一点就 `attempt to call a nil value`。
local SFX_BTN = 30148
local sfxFail = 0
local function sfx(id)
    local ok, err = pcall(function() game.PlayAudio2D(id) end)
    if not ok then
        sfxFail = sfxFail + 1
        if sfxFail <= 3 then                 -- 同一原因最多报 3 次：不静默、也不刷屏
            log("警告：音效 " .. tostring(id) .. " 播放失败：" .. tostring(err))
        end
    end
end
```

**随机池**（如"开局音从 10046~10050 随机取一个"）：

```lua
local SFX_START_IDS = { 10046, 10047, 10048, 10049, 10050 }
local sfxStartSeeded = false
local function sfxStart()
    if not sfxStartSeeded then
        sfxStartSeeded = true
        local okSeed = pcall(function() math.randomseed(os.time()) end)  -- Lua5.3 不播种 ⇒ 每次启动序列相同
        if not okSeed then
            log("提示：随机种子播种失败（仍随机，但每次启动序列相同）")
        end
    end
    sfx(SFX_START_IDS[math.random(1, #SFX_START_IDS)])
end
```
> `os.time` / `os.date` / `os.clock` 平台**可用**（不可用的是 `io.*` / `coroutine.*` / `string.dump`）。

**限时播放（"只播 0~1 秒"）**：

```lua
local sfxStopId, sfxStopT = nil, 0
local function sfxTimed(id, sec)
    local ok, inst = pcall(function() return game.PlayAudio2D(id) end)
    if not ok then
        log("警告：音效 " .. tostring(id) .. " 播放失败")
        return
    end
    if inst ~= nil then
        sfxStopId, sfxStopT = inst, sec
    end
end
-- OnUpdate(dt) 里：
if sfxStopId ~= nil then
    sfxStopT = sfxStopT - (tonumber(dt) or 0.016)
    if sfxStopT <= 0 then
        local okS = pcall(function() game.StopAudio(sfxStopId) end)
        if not okS then
            log("警告：音效掐断失败（到点）")
        end
        sfxStopId = nil
    end
end
```

## 2. 状态跳变检测：只响一次 / 只在"跨档位"时触发

不要为了一个音效往别人的函数里硬插点。**在每帧都在跑的那一处做跳变检测**，标记在每关初始化里重置：

```lua
local sfxShroudDone = false              -- 文件级（不是 build 里的 local！）

-- 每帧跑的地方（状态写入函数等）：
if not sfxShroudDone and shroudLifted() then
    sfxShroudDone = true
    sfx(SFX_SHROUD)
end

-- initBoard / freshStart 里：
sfxShroudDone = false
```

**"只在变差时才响"**（名声掉档，而不是每次扣分都响）：

```lua
local function repRank(w)
    if w == "糟糕" then return 1 end
    if w == "良好" then return 2 end
    return 3
end
-- 扣分**之后**（dmg 是负数，所以扣前值 = G.rep - dmg）：
if repRank(repLevel(G.rep)) < repRank(repLevel(G.rep - dmg)) then
    sfx(SFX_REP_DOWN)
end
```

## 3. UI 按钮四态：**每帧按同一份状态成对刷** ← 血泪

**创作者口径**：默认 **黑字白底**；鼠标在按钮上 / 按下 = **白字黑底**。

❌ **错误形状**（真机症状："点下一页时鼠标还在按钮上，却变成**黑字黑底**"）：
底板由"悬停进入 / 悬停离开 / 按下结束 / pressFlash"**四条分支各刷一半**，字色由另外两条刷 ⇒ 互相覆盖 ⇒ 底板黑了、字还没白。

✅ **正确形状**：每帧算一次"是否亮起"，**底板与字色成对 set**：

```lua
local lit = (bt.name == hit) or (bt.name == pressName and pressT > 0)
setImgColor(bt.name .. "Bg", lit and C_LINE or C_BAR)     -- 白底 → 黑底
setTxColor(bt.name .. "Tx",  lit and C_WHITE or C_TEXT)   -- 黑字 → 白字
```

配套两条：
- 按钮文字的**出生色**必须是默认态（`add(..., color or C_TEXT, ...)`）—— 出生色写错，第一帧就是错的；
- 按下反馈**不要再单独改底板**（`pressFlash` 只设 `pressName/pressT`），否则又变成两条路径。

## 4. 单文本框排"表格"：补全角空格

平台没有多列排版；**CJK 等宽** ⇒ 把术语**补足固定全角宽度**，释义自然对齐成一列：

```lua
b = "善恶　　善良 = 不该抓；邪恶 = 该抓（爪牙、叛徒）\n"
 .. "阵营　　老实人、搅局者（善良）｜爪牙、叛徒（邪恶）\n"
 .. "在场　　在板上 = 在场；只在身份名单里 = 不在场\n"
```
> 顺带：一条术语里塞两个概念（"在场 / 不在场"）会**破坏对齐** ⇒ 拆成单词条 + 释义里说明。

**要给某一行单独染色**（如"伪装"标红）：必须给它**独立的文本框**（大文本框没法局部染色）。新控件的名字要落在显隐的**前缀组**里（本项目 `showOverlay` 按 `ov/pk/cx/mx` 前缀显隐 ⇒ 新控件叫 `cxKwKey` 就自动跟着图鉴一起显隐，不用改名单）。

## 5. 平台没有圆角 / 没有实心圆

**核对结论（官方 API 全文）**：`Enum.ImageType` 只有 `Basic/Stretch`（**没有九宫格 Sliced**）；搜 `圆角/Corner/Radius/Rounded/Slice` = **0 命中**。

| 想要 | 做法 |
|---|---|
| **圆角矩形底** | 图片控件**边缘羽化**：`c.enableSoftEdge = true` + `c:SetSoftEdgeWidth(12, 12)` ⇒ 四边带四角一起淡出（不是硬矩形了） |
| **实心圆**（表盘 / 白底圆） | **多圈窄条拼**：每圈 N 段（12~16 段肉眼即圆），半径递减铺满；4 圈 × 12 段 ≈ 实心圆 |
| **环形 / 刻度 / 指针** | 每段一个图片控件 + `SetLocalRotation(0, 0, -math.deg(th) - 90)`；弦长 `2r·sin(π/N) + 2` 保证段间无缝 |
| 真圆角 | 只有**素材**一条路：让创作者给一张圆角矩形底图，换 `imageId` 即可 |

## 6. 颜色：**别按名字猜，先看 theme 的值**

实例（真机踩过）：`C_GOLD` 的实际值是 **青蓝 `{58,150,200}`** —— theme 里注释写明"名字是历史遗留"。
按名字当"金色"用 ⇒ 白底上发闷、深底上发黑（创作者原话："字用亮色"）。

⇒ 用色前 grep 一下 theme 的定义；**语义 token** 比颜色名可靠：
- 红 `C_BAD` 的约定是"**只用于危险 / 坏人 / 失败**"（给"伪装"标红正好合适，别拿它做普通强调）；
- 深底取亮色、白底取深色的**成对**关系要写进注释，避免下一轮又反过来。

## 8. 音效该接哪些点（按"玩家会在什么时候突然安静"找）

| 类别 | 时长 | 例子 |
|---|---|---|
| 交互反馈 | 0.2~0.6s | 翻牌揭晓 / 点格子 / 按钮点亮 / 图鉴翻页 / 详情切人 / **全局按钮**（点非格子的地方统一一个音） |
| 状态氛围 | 1~3s | 钟楼敲响 / 名声掉档 / 遮蔽被掀开 / 进关卡·换关 |
| 结局 | 3~6s | 案子解决 / 判负 / 抓人阶段开始 |
| ⛔ 不要 | — | **高频节奏音**（"每 N 小时"这类）—— 创作者实测：加完当场要求移除 |

**全局按钮音的省事写法**：在点击入口一处播（`if cell == 0 then sfx(SFX_BTN) end`），不给每个按钮单独接；格子另有音时用 `cell == 0` 排掉，避免两个音糊在一起。

## 9. 跨脚本调用：先定位宿主，再调用脚本实例

完整范例见 [对话工程参考](dialog-template-patterns.md) §3。纯库 `require` 后可普通函数调用；挂载脚本的状态属于其 Script 实例，应从目标控件 `GetScripts()` 或按真实映射/路径取得 Script，再 `targetScript:Invoke("公开函数", ...)`。

- `GetScripts()` 只取当前控件挂载的脚本，不递归。A 上找不到 B，不代表跨脚本调用不可用；先找到 B 的宿主控件。
- 公开函数在脚本环境顶层定义；内部辅助函数保留 `local`。不要把这些公开函数误判成黑板字段泄漏。
- 当前 `annotations.lua` 的 `Script:Invoke` 没有返回值契约；不得靠它拉取 table 或判断业务成功。范例通过回调传回正常完成事件；跨客户端/服务端仍走服务器信号与变量。
- `pcall` 成功或 Invoke 数量仅证明调用未抛错；业务完成需目标回调或明确状态确认。句柄判活、错误列表和启动就绪仍须处理。
- 分清 0-based 原生网格/服务器分支索引与 1-based Lua 业务数组；仅在边界转换一次。

## 10. 把「黑板（文本框串）」改造成「自定义变量 + 服务器信号」—— 完整迁移经验

> 来源：2026-09-29《侦探杀》真机全程（`main` 客户端 Lua ↔ 10 个界面脚本，原方案是 `t1_kb_state` 三分片文本框 + `t1_kb_cmd`）。
> **每一跳都是真机实测**，不是推断；改造仍在进行，本篇记录**已经验过的形状与踩过的坑**。

### 10.1 黑板为什么必须换（不是审美问题，是三个硬伤）

| 硬伤 | 真机证据 |
|---|---|
| **文本框有长度上限** | `主控 main:2742: 文本长度超出限制`（平台自己打的 ✓ 带文件名:行号）；状态串 **4431 字符**时开始刷这条 ⇒ 超出的部分**根本没上屏** ✗ |
| **只有字符串**（要自己定格式、拼、切分片、解析） | 分片 `t1_kb_state2/3` + `gmatch` 逐键解析；一处拼错全串静默缺字段 |
| **只能轮询**（没有"变化通知"） | 每帧读文本框 + 解析；而自定义变量**有变化回调** ✓ |

### 10.2 能力边界（真机定案，别记反）

| 动作 | 客户端 Lua | 写方 |
|---|---|---|
| **读**自定义变量 | ✅ `game.GetGlobalCustomVariableValue(Enum.CustomVariableEntityType.Level, "名字")` —— **返回带类型的值** ✓ | — |
| **写**自定义变量 | ❌ **没有任何写接口**（8 个候选名逐个试 = 全无 ✓；连 `levelScript` 也不行 ✗） | **只有服务端节点图** ✓（官方原文：读/写/监听都在**节点图**里 ✓） |
| **监听变化** | ✅ `script:RegisterCustomVariableChangedHandler(Level, "名字", function(entityType, name) ... end)`（**注意是 `script:` 不是 `game:`** ✓；**回调不带新值** ✗ ⇒ 里面再 `Get…Value` 读一次 ✓） | — |
| **枚举** | 客户端 `PlayerSelf` 可读：已有《侦探杀》记录，且 2026-10-18 用户确认运行的对话/任务工程多处实际使用；`AvatarSelf` 在通用解析器中有支持分支，具体角色变量读值仍需实例证据。按数据归属选 Level / PlayerSelf / AvatarSelf，不能把“只验过 Level”当限制。详见 [对话工程参考](dialog-template-patterns.md)。 | — |
| **控件直接绑变量**（零代码刷新 ✓） | 文本框插变量 `{1:lv.变量名}`（前缀 `lv`=关卡 / `ps`=自身 / `p1~8`=玩家 ✓）；进度条 / 自定义开关 / 交互按钮次数 / 计分板 也都能绑 ✓ | — |

### 10.3 打通的那条链路（四步，每步都有真机证据）

```
main（客户端 Lua，状态机）
  │ ① game.ServerSignal("侦_状态")  → :AddInt()/:AddString() → :SendSignal()
  │    文档原文：「参数按服务器约定依次添加」⇒ 顺序必须与信号管理器里**逐字一致**
  ▼
服务端节点图（一张：监听信号 → 多分支(type) → 设置自定义变量）
  │ ② ⚠️ 目标实体**别用「事件源实体」** ✗ —— 发信号的客户端脚本不是实体 ⇒ 写不进去/写错地方
  │    ⇒ **写死「关卡实体」** ✓（读方用的是 `EntityType.Level` ✓ 必须对上）
  │ ③ ⚠️「是否触发事件」必须 = **是** ✓ —— 否则 Lua 的变化回调**永远不会响** ✗
  ▼
关卡自定义变量（带类型 ✓）
  ├─ ④ 控件**自己**刷新（文本框插变量 ✓ 零代码 ✓）
  └─ ④ 客户端 Lua 读（带类型、免解析、免分片 ✓）+ 变化回调（推模式 ✓ 零轮询 ✓）
```
**信号参数类型**：`AddInt / AddIntList / AddFloat / AddFloatList / AddString / AddStringList / AddVector3 / AddBool / AddParam` ✓ —— **列表类型是省参数的关键** ✓（一张名单用 `AddStringList` 一次带走 ✓ 不用拼 `|` 分隔符 ✓）。
**多字段怎么省信号**：一个 `type` + 复用 3 个参数 ⇒ 每个 type 对应"这一类更新"（`type=1` 时间 / `2` 名声 / `3` 消息 / `4` 比例…）；节点图**每类加一条分支**即可 ✓。

### 10.4 迁移顺序（**一次全切必炸**，按这个顺序）

1. **先只推 1 个字段**（挑**零歧义**的那个：本地已有现成变量、值一眼能验）⇒ 打通链路 + 拿真机证据 ✓
2. **读方逐个切**（一次一个脚本）：读到的值**覆盖**黑板解析结果（**黑板照旧解析** ⇒ 天然回退 ✓）；
   ⚠️ **变量读不到时保持黑板值** —— 绝不把 nil 写进去 ✗
   ⚠️ **只在"命中数变化"时打一行日志**（否则每帧刷屏 ✗，但必须看得见 ✓）
3. **顺带处理黑板长度**：把**静态长文本**（术语/图鉴/关卡表这类**内容固定**的大块）挪去 **`Invoke` 查询** ✓
   ——它们**本来就不该走状态通道** ✓（"查询走 Invoke、状态走黑板/变量" ✓）
   ⚠️ 动它们前先看清**分片切点标记**（我们的切点就锚在 `;tutB4=` 上 ✗ —— 删字段会打断切分 ✗）
4. **控件直接绑变量**（静态展示类：消息/时间/名声/比例…）⇒ 这部分代码可以整段删掉 ✓
5. **确认没有 reader 之后**再撤黑板 ✓（最后一步，别提前 ✗）

### 10.5 坑清单（本轮真机踩到的）

| 坑 | 真相 |
|---|---|
| 把「父控件路径」当通用解 | 见 §9.3：**先量控件树**（`GetScripts()` 数一下）再决定 |
| **静默 return** | 我给失败分支写了"每 20 次点名一次" ⇒ 玩家一局只点 8~25 下 ⇒ **一声不吭** ✗ 白跑两轮；诊断期**每次失败都出声** ✓ |
| **后置 `local`** | 助手函数写在 `local function log` **之前** ⇒ 那是**全局 nil** ✗；`scripts/lua-check.mjs scope` **抓不到函数体内的前向引用** ✗（本轮第二次栽在同一个坑，见 §1 的"位置铁律"） |

## 11. 改「模板引用控件实例内部」的文字：**钻够深度 + 全刷 + 读回校验**

**场景**：一批同款控件都引用同一个模板（如 10 个数字键都引用「数字按钮」），要让它们**各自显示不同内容**（数字 / 编号 / 卡面序号）。

**真机实测结构**（`.gil` + `.gia 2026-10-01`）：

```
引用控件 "0"（ClientUIReferenceControl，引用模板 1073742430）
  └ 数字按钮（ClientUIPresetButtonControl）
      └ 不可用 / 按下 / 悬停 / 默认（ClientUIContainerControl × 4）
          └ 图片 + 文本框          ← 字在这里：第 3 层，而且四态各一套
```

**三条规矩**（缺一条就是真机 `初始化完成 total=10 done=0`）：

1. **递归深度给 4** —— 引用控件→预设按钮→状态容器→文本框 = 3 层，留 1 层余量；
2. **整棵子树全刷** —— 不是"找到第一个能写 `text` 的就停"：四态各有文本框，只刷一套 ⇒ 默认态对了，**一按 / 一悬停就变回模板原值**；
3. **每条写入都读回校验** —— 给没有 `text` 字段的控件写 `text` 是**静默无效**（不报错），不校验就会把"没刷上"记成"刷上了"。

代码形状（`assignAllText` + `setTextVerified`，真机跑通）见
[`case-reference-control-numkey.md`](case-reference-control-numkey.md) §2。

**配套两条**：
- **按控件名认键**（`type(name)=="string" and name:match("^%d+$")`），不写死个数与名字 ⇒ 多一个 `0`/`10` 自动跟着走；
- **日志给足判据**：`键 name=… type=…`（认结构）+ `刷上 name=… 文本框数=N`（认结果）+ `初始化完成 total=… done=…`（认全量）—— 一局就能定位"断在哪一层"。

> 相关：`ClientUIReferenceControl` 实例内部**可以访问**（`GetChildren` 进得去）见 `engine-boundaries.md` #30；
> 四态按钮四套文本框见 #31；「无父节点的组可建、组内子节点不可建」见 #29。

**配套：解开之后"关掉整个 UI"怎么写**（2026-10-01 真机，密码解密案例）

```lua
local target = script.object
for i = 1, CONFIG.CLOSE_UP_LEVELS do          -- 沿 parent 上溯，别写死索引
    local parent = parentOf(target)
    if parent == nil then break end
    target = parent
end
log("准备关闭 UI name=" .. target.name)       -- ★ 必须先打日志再关（见下）
pcall(function() target:SetActive(false) end)  -- active=false ⇒ 不可见 + 旗下脚本逻辑停止
```

- **为什么要用 `SetActive(false)`**：文档 §13 写的是「active=false ⇒ 控件不可见**且挂载脚本逻辑停止运行**」——
  正好就是"UI 关掉、也不再收点击"，而且**可逆**（`SetActive(true)` 能再开）。要彻底删掉省控件数就用
  `game.DestroyClientUIControl(target)`（不可逆，且别在 `OnDestroy` 里调 —— 边界 #7）。
- **⚠️ 日志顺序坑**：`active` 关掉的**那一瞬间本脚本逻辑就停了**，所以"已关闭"那条 `print` 可能永远不出现。
  排查时把「准备关闭」打在动手**之前**，否则你会以为关闭失败。
- **关闭目标别写死索引**：实例化出来的 UI，其容器索引随关卡/存盘变化；用 `script.object` 沿 `parent` 上溯最稳。

## 12. 剧情/对话类玩法：**结构体当数据、信号当触发、状态机里找唯一挂点**

> 2026-10-01 真机跑通（《酬礼03》「对话框模版」v13/v14：从零加**跳转 + 淡出过渡**）。

**数据模型**（这类玩法的通用三层形状）：
```
服务器信号「开启对话」(参数1 = key，参数2 = 类型)   →  客户端脚本
      ↓ 读
自定义变量 PlayerSelf「对话」 = 字典 { key → 条目结构体 }
      ↓ 解析
条目 = { 对话列表 = [ { 标题/副标题/内容/内容显示时间/节点图事件触发 } ]，
         跳转对话 = 「基础跳转对话结构体」}
```
- **触发层用信号**：一个信号名 + **参数位置约定**（参数 1 = key、参数 2 = 类型；**省略或认不出的值一律回落到默认类型** ⇒ 旧信号不用改也能用）。
- **内容层用自定义变量**：改剧情内容**不用重新部署脚本**；客户端侧 `GetGlobalCustomVariableValue(scope, 变量名)` 是只读（写靠服务器）。
- **形状未知就三路探测 + 首次 dump**：`pick`（中文名候选 → 数字序兜底）／`asList`（数组 / 字典 / 单值三态都吃）／`dictGet`（直查 → `{key,value}` 数组成对 → 数字 key 兜底），首次读到就把真实形状打进日志（看清后关）。

**跳转（"结构体 → 行为"）的三条实测规矩**

1. **互斥/缺省语义必须问清三种情况**。本案例创作者口径：**恰好填一个 ⇒ 执行**；**多填 ⇒ 不执行**（打日志把三个值都列出来，按"正常收尾"处理）；**都不填 ⇒ 正常收尾**；**空串按"没填"算**（编辑器里留空常给 `""`）。别替创作者发明规则 —— 0 个 / 1 个 / 多个的处置各不相同。
2. **挂点找"唯一出口"**。跳转只能挂在 `tick` 里 `segIndex > #segs` 那一处 —— 那是全脚本**唯一**"整条播完"的时刻。⇒ **改状态机脚本前先定位"这件事只可能发生的那一处"**，别到处插（在多处插 = 同一个行为被触发两次或漏触发）。
3. **"等动画走完再做事"要挂在那个动画的既有完成点**。淡出过渡**没有新起计时器**：复用 `phase == "fading"` 分支里 `destroyBox()` 之后那一刻去续播。并行开一个计时器 = 两套时间源，迟早对不上（也是 R16"同一批字段只有一个所有者"的同族）。

**"待办"型状态必须有清理点**（本案例踩到）：等渐出的 `pendingJump` 在"渐出途中被新信号打断"时会**残留**，之后在**别的场次**渐出完毕时被误触发 —— 症状是"莫名其妙跳去一段不相干的对话"。⇒ **在新一场开始时清掉它**（别只依赖"用完即清"，因为它可能永远用不上）。

**给既有脚本加函数：先看有没有"前向声明区"**。`对话框模版.lua` 顶部有一行 `local fail, stopDialog, …`：要调**后面才定义**的函数（如 `startDialog`），就得把新函数名**并进那一行**。不声明 ⇒ 要么被当全局写（R2）、要么闭包读到 nil（R3，**静默失效**）。
