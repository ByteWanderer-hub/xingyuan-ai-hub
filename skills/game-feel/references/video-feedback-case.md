## 迁移配方：触发 → 不变量/原因 → 方法 → 反例/验证边界

### 1. 先让动作与危险能被读懂

- **触发**：主体淹没在装饰里，或预警、释放和背景看起来一样。
- **不变量/原因**：反馈应解释动作与状态；美术复杂度不能替代信息。观众能追踪主体，不等于玩家能及时决策。
- **方法**：为主体、状态提示、主要效果、背景分别列出轮廓/亮度/色彩/运动职责；选最少的冗余编码。先确保不靠颜色也可区分，再加拖尾或局部描边。不要机械照搬“红色必危险、青色必安全”。
- **反例/验证边界**：关掉装饰后仍需靠猜规则，说明不只是反馈问题。用灰度与小屏截图、遮住直播覆盖层后的原始游戏画面检查识别；可交互版本再测第一次见到时是否读懂。不因一帧漂亮就判体验通过。

### 2. 用预示—释放—恢复描述一个事件

- **触发**：重要动作突兀，或特效常驻后再无强弱。
- **不变量/原因**：重要事件需要可识别的前后差异；反馈不应偷偷改写玩法判定或延迟输入。
- **方法**：列出预示、释放、恢复三态及各态信息；可用细线→亮带、倒数→扩环→回落等原创组合。视觉时间线绑定已确认的权威事件，暂停/重试/跳段时清理临时状态，避免残留。
- **反例/验证边界**：只加释放闪光却没有预示，或为了“重量”擅自冻结玩法，都不成立。0.5 秒抽样只能证明样本先后，不能给毫秒级时长；要精调需连续逐帧和实际事件时间戳。失败预警应先查规则与触发，不凭录像判根因。

### 3. 用重复图元和状态变化替代无上限堆量

- **触发**：效果单调，或为丰富画面不断增加独立素材和粒子。
- **不变量/原因**：统一词汇帮助学习；变化来自编排，也可能来自造型。减少素材种类不保证减少绘制成本。
- **方法**：先选一种母题，再比较位置、朝向、数量、相位、间距、亮度等少量变化。只选择服务当前事件的维度，保留主体可见性；是否省控件、实例与更新开销另测。
- **反例/验证边界**：把参考环阵、图腾、敌人造型或整段编排直接复制；认为同图复用就零成本；把闪烁强度当效果质量。预算与可访问性必须在目标工程另验。

### 4. 对比可以很强，持续刺激不必很强

- **触发**：每个事件都最大强度，玩家分不清重点。
- **不变量/原因**：显著性取决于前后对比。低刺激段也可有反馈，不要求所有动作震屏。
- **方法**：按事件重要性分小/中/大档；将大面积亮度和尺度变化留给少数明确事件，用稳态构图或局部动效承接恢复。场景节奏或关卡难度调整交给 `level-design`，不在反馈润色时擅改。
- **反例/验证边界**：把大圆环当成真实运镜、把暗场认定为休息或把观众惊叹当普遍可玩性证据。提供减弱镜头运动/闪光的替代；缺少连续帧时不宣称光敏安全。

## 使用时的最小交付

输出：**事件/目标 → 视频时间点与证据等级 → 可复用信息职责 → 原创反馈方案 → 实现依赖 → 验证方法/未知项**。

- 参考不可读：只做通用建议，明确没有分析到指定片段；请求片段或时间点，不编造观察。
- 只想借鉴体验：交付上述设计，不自动变成关卡复刻或写入游戏。
- 要求实现：先确认目标引擎、事件合同、授权与预算。千星用已安装的 `miliastra-motion`/`miliastra-code`，需要原生图形时按 `miliastra-ui` 的现行约束；本文不给虚构 API、模板号或碰撞数值。
- 原型验收：关装饰检查信息 → 无声检查视觉预示 → 减弱动效检查非颜色线索 → 实际操作检查输入与状态 → 连续音画检查同步。无声检查只是隔离变量，不能替代音画验收。
- 本案例只支持观察性方法参考；没有 A/B 玩家实验，不宣称更好玩、延迟更低、性能更优或原作同等体感。
