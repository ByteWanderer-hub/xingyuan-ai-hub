# 从开源动效读节奏

## 选源与取数

先在演示页看常速，再打开同一版本的关键帧。抄录持续时间、延迟、循环方式、原始姿势、峰值、回落和静止区。负延迟表示开始时已经进入循环的某一相位。按关键帧百分比乘周期换算毫秒，项目覆盖的 CSS 变量要用实际值重算。以下记录是源码行为，迁移栏是设计推导。

|演示与授权范围|原始动作及可复核节拍|可迁移的设计决定|
|---|---|---|
|[Animate.css](https://animate.style/) · 所引 v4.1.1 [MIT](https://github.com/animate-css/animate.css/blob/v4.1.1/LICENSE)|[heartBeat](https://github.com/animate-css/animate.css/blob/v4.1.1/source/attention_seekers/heartBeat.css) 的两峰在 14% 和 42%，均为 1.3 倍，28% 回原位，70% 再归位。基础时长 1 秒时，该动作乘 1.3，峰值在 182 和 546 ms。|同样的两次强调可以靠收尾留白形成一组。适合双击确认；做稀有奖励时，把玩家需要看清结果的时间留在后面。|
|同上|[rubberBand](https://github.com/animate-css/animate.css/blob/v4.1.1/source/attention_seekers/rubberBand.css) 在 30% 横宽纵扁，40% 反向，50%、65%、75% 的形变逐渐减弱，100% 复位。|受力方向翻转最密集的片段适合表达接触。若项目只许改时间，把既有反弹姿势的间隔压紧，维持原幅度。|
|[SpinKit](https://tobiasahlin.com/spinkit/) · [MIT](https://github.com/tobiasahlin/SpinKit/blob/master/LICENSE)|[sk-wave](https://github.com/tobiasahlin/SpinKit/blob/master/spinkit.css) 五条共用 1.2 秒周期、ease-in-out，相邻负延迟相差 100 ms，首尾错开 400 ms。|用峰与峰的间隔安排连续拾取或评级。单次结算用实际开始时间顺序触发，保留第一项的完整起势。|
|同上|同一源码的 sk-bounce 让两个圆共用 2 秒周期，第二个提前 1 秒进入循环。|半周期错开适合交替呼吸。双元素同时表示“已就绪”时，同相更易读。先决定语义，再决定相位。|
|[Loading.io CSS loaders](https://loading.io/css/) · 此页十二例标注 CC0|[Ripple](https://github.com/loadingio/css-spinner/blob/master/dist/ripple.html) 两个环使用 1 秒周期，错开半秒，从同一中心扩张并淡出。|可用于持续可交互提示。做一次性命中时，按原有层数安排扩张和消散，限制重复次数，以免看起来还在持续判定。|

## 执行一次只改节奏的任务

1. 找项目当前播放入口、收尾条件和分支。以能匹配当前实现的逐帧素材或运行输出为底。把角色动作、星星、火花、音效、输入开放点分别列在原时间轴上。截图只可用来对静止构图。
2. 写一句玩家应当察觉的变化，例如“前三项一口气读完，第四项出现前有明显期待”。列出原版与候选的开始、峰值、落稳、停留、下一事件。固定结构的素材优先做单调时间映射，逐层工程才单独改变各层起点。首尾画面、层次、数量和动作路径都按约定保留。
3. 先试两种明确不同的组织方式。例如四项依次出现，可让前三次峰值分别落在 0.50、0.65、0.80 秒，第四次落在 1.65 秒；也可用均匀的四拍。以上是试验参数。若原画面还有蒸汽或输入提示，插入整帧停留会冻结它们；需要持续运动时改独立轨道。多人判定和计时独立于表现时钟。
4. 声音保留同一素材，将可闻起音对齐新接触帧。选中按钮的时刻独立记录。需要判断声音同步时另用有声预览；在千星和蛋仔分别核对目标地图可调用的视觉层、声音接收者和控件时间单位。
5. 常速并排同起点，先隐去版本与数字，请观察者说出哪一下最重、哪一段像等太久。先看一遍，再慢放定位。逐帧比对能证明元素守恒；“差别可感”要有观察者反馈。没有反馈时，交付仅标明节拍、编码时长和待试玩。GIF 导出回读每帧实际延时，对照帧序、总时长和循环接缝。

**适用边界**　网页循环样例验证了编排机制。设备帧率、战斗可读性、玩家喜好和平台性能另做游戏内验证。需要诊断随机卡顿时走性能分析。
