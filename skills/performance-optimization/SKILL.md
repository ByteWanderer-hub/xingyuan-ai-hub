# 游戏性能优化

> 星愿修改版（2026-10-25）：基于 awesome-gamedev-agent-skills 的同名技能重写、校正并增加千星适配。来源提交、许可及修改清单见 [来源与校正](references/sources.md)；保留 Apache-2.0 [LICENSE](LICENSE) 与上游 [NOTICE](NOTICE)。

用于持续低帧率、帧时间不稳、首次使用停顿、周期性卡顿或长时间运行退化。先区分画面掉帧、网络响应慢、脚本停止更新与刻意的 hit-stop；仅后者走 `game-feel`，无法确定故障原因时按需配合 `systematic-debugging`。本技能不授权部署、改玩法或降低已确认的视觉标准。

## 工作方法

1. **固定可复现负载。** 明确目标设备、客户端/构建版本、分辨率与画质、帧率上限、人数/实体/特效量、操作路径和采样时段。区分冷启动、首次出现、稳态及长时间运行；偶发问题保留触发记录继续取证，不宣称无法优化。
2. **建立基线。** 目标帧预算为 `1000 / FPS` 毫秒（60 FPS ≈ 16.67 ms，30 FPS ≈ 33.33 ms）。有逐帧样本时记录样本数/时长、p50/p95/p99、最大值、超过约定阈值的帧数；无足够样本不强报分位数。平均 FPS 用帧数/总时长，不能平均瞬时 `1/dt`，也不能用它掩盖尖峰。
3. **定位成本而非猜测。** 分开看脚本/物理、CPU 渲染准备与提交、GPU pass、I/O/资源加载、同步等待、限帧/VSync。CPU 与 GPU 可流水并行，不把两者直接相加作为整帧耗时；回调间隔或脚本耗时都不等于 GPU 时间。无工具时用受控 A/B 缩小范围，结论标为推测。
4. **提出一个可证伪假设。** 对最影响目标的瓶颈做最小修改：减少总工作量、缓存、事件更新、错峰/分帧、复用，或降低已确认冗余的视觉开销。单次只改可归因的一组因素。不能通过吞异常、关闭玩法、丢关键反馈或静默丢事件制造“流畅”。
5. **同条件复测。** 重复相同路径，比较分布与长帧而非只看平均值；保留运行间波动，区分探针开销。优化了局部但整帧不变，可能是等待、另一瓶颈或收益低于噪声，不直接推断原热点不存在。按数据保留有效改动或回退无效复杂度。
6. **交付证据。** 报基线/修改/复测、收益与回归、设备及版本、证据文件和剩余未知项。预算由目标设备实测形成；工具估算、历史样本和本轮结果分开记载。文件安装、静态验证与真机效果分别报告。

## 选择优化方向

| 证据 | 优先实验 | 不可直接推出 |
| --- | --- | --- |
| 脚本热点、重复查询、分配峰值 | 缓存与失效策略、复用表/缓冲、降低非关键更新频率、缩小遍历集合 | 所有卡顿都是 GC；强制 GC 一定有效 |
| CPU 渲染提交成本高 | 减少冗余可见对象和状态切换；支持时核对批处理/实例化 | Draw Call 多一定是 GPU 算力不足 |
| GPU pass 实测高 | 按 pass 查透明覆盖面积、着色器、阴影、后处理、分辨率 | Draw Call 下降必然使 GPU 耗时下降 |
| 首次使用或资源切换尖峰 | 测量加载/创建/编译，预热必要资源，限制每帧工作 | 预热无代价；所有资源应一次加载 |
| 长时间退化 | 追踪累计对象/任务/内存、池增长、重复订阅；有证据时查温度/功耗 | 运行两分钟变慢就一定热降频 |
| 回调停更、画面冻结 | 先查首错、守卫、死循环及状态；恢复更新后再测性能 | 减粒子能修复脚本异常 |

## 按需参考与分工

- **千星奇域**：先读 [千星测量与优化边界](references/miliastra.md)。实际 Lua 修改/API/验证/部署走相邻 `miliastra-code`；控件与素材走 `miliastra-ui`；动效编排和粒子参数走 `miliastra-motion`。仅咨询时不启动业务恢复或 Host 调用。
- **跨引擎分析、池与资源预算**：读 [测量与预算细则](references/profiling-and-budgets.md)。其他引擎的工具名称仅作入口，命令和支持范围按项目实际版本核实；不假设本库安装了上游提到的 `physics-tuning`、`godot-export` 等技能。
- 刻意的打击停顿与反馈设计走 `game-feel`；网络延迟另查网络链路，物理抖动另查时间步与插值，不能把症状全部归为渲染问题。
