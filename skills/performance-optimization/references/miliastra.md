# 千星奇域：可观测性能与平台边界

> 星愿新增适配（2026-10-25）。这是分析/验证工作法，未提供或承诺底层 GPU profiler、批处理控制、独立构建或抓帧接口。

## 先确定能测什么

实际实现前读相邻 [miliastra-code](../../miliastra-code/SKILL.md)，按项目 `annotations.lua` → 现有 API 参考确认类型、签名和时钟口径。仓库 [API 参考](../../miliastra-code/references/api-client-ui.md) 记载 `OnUpdate(dt)` 为脚本逐帧回调且不受关卡时停影响，`OnLevelUpdate` 受时停影响；这不证明 `dt` 是最终显示器呈现时间。需核对单位、暂停/切后台及夹取行为，不把回调 dt 统计称作 GPU 耗时或已呈现帧率。

`os.clock` 在现有参考的允许列表内，但通常表示进程 CPU 时间，平台语义和精度仍需核实；不能直接作为 GPU 或端到端 wall-clock 计时器。没有经核实的高精度时钟时，分区 CPU 耗时标 unknown，用调用计数、工作量计数与 A/B 实验继续定位。不编造 `GetGPUTime`、`GetDrawCalls`、分配计数器或强制 GC 接口。

采样保存原始、有效的 dt，再由动效逻辑单独决定如何推进；不要先钳制 dt 再拿来统计长帧。对 nil/非数/NaN/无穷/非正值记录无效数，不执行倒数或分位排序；暂停、切后台、恢复首帧独立标记，保留原始记录。`回调次数 / Σdt` 只有在 dt 单位和累积语义已确认时才可报告为回调频率，不默认等于真实平均 FPS。`os.time/os.date` 不作为高精度帧计时；进程级时钟差也不能自动归为本脚本独占 CPU 成本。

轻量观测按当前能力选择：

| 观测 | 口径与限制 |
| --- | --- |
| 回调间隔/次数 | 记录窗口、单位、丢样/暂停；只能证明相应回调节奏 |
| 创建/更新/回收/销毁次数 | 在本次代码调用边界计数，不冒充引擎全部内部工作 |
| 控件与粒子 | 分总数、可见数、活跃更新数、池空闲/高水位、扩容与池满次数；控件数不等于 Draw Call |
| 首错/重复失败 | 聚合首错及次数；冻结先排脚本停更，不当成渲染慢 |
| GPU/实际呈现/内存 | 仅有经核实工具或设备证据才填，缺失明确 unknown，主观“小卡”另列 |

诊断放聚合日志/离线结果，不加入游戏画面。接入 `OnUpdate` 仍遵守现有 R1 聚合故障块与平台调用失败处理；不能为降低开销移除异常保护、吞掉失败或无限重试。采样需有停止条件与容量上限。

## 用受控对照定位

固定关卡、脚本 SHA、操作、设备/分辨率/画质及负载，分别测首次出现、稳态、重开和持续游玩。不能取设备 GPU 数据时，以下只形成假设，不下“GPU 已证实”结论：

- 从相同起始画面临时冻结装饰位置计算/属性写入，与原版短窗口对比：改善支持更新路径成本假设，也可能包含引擎脏状态处理收益，不能称纯 Lua 成本或假设后续画面不变。
- 保留池与逻辑，只临时隐藏一组视觉层：改善支持可见渲染工作相关假设；平台隐藏是否停止其他工作需验证。此对照不作为删掉已定视觉的最终方案。
- 分别减少透明覆盖面积/叠层、活跃粒子、每帧 setter、创建速率，每次只动可归因因素。记录同时变化的量，避免把减少对象带来的多种收益全归给 GPU。
- 检查重复注册、重复建池、失效对象仍更新、退出/重开未清理、日志与字符串增长；尖峰与创建/加载时间相关才进一步测试预热或分帧。

冻结属性写入会改变运动画面、空间覆盖和脏状态，隐藏一组也可能改变输入路径；不能声称这些对照始终“画面/其他条件完全相同”。用相同起始快照、可重复操作及足够短的比较窗口，记录无法控制的混杂因素。输入相关面板另按 [UI 交互可靠性](../../miliastra-code/references/ui-interaction-reliability.md) 核对热区、祖先 `showCursor`、层序与真实输入路径。

## 显隐、更新与复用不是同一个开关

当前 API 参考（仍以目标项目版本为准）明确：

| 操作 | 已记录的作用 | 优化时的边界 |
| --- | --- | --- |
| `control:SetVisible(false)` | 隐藏控件，不停止挂载脚本逻辑 | 隐藏不等于停止更新；父脚本维护的粒子循环仍需移出活跃集合 |
| `control:SetActive(false)` | 不可见且挂载脚本逻辑停止运行 | 不等于所有父级/管理器/外部回调和 Tween 全部取消；重新激活后验证输入、状态和更新恢复 |
| `script:EnableUpdate(false)` | 关闭当前脚本的 Tick 更新 | 不是单颗粒子的开关；管理器仍有其他任务或采样/唤醒依赖时不能整体关闭；安排不依赖已关闭 Tick 的恢复路径 |

池对象区分装饰叶控件、自带脚本的实例和共用宿主。借用/静态控件不可销毁；回收只解绑自己持有的监听/任务，不能用全局移除清掉其他功能。`OnDestroy` 是脚本销毁回调，面板隐藏或新一局不保证触发销毁或重新执行 `OnStart`；提供项目实际入口调用的显式重置，按持久池/销毁重建的既定策略收尾，重复调用也应安全。

Tween/Sequence 在复用、替换或销毁前处理本次拥有的句柄。API 中 `Tween:Kill(true)` 会完成并触发完成回调；取消路径应按语义使用 `Kill(false)` 并使旧会话/代际失效，不触发正常完成的玩法结算。`Sequence:Kill(false)` 的实际顺序仍按项目验证。回调可能同步开启新会话，先移除旧状态再回调，防止旧收尾清掉新池项。必要写法与证据边界见 [对话工程生命周期与 Tween](../../miliastra-code/references/dialog-template-patterns.md)。

## 平台可落地的优化

1. 先做缓存、值变化才 setter、非关键 HUD/装饰降频、活跃集合遍历、错峰/分帧。精度阈值和频率按视觉/响应验收调整，不给全地图统一值。
2. 对高频出现的装饰控件按已核实创建/显示/生命周期 API 建有界池。创建与复用状态分离，完整重置，停止闲置项更新；池满计数与可接受策略显式化。位置/尺寸/颜色 setter 个数分别统计。
3. 控件与素材按 [miliastra-ui](../../miliastra-ui/SKILL.md) 的同型资产优先规则，不把一个现成形状拆成像素块增加控件。只在已确认美术范围内减少冗余叠层；不自行替换用户定稿或删除关键反馈。
4. 粒子发射、寿命、池与编排读 [miliastra-motion](../../miliastra-motion/SKILL.md) 的相关分支。视觉配方不是设备安全上限；平均 `发射速率 × 平均寿命` 只是稳态量级，还要测同时爆发峰值与空池。
5. 不从 Unity/Godot 推导千星支持 GPU instancing、图集合批、Canvas 分割、资源压缩/LOD 配置或渲染管线修改。需要底层能力时先找当前平台依据，缺失就限定可交付范围。

实现取舍还需覆盖：

- **先选更新路径，再测代价。** 已支持的 Tweenable 字段可比较原生 Tween/Sequence 与 Lua 逐帧计算；Tween 减少手写插值并不代表零每帧开销或必然更快。不要每帧新建/重启 Tween，同一字段应有一个写入者，不能让 setter 与 Tween 争写。并非所有 `OnUpdate` 都换成 Tween。
- **停顿后的追赶有上限。** 按已核实 dt/时间域推进，保留非关键装饰降频的余量；长帧后用无界 while 补发粒子、补建池或补跑历史步会进一步卡顿。对装饰定义每 Tick 工作上限和剩余任务策略；暂停/恢复是否追赶按效果需求验证。不要为提帧钳制整个玩法的时间、丢关键事件，或把服务端信号/变量责任改到客户端。
- **setter 缓存有所有权。** 只在自己独占字段且缓存有效时跳过未变值；重开、借用、外部写入、Tween 结束或重建后要使缓存失效，否则画面停在旧状态。按需复用共享父节点整体位移/缩放，但不得因此改变子级锚点、pivot、裁剪、层序或交互区域。不能为省调用在创建/销毁回调里改 `parent`；该时机已有平台拒绝案例，见 UI 交互可靠性参考。
- **模板依赖与构建边界。** 原生创建用已配置的模板索引（如 `InstantiateClientUIControl` 的第一个参数），不是图片资产 ID；创建前确认父级和生命周期就绪。预算计入模板包装层与挂载脚本、空闲池和常驻控件，不只算粒子叶节点。静态美术按原生控件/GIA 流程复用，数据在项目既有构建期预计算；不要为预热、探针或生成资产把大批新建塞进每帧热路径。没有经核实单次计时器时，每帧数量上限只能称工作量预算，不称毫秒硬预算。

历史 [粒子与预算](../../miliastra-code/references/vfx-particles-and-budget.md) 中约 950 控件/58.8 FPS、5188 控件/3200 粒子的记录只是其特定旧场景证据；本次未复测、设备条件未全量复核。“小卡可接受”的主观裁决不是通用通过线，1024 的工具预算也不是硬件上限；均不能作为当前关卡或其他设备的放行阈值。不复制历史文档中的绝对化结论（如预存多套是唯一方案）。

## 验收与交付

静态门禁只证明适用检查通过，模拟器不证明实际渲染性能。实际改脚本/部署时按 `miliastra-code` 的备份、活文件指纹、显式候选、存盘与试玩流程执行；本技能安装不授予业务部署权限。

交付至少写：目标与复现场景、设备/版本/画质、脚本 SHA、采样工具与口径、窗口与样本数、基线/修改后数值、波动与未测项、视觉/交互回归、证据路径。分别填 `evidence_source` 与 `device_status`：实际优化任务缺真机验收记 `pending`，纯咨询/技能维护无需真机则记 `not_required`；有已执行的失败验证记 `failed`，不能用 pending 覆盖失败。已有用户试玩反馈保留其来源与时点（如 `provided_unverified`），不要冒充本轮现场复测。不能把装好技能、代码更少或工具估算写成优化通过。
