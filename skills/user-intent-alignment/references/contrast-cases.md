以下为最小化改写的案例，不是逐字聊天转录。设计案例仅说明如何理解指代、保留与修改，不携带该项目的美术方案、素材、地图数据或部署权限。资料库名称、物理路径等不作为此技能的业务配置。

| 观察 | 证据强度 | 适用限度 |

## 第一轮：从原表达比较理解方式

| 案例 | 容易误读的方式 | 应执行的理解 |
| --- | --- | --- |
| C1：问之前在另一设备挑选的那批工具装没装 | 报本机默认技能的安装数量；这是样本中已发生的对象误读 | 先找用户所指的选取清单，再逐项核查；不能只凭“技能”一词换成默认集合 |
| C2：选中 B 版，要求基于它再出三版 | 另起三种无关方向 | 保留 B 的核心基底，给三种可比较的变化；这是候选阶段 |
| C3：喜欢 B2 的书本；主页和选关沿用，成功与失败页换掉 | 把“重新生成三版”理解为四个界面全部重做 | 锁定两页书本主体，变化集中在指定两页 |
| C4：认可动画，要求成功页更简洁、去掉食物但保留热气 | 重新设计动画；或把简洁理解为清空所有元素 | 动画沿用，去除指定元素、保留指定元素；简洁由可观察改动体现 |
| C5：已定稿之后又要求重做主页，让玩家看出解谜玩法 | 以“已经定稿”为由不改，或把所有页面重新打开 | 新请求重新打开主页，继承“书本、简洁”等仍有效条件，其他页面维持已确认状态 |
| C6：检查依赖，缺少就安装，安装到指定盘 | 只给缺项列表；或忽略安装位置 | 核查相关依赖，按本次条件补齐；无法满足位置/兼容性时报告具体限制，不偷偷换位置 |
| C7：把这份文档和必要预览图打包，发给另一个 AI | 只给本机路径，或复制整个项目 | 交付含文档与必要图片的可传递包，核查相对引用；没有授权发送给第三方 |
| C8：方案不用共享仓库，只有技能需要，记住此规则 | 同步所有新文件；或擅自删除旧发布内容 | 更新以后发布的默认边界；已发布内容撤回需要单独指示 |

这些“应执行”是本轮归纳，不冒充当时助手已全部做到。
