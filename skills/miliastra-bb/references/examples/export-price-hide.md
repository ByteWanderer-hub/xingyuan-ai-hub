## 三、类别判定（步骤 4，六问判定器）

**这是"bug 里夹带需求"**：

- 前端移除价格显示 → **纯 bug（B组）**：现有行为（显示价格）违反已拍板预期，回到"不显示"。
- 后端 VO 剔除价格字段 + 排序口径 → **边界需求（A组）**：涉及对外接口的字段裁剪（防抓包防泄），非简单修复。

按 miliastra-bb 铁律拆分：**B组（前端移除显示）+ A组（后端 VO 剔除，标 [原混在bug单中，实为需求]）**。

## 四、实现方案（步骤后续：实现方案快速产出）

### 后端实现方案（对接 code-java）

- **接口**：产品列表/详情接口（`/om/web/products`、`/om/web/products/{id}`）——VO 去掉 `price / priceMax / currency / currencySymbol`（防接口被抓包拿到价格，属"防扒"需求）；排序口径去掉"按价格排序"。
- **表/实体**：不动表结构，仅 VO/DTO 层裁剪（价格字段仍在库中，仅不下发前端）。
- **关键实现点**：① 用 ProductVO 剔价格字段返回（不推荐用 Map，见铁律5）；② 前端不再传 `currency`，后端接口可保留 currency 兼容或去除；③ 分页限上限（铁律9）；④ 鉴权全（铁律10——对外匿名可访问接口不应泄露不该公开字段）。
- **铁律提示**：⚠️ 落地遵守 code-java 铁律 → 铁律5 强制 VO 返回禁 Map/JSON 泄漏（价格字段必须在 VO 层剔除，不能依赖前端隐藏）、铁律7 复用已有公共方法、铁律9 分页上限、铁律10 鉴权全 + 凭证不下发。

### 前端实现方案（对接 code-vue）

- **页面/路由**：`Products.vue`（产品列表卡片）、`ProductDetail.vue`（详情页）、收藏夹页（若有价格展示）。
- **交互**：① 移除 `v-if="isValidPrice(p.price)"` 价格渲染区块（369-371）；② 移除 `useCurrencyStore()` 币种切换对价格的影响；③ 移除 `formatProductPrice` 调用；④ 排序去掉"按价格排序"选项。
- **规范提示**：⚠️ 落地遵守 code-vue 统一规范 → 组件统一（价格区块删除后 `product-card__price` 样式一并清理）、样式 token（不残留无用样式）、Vue3 composition API 规范；`useCurrencyStore` 无其他用途则一并清理。

## 五、本次案例验证的关键点（防"AI 违反铁律"）

> 这个功能点**特别容易违规**，是 miliastra-bb 价值的典型体现：

- **❌ 错误做法**：只在前端 `v-if` 隐藏价格（`v-if="false"` 或注释掉）——**防抓包失效**，接口仍下发价格，curl 照样拿到。
- **✅ 正确做法（miliastra-bb 方案）**：前端隐藏 + **后端 VO 层剔除价格字段**（铁律5）+ 前端不再传 currency。**双层防泄**。

> 这正是"AI 用最省事方式（前端 v-if）糊弄 → 价格泄漏 → 违反铁律"的场景，miliastra-bb 通过"后端 VO 剔除 + 铁律提示"主动拦截。
