## 步骤 1-2：证据采集与拆解（不猜玩法）

- TapTap 页 + 攻略页交叉印证：《双相》(Biphase) = 躁郁症题材 **2D 横版平台跳跃解谜**，章节制；核心机制 = **红/黑（狂躁/压抑）双相切换**；"操作方式非常简单"
- **[待确认]纪律实战**：切相的精确规则（异相平台到底能不能踩）网页证据不足——攻略页 GBK 乱码只有"色彩切换为核心"级别的信息。**不猜**，拆成 FP4 标待确认，交给玩过原作的用户拍板（用户就是最准的证据源）
- FP1~FP8：移动 / 跳跃 / 切相 / 相位规则 / 关卡+出口 / 失败重生 / 多关卡 / 红黑表现

## R0 实战：试玩后用户拍板的玩法变更

用户试玩后提出：**"在红色的格子上，跳就切相了"**——跳跃本身触发相位翻转，而不是独立切相键。

处理（这是**规则升级**不是 bug，走 R0 记录）：
1. `doJump()` 起跳瞬间翻转相位 + 解卡（若与刚实化平台重叠则顶到平台上沿）
2. **关卡按红黑交替链重排**——每次跳都翻相意味着相邻两级平台必须异色，否则跳过去没有落脚点：
   `地面(通用) → 黑1 → 红1 → 黑2 → 红2 → 黑3 → 红3(出口)`，每级落差 100~130px（< 跳高 153px），横向缝 ≤60px
3. 边界清单回填「玩法变更（用户拍板）」条目；F/X 手动切相保留为调试用

> 方法论：**复刻类需求的规则细节，最终裁决权在玩过原作的用户手里**。网络证据负责圈定"它属于哪类玩法"，用户负责钉死"具体是哪条规则"——两级证据缺一不可。

## 落地要点（千星域无物理引擎的 2D 平台跳跃）

- **设计坐标系**：1600×1000、y 从顶部向下（关卡数据按人读习惯写）；渲染时换算引擎 y 向上（边界 #1）：`anchoredY = canvasH/2 - dy*sy`
- **AABB 分轴解算**：X 移动→解算，Y 移动→解算（含落地判定 onGround）；快落 = 重力×2.6
- **互斥碰撞**：`solidFor(p) = p.phase==0 or p.phase==current`——切相即切换碰撞集合，零额外成本
- **解卡**：切相后若玩家与刚实化的平台重叠 → 顶到该平台上沿（不做的话玩家会卡在实体里）
- 控件 13 个；Jump 手感参数（GRAVITY 2200 / JUMP_V 820 / 跳高 ~150px）为首版预设，`pending` 真机调参
