# 案例：千星域首个完整玩法——俄罗斯方块（从空文件到可玩 + 服务器信号闭环）

> 平台：千星奇域｜技能链：miliastra-bb（边界）→ miliastra-code（落地）｜日期：
> 演示内容：**"1 容器 + 1 脚本 = 一个完整玩法"的从零落地路径**；Runtime 骨架四件套；**三轮聚合故障排障**（每轮一行定位）；ServerSignal 上报闭环。适用：千星域任何"从零写玩法"的任务。

## 需求与起点

创作者在千星沙箱创建了空脚本 `测试.lua`（沙箱映射已建立），问"我现在要做些啥"。
需求极模糊 → 按 miliastra-code 交接节奏反向推进：

1. 创作者建【客户端控件容器】并把脚本挂上容器节点
2. 交回第一批交接值：容器节点索引 `1073741862` + 挂载脚本名 `测试`
3. 第二批：控件模板索引（文本框 `1073741867` / 图片控件 `1073741866`）
4. 授权后从标注文件检索图片资产：`100001`（纯白实心正方形，tintable + free_nonuniform）

**教训**：先建脚本还是先建容器无所谓，但**没挂到容器节点上，脚本永远不运行**（硬边界）——创作者最初的"懵"就来自这里。

## 三轮聚合故障排障（本案例最值钱的部分）

`OnUpdate` 全体包 `pcall` → 任何异常转成 `GAME FAULT BEGIN/END` 块（带行号与现场数据）。**每轮排障只花一轮日志往返**：

| 轮 | 故障块内容 | 根因 | 修复 |
|---|---|---|---|
| 1 | `测试:541: bad argument #2 to 'format' (number has no integer representation)` | `GetUICanvasSize` 返回非整值浮点，Lua5.3 `%d` 直接抛错 | `%d` → `%.0f`（边界 #3） |
| 2 | `按键注册失败: KeyboardMoveLeftKeyDown 不在 KeyboardKeyCode 中（表键=nil…）` ×15 | 事件值在 `Enum.KeyEventType` 不在 KeyCode；且枚举是元表对象 `next()` 枚举不出 | 三枚举特性探测 + 失败时报出试过的候选（边界 #4/#5） |
| 3 | 110 条「生命周期处于创建或销毁时，无法调用 DestroyClientUIControl」警告 | `OnDestroy` 里手动销毁无效——控件随脚本自动回收 | 移除手动销毁（边界 #7） |

> 方法论：**故障块是"一轮定位"的前提**。如果 OnUpdate 没包 pcall，第 1 轮的异常会让更新循环静默死亡——画面空白 + 日志干净，排障成本×10。

## 已验证可复用的模式（直接抄进下一个玩法）

- **启动链**：STARTING(挂载核对,有界重试90帧) → 画布等待 → 分批建池(15/tick，110 控件无卡顿) → 注册输入 → RUNNING → 首渲染自证
- **槽位缓存渲染**：每槽位缓存 {vis,x,y,w,h,colorIndex}，只对变化调 setter；行段合并（同色连续格→一个拉伸矩形）把 200 格压到 ≤100 槽
- **输入**：Down/Up 成对注册（持键状态）+ Down 单发（跳/切）；键盘与手柄同构；首按键打一条日志证明事件链路
- **服务器上报契约**：信号管理器定义（信号名+参数序）→ 客户端 `ServerSignal:AddInt:SendSignal` → 服务器节点图【监听信号】。联机回执延迟 ≥100ms，UI 不做同步等待
- **测试钩子模式**：先用常量（233）验证管道，通了再换真实数据（game over → sendScore(score)）
