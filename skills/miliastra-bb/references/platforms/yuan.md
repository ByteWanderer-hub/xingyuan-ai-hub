# 平台适配：千星奇域（原神 UGC / Miliastra Wonderland）

> 🔗 **联动**：需求方法论 → 本技能 `../../SKILL.md`（按需分析与授权边界）｜落地技能 → `miliastra-code`（AI 能力边界 / 平台硬边界 / API 文档索引）｜蛋仔域适配 → `eggy.md`

> 本文件是 miliastra-bb 的**千星域落地适配**。这个域的第一性原理：**AI 修改已授权的客户端脚本及模块，`levelScript.lua` 是常见入口而非单脚本限制**；控件建不了、脚本挂不了、画面看不见。所以需求阶段的核心动作是：把"哪些是 AI 写脚本能做的、哪些必须创作者在编辑器做"在边界清单里就切开，并把**要向创作者交接的东西**一次列清。

## 1. 工程识别

- 项目特征：千星沙箱项目工作区，含 `levelScript.lua`（AI 的唯一落点）；可选 `annotations.lua`（平台随项目提供的 API 签名）。
- 相关词：千星奇域 / 千星沙箱 / 米哈游 UGC / 原神 UGC / 客户端控件容器 / 控件模板 / 图片资产 ID / 手柄导航。
- 与蛋仔域**API 完全不通用**（`EggyAPI`+RPC vs `game.*`/`script:*`）——识别成蛋仔就是全盘错误。

## 2. 四层比对手段（按涉及层选择）

| 层 | 查什么 | 手段（工具/命令） |
|---|---|---|
| **逻辑层** | 已有状态机/事件回调（`OnInit`~`OnDestroy`）/绘制流水线/资源登记 | grep 工程 `levelScript.lua`（文件:行号） |
| **触发/挂载层** | 脚本挂载在哪个控件模板上；容器是否可见/开启 | **此域无触发器编辑器**；挂载是创作者侧手工操作，AI 不可达 → 只能向创作者要「容器节点索引 + 实际挂载的脚本名」，证据标 `provided_unverified` |
| **场景/资源层** | 客户端控件容器/控件模板/图片资产 | 全在创作者侧编辑器，AI 看不到真实画面；模板索引/图片资产 ID 按需向创作者索取；检索素材用 `miliastra-code/assets/Image_sample_by_id.json`（**rg 定向检索，禁止整份加载**） |
| **能力层** | 官方 API 支不支持；平台硬边界 | `miliastra-code/references/api-client-ui.md`（1127 行，接口全带签名）；**优先级：工作区 `annotations.lua`（若存在）→ api-client-ui.md → 冲突以工作区为准并记报告**；平台 9 条硬边界见 `miliastra-code/SKILL.md §1`；已知差异：`script:EnableTick` 实为 **`EnableUpdate`**，照抄旧文会静默失效 |

**F1 证据卡采集格式（千星域）**——与 `miliastra-code` 证据双轴对齐：

| 层 | 证据格式 | 证据来源标注 |
|---|---|---|
| 逻辑层 | `levelScript.lua:行号` / 函数名 | `observed`（文件里真实存在） |
| 挂载配置层 | 容器节点索引 + 挂载脚本名 | `provided_unverified`（创作者给的、未核对） |
| 资源层 | 控件模板索引 / 图片资产 ID | `provided_unverified` 或标注检索文件路径 |
| 能力层 | api-client-ui.md 行号 / annotations.lua | `documented`；查不到标 `unknown` 并停止依赖，**禁止猜** |

> 运行时类结论（画面真出来没有、绑定真生效没有）在没有真机试玩前一律 `device_status: pending`——需求清单里**不许预写"真机通过"**。

## 3. 六维体检的千星域口径（按相关维度选择）

六维定义与问法见 [`../dimensions.md`](../dimensions.md)；**下面是千星域"怎么取证/怎么标"的换算表**：

| 维度 | 千星域怎么问 | 证据与工具 | 常态结论 |
|---|---|---|---|
| **D1 玩家体感** | 玩家看得见这个反馈吗？输入→反馈的平台延迟量级？"这个角度"下控件是否被遮/出画/超出安全区？控件高度不够会怎样？ | 画面取证 `miliastra_shot`；布局与字号机械门禁 `miliastra_code op=lint-ui`（★真机铁律：**文本框高度不够 ⇒ 一个像素都不画**，模拟器不模拟它）；模拟器闭环 `miliastra_sim op=hud`（直接读 HUD 上的字）；帧间变化 `op=frames`（像素差） | 未真机前一律 `pending`：**截图只能证明"画出来没有"，证明不了"好玩"** |
| **D2 失败与重复** | 死亡/失败后玩家怎么重来？重来要几步？可跑局时长的量级？ | 局时长与状态切分 `miliastra_playtest op=status`（单局开跑/结束的真实时刻）+ `miliastra_log op=runs`；死亡位置分布 `miliastra_log op=metrics`（**不用改脚本**就能拿到集中区） | 需要数字：重开步数 / 单局秒数 / 死亡集中点 |
| **D3 公平与社交** | 本图支不支持联机？人数上限？（AI 不可达） | **向创作者问**（写进方案）：人数上限、联机形态（同屏/异步）、存档是否跨局 | 创作者没答 → `[待确认]`，配"缺人数上限 ⇒ 难度曲线与奖励无法定档"的后果说明 |
| **D4 平台规则与合规** | 素材来源（官方素材授权范围）？内容分级？有没有血腥/恐怖表现？玩家名与自定义文本？ | 素材台账 `miliastra_health`（活文件/关卡）+ `miliastra_map op=clientui`（模板与资产索引，判断"新增了什么素材"）；规则查不到 → `[待确认]` + 补证路径 | 素材来源不明 = 必查项，不许"应该是官方的" |
| **D5 性能与规模** | 同屏控件/实体几个？刷新频率？（千星域**没有跨设备的通用帧率口径**） | 控件计数 `miliastra_sim op=controls`（`runtime:true` 看脚本运行时建了几个）；已知量级：**110 控件工程在模拟器里可跑**（案例 `../examples/yuan-tetris-first-game.md`）；用户 Lua 在**可终止 Worker**里跑（默认 8 秒超时 terminate）⇒ 单帧循环过长会被判超时 | **帧率不许编**：真机试玩后用 `miliastra_log` 的耗时/帧率记录取证；拿不到就 `[待确认]` |
| **D6 可撤性与维护** | 脚本怎么"关掉"（有没有开关）？改坏了怎么回滚？牵连几个文件？ | 回滚 = `miliastra_code op=backup / op=restore`（部署自动备份，永远有还原点）；改前指纹对账 `op=inspect`（编辑器可能把旧版写回）；牵连面靠工程 grep | 无开关 + 无备份 = 必须补；**覆盖面广的改动先备份再动手** |

## 4. 交接表（实施分工）

> 新增脚本、容器划分或数据契约等复杂结构变更，按 `miliastra-code/references/project-architecture-assessment.md` 的相关部分先厘清架构。明确小改、已有规划和不影响结构的修复直接沿用现状。已获实现授权不再逐工单确认。

下表「交接给」指的是**② 落地**阶段的主技能：

| 功能点类别 | 交接给 | 交接内容 |
|---|---|---|
| 玩法逻辑 / 状态机 / 多脚本契约 / 黑板字段 / 存档与信号 / 试玩取证 | **`miliastra-code`** | 功能点 + 确认方案 + 验收口径 + 现状比对 + **创作者交接清单**（见下） |
| **界面视觉与版面**（版面表 / 栅格 / 字号配色 / token 档位 / 层序 / 可点四态 / 动效规格 / 素材整组接入） | **`miliastra-ui`** | 界面功能点 + 设计稿坐标 + 层序要求 + 素材是否整组 + 验收（截图回看） |
| 控件帧动画 / 像素画重建 | **`miliastra-code`** | 参考帧或参考图 + 目标控件数上限 + 体积/调用量预算 |
| 官方 API 到底支不支持 / 枚举叫什么 / 参数与返回值 | **`miliastra-code`** | 要查的能力点（`annotations.lua` → `api-client-ui.md`；查不到就标 `unknown`，**不许推测**） |
| "代码没问题但没效果" / 静默失效 | **`miliastra-code`** | 现象 + 复现步骤 —— 先按 9 条平台硬边界倒查环境，别先改代码 |
| **存量代码规范整改**（风格清理 / 接手别人的脚本） | **`miliastra-code`** | 走 `miliastra-code` 的 `references/style-remediation-workflow.md` 三步（先备份 → 摸底 → 分档），并过两道机械门禁 |
| **工程摸底 / 档案**（活文件与关卡定位、素材与模板索引、日志目录） | **`miliastra-code`** | 用 `miliastra_health` / `gil-clientui` / `miliastra_map op=clientui` 盘点，产物落 `docs/` |
| 需求边界确认本身 | **本技能（miliastra-bb）** | 重复分析新需求 |

**主 / 协作规则（对齐 `code-bb` 的"按主次要交接"）**：
- 一个功能点**同时涉"逻辑 + 版面"**（典型：加一个弹窗、加一栏 HUD）⇒ **主 `miliastra-code`（行为与建控件）、协作 `miliastra-ui`（版面表与视觉口径）**，方案里把两侧落点都写清。
- ⚠️ **同一文件同一函数不得两个技能并发改**——千星域的常见冲突点是 `view.lua` / `board.lua`（既摆版面又管逻辑）：
  一个功能点**只派一个主技能**，另一个技能只出**方案级建议**，改由主技能落地。
- 下游发现影响玩法、范围、权限或验收的歧义时集中澄清；普通实现细节自行解决。

**创作者交接清单**：先从当前工程与工具获取容器索引、实际挂载脚本及所需模板索引；确实缺失再集中询问。图片素材按 `miliastra-ui/references/asset-search.md` 检索。涉及编辑器开关或挂载时提前给出本次所需的具体配置，不让用户反复猜测；未形成可玩候选前不要求反复点击/校准。

## 5. 实现方案模板的千星域落点（按实现需要）

- **逻辑层**：改哪（`levelScript.lua` 的哪个状态机/回调/绘制流水线段）；运行环境红线（**Lua 5.3**：无 `io.*`、`string.dump`、大部分 `os.*`/`debug.*`；补充 `math.isnan/isinf`）；取证口径（证据双轴 + 四条"不能证明"，静态检查≠真机行为）。
- **资源层**：能实例化什么由平台定（**只有存为模板的客户端控件的父节点可被脚本实例化**，模板子节点不行——方案涉及动态创建时先过这条）；控件帧动画 / 像素画重建两条路线按 `miliastra-code §4`。
- **视觉/版面层（对接 `miliastra-ui`）**：版面表（元素 | x | y | w | h | 字号 | 颜色）与层序表（谁先建）；
  数值**只从档位取**（8 基数 / 面板宽 480·720·960 / 字号 4 档 / 语义色表），档位里没有的**不许造** → 标 `-- TODO(token): 需要 <语义> 档`，
  一次性定位标 `-- one-off: <为什么>`；可点元素要四态；素材**整组**接入（先缩放再摆位）。
  验收：`miliastra_shot` 截图走「截→读→修→复截」，动效用 `miliastra_sim op=frames` 的**帧间像素差**证明。
- **契约核对**：API 一律以当前文档为准（模型记忆只能当检索线索）；**API 文档变化时复核本次依赖的相关结论**。
- **风险与通道**：9 条硬边界任一不满足即**静默失效**——"代码没问题但没效果"先倒查环境，别反复改代码；验证器必须独立于编码器；**自报成功 ≠ 成功**（绑定报错/读回不一致/占位图/回退默认资源任一出现即 FAILED）。
- **改造前备份**：千星域脚本文件不在任何 git 里，改造已存在的 `levelScript.lua` 前先复制到项目 `project-docs/`（惯例 `<玩法>_v<n>_备份.lua`）——覆盖即丢失。
