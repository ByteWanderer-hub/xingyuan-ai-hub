# 通用角色人设图

将角色身份与画面表现分开维护。适用于人物、动物、吉祥物、机器人及其他生物；不预置鲸鱼尾巴、性格、服装或固定头身比。

## 明确本次产物

沿用当前对话已确认的角色、参考图、用途、数量和授权。用户明确要求生成时直接执行；仅要方案时只交付方案，不自动出图。不重复要求方向、数量两轮批准。只在影响角色身份的矛盾或必需输入缺失时集中澄清。

- 已有人设：从用户指定母版提取身份锚点；局部修改只改指定字段。
- 从零设计：按描述给出一个完整、可辨识的初稿；只有用户要求比较方向时才展开多方案。
- 未指定数量默认一张；设定图、头像、立绘与三视图按用途选择，不默认全部生成。
- 比例、尺寸、背景及透明要求服从用户与目标平台；不把默认正方形、浅色背景当角色属性。

## 建立角色卡与参考分工

使用 [角色卡与检查表](references/character-card.md) 提取必要字段，不为单张图强制填写长表。区分固定身份、允许变化和未定设计。

每张参考图注明用途：身份、画风、姿势、服装、构图或文字。姿势参考不能覆盖脸型，画风参考不能带入另一角色的配饰。冲突按用户最新明确指令处理；无法辨别角色身份来源时再问。未说明的背面、遮挡结构是设计提案，不称为已有设定。

保持同一已认可母版为身份来源，避免连续以上一张变体为母版导致漂移。用户认可的新身份修改才更新角色卡；换服装和画风不自动重写身份。

## 编制与执行生成

提示词按以下顺序组织：产物与用途 → 身份锚点 → 形体结构 → 本次姿势/表情/服装 → 画风/构图/光线 → 背景/文字/输出要求 → 必须避免的具体偏差。

1. 将可见特征写成可画的形状、位置、颜色和材质；“高冷”要落实为视线、眉形、嘴角、姿态，不能只堆性格词。
2. 三视图采用一致尺度与正交视角，前侧后结构相互对应；不把三个不同动作当三视图。复杂角色优先确认可辨识的主视角，再补其他视图。
3. 实际出图时使用当前环境的图像生成能力；有 `imagegen` 技能时按需读取并遵守工具接口。先查看本地参考图，再进行编辑。不得把提示词、占位图或脚本绘图当生成成品。
4. 不依赖鲸鱼娘脚本、素材库或外部 API。工具不可用则明确交付到提示词/方案的范围；不擅自切付费服务或上传参考图到其他服务。
5. 在用户数量与预算内生成。发现问题先定位需改字段，保留已合格部分；每张默认至多两轮定向修正，用户另有预算优先。重复同一错误或服务失败即报告，不无限重试。

## 检查与交付

逐张检查身份、物种结构、动作、配饰连接、视角、文字和输出要求。人体检查不能套在无手或多肢生物上；遮挡和裁切处不能虚报精确头身比。缩略图检查轮廓辨识，原图检查细节；多图再横向比较身份是否漂移。

透明需求必须由图像工具生成真实透明背景，棋盘格画面不算透明。仅在工具或文件检查有证据时声明尺寸、格式和 alpha 已通过；无法满足精确规格时如实说明。

展示成品并简述必要限制。连续创作时保留母版、简短角色卡、参考图分工及本次修改字段；单张任务不强制制造运行目录和多份报告。未实际查看图像不得称视觉验收通过。

生成角色表情包/漫画时转 `character-sticker-comic`；明确鲸鱼娘使用专用技能；游戏 UI 落地另走对应平台技能。
